# @probebench/rule

告警规则引擎。注入 `config`，订阅 `poller/result` 实时评估采样点。

## 规则模型

| 字段 | 说明 |
|---|---|
| `registerId` | 目标寄存器 id |
| `operator` | 比较符：`>` `<` `>=` `<=` `==` `!=` |
| `threshold` | 阈值 |
| `message` | 命中提示 |

## 评估流程

`poller/result` → 逐点匹配规则（同 registerId）→ 比较 → 命中发 `rule/trigger` 事件：

```ts
{ ruleId, objectId, registerId, value, threshold, message, timestamp }
```

## API 端点（由 api 插件暴露）

- `GET /api/rules` — 规则列表
- `POST /api/rules` — 新建 `{registerId, operator, threshold, message}`
- `PUT /api/rules/:id` — 编辑完整规则 `{registerId, operator, threshold, message}`
- `DELETE /api/rules/:id` — 删除

## 前端联动

在设备实时数据页切换到「配置」，点击具体点位的「告警」按钮，可添加、编辑、删除该点位的规则；既有规则仍保留。观测页顶部显示当前告警，触发点位的原始值和物理值（含单位、枚举文字）标红，条件恢复或规则删除后恢复正常颜色。界面使用有效的最新采样持续显示当前触发项，条件恢复后自动消除；数据过期、设备或分组暂停、通信异常时显示等待有效数据，不将其当作正常值。

比较对象是按点位类型解码后的原始值，不应用工程系数、偏移或显示小数位舍入。后端按数据区域隔离并检查完整字宽；64 位整数比较不转为浮点数。同一次持续告警只记录一条 WARN 日志并发一个 `rule/trigger` 事件，恢复后再次命中才重新记录。日志可在现有运行日志中查看。

新采样携带响应 `batchId` 时，多字必须来自同一批次；混批按未知处理，不能触发或解除告警。后端不从 latest 缓存补齐当前事件的缺字。没有 batchId 的旧样本保留原有校验路径，不能视为已证明响应一致。

`pollOnce` 继续把读取结果合成一个 `poller/result` 事件。告警在该事件内按响应身份收集完整字宽，使用事件顺序中最后一个完整响应，避免较早重叠组的单字遮蔽完整多字值。最新完整响应若质量异常、非有限或地址重复，保持未知，不回退到更早有效响应；不同事件的缺字也不会互相补齐。
