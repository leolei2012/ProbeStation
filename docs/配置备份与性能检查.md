# 配置备份与性能检查

## 备份和恢复

进入左下角「设置 → 数据管理 → 配置备份与恢复」。导出文件为可阅读的 JSON，包含版本、导出时间、devices、groups、registers、rules。设备连接参数、设备级保留时长、点位类型、工程单位、系数、偏移、小数位数、枚举和告警规则均保留。

恢复时先选择文件查看新增数量、设备名称及连接地址；同名设备会提示。点击「确认新增并恢复」后，以新 ID 新建设备、分组、点位和规则，已有配置及历史记录保持原样。所有恢复的设备默认暂停，检查连接参数后再手动启用。导入过程使用事务，任意校验或写入失败均回滚，只有成功后才广播配置变化。

2026-10-28 已修复多分组备份漏点位的问题，导出按设备汇总全部分组点位，保留空分组和没有分组的设备。此前生成的备份可能已经遗漏点位；修复不能补回文件中不存在的内容，应从仍完整的原配置重新导出。

点位 quantity 已按独立备份元数据保真：接受正 JavaScript 安全整数（1–9007199254740991），不按 dtype 重算、不绑定 Modbus 读取上限；JSON 和 SQLite INTEGER 在此范围可精确保留。旧 v1 备份缺字段时默认 1，显式非法值在预览/恢复时拒绝且不改变目标配置。实际字宽和分组读取长度保持原有规则。本次未修改 XLSX/MBP 数量列的既有导入行为。

这不是整个工作区的备份：历史采样、固件文件、运行日志、AI 密钥及会话不包含在 JSON 内。迁移整个实例时，仍应停止服务后备份实际数据目录。

REST 接口：

| 方法与路径 | 行为 |
|---|---|
| GET `/api/config/backup` | 下载配置 JSON |
| POST `/api/config/backup/preview` | 以备份 JSON 为请求体，完整校验并返回新增数量及同名提示，不改现有配置 |
| POST `/api/config/backup/restore` | 同样的请求体，事务新增并保持设备暂停 |

两个 POST 需请求头 `x-probestation-config: 1`；浏览器 Origin 必须与服务一致。自动化时先预览，只在用户要求恢复时调用 restore。单次备份上传容量为 64 MiB；这不改变 AI 附件的无限额策略。

## 曲线与实时显示

历史曲线使用 GET `/api/data/object/series`。查询覆盖完整选定区间，按实际采样时间解码，保留各桶首值、末值、最小值、最大值和无效读数。多字点位只合并同一实际时间的完整原始字；不再按不同地址各自的最新字拼接。放大或平移视窗后自动重新查询，重置返回原查询范围。`max_points` 是每点位显示预算，不是历史查询行数截断；返回 `sourceSamples`、`displayedSamples` 和 `downsampled` 说明精度。

数据库通过独立连接分批流式消费结果，JavaScript 内存只保留显示桶的代表样本。取消过时请求会中断对应查询。长范围仍须扫描所选点位的数据，查询耗时随数据量增加；这不是预计算的多级聚合索引。

曲线上方可展开「采样质量摘要」，逐点查看当前查询区间内降采样前的采样数、有效数、无效数与有效率。统计基于原始解码结果，不随物理值显示切换变化。无效包含质量异常、缺字和无法表示的数值；完全没有产生采样的时段不在分母中，不能用该有效率判断设备在线率。图例的末值严格取末次采样，末次无效显示 `—`，不会回退到更早有效值。

桌面单组超过 200 行时，只渲染可见行及缓冲区，滚动可查看全部点位。手机卡片保留正常布局。实时曲线隐藏或暂停时继续维护采样缓冲，但不再每 250 ms 更新绘图状态；后台页面暂停计时刷新，回到前台恢复。

## 检查入口

- `npm run check`：前端及配置/历史服务类型检查、生产构建、无硬件回归测试。
- `npm run typecheck:web`：前端及引用模块的 TypeScript 检查，不等于整个后端的类型检查。
- `npm run typecheck:services`：配置、历史存储和新增曲线/备份接口的类型检查。
- `npm test`：显式白名单的 14 组测试，覆盖编解码、物理值、数据质量、曲线、配置恢复和模拟 AI。

不要自动遍历执行全部 `scripts/test-*.ts`：部分脚本故意连接设备、开启监听或串口。新增安全测试时，人工确认后加入 `scripts/test-safe.ts`。
