# 录制间隔核对提示与只读检查

2026-11-06，基线`3ffb43a`，初始工作区干净。本轮仅本地开发、真实ConfigStore内存库及mock验证；不启动主应用/MCP监听，不打开用户数据库，不操作设备/串口/PLC，不调用模型，不部署/重启服务/推送，不安装依赖。

## 发现与选择

录制目前仅有MCP入口，Web没有录制会话页。39阶段已在停止返回/会话对象中区分恢复结果，但定时结束的警告需主动查询，删除会话或最近50段淘汰会丢失该对象。Web“运行日志”只有清理入口，没有日志查看器。因此本轮补充只读核对链路，沿用现有设备编辑处理需要变更的间隔，不增加强制恢复、自动回填原值或新的写接口。

## 用户工作流

设备概要、采样表格/曲线之前新增“录制间隔核对”：读取当前配置间隔、核对时间、活动录制数量；有preserved/uncertain结束记录时显示醒目边框、人工核对说明，可展开原间隔、录制间隔、结束时间、录制ID与警告。当前配置值不是硬件实测频率，也不能凭“当前等于原值”推断已经处理。

用户先确认当前间隔是否符合预期。需要调整时，从上方已有设备编辑入口审阅当前配置并保存所需值；继续使用既有原快照/事务冲突检查。提示中只有“重新读取”，不会填回旧值、自动恢复、开始/停止录制、连接设备或绕过冲突；设备已删除时明确显示缺失，不建立替代设备。没有自动确认或全局“已解决”状态，不按数值相等清掉警告。

组件首次读取，完成后间隔15秒再次读取，可主动重读；单次10秒超时。旧响应/取消/切换设备不会替换新结果。失败/超时保留上次结果并标记“未核实/上次读取”，成功后恢复本次时间。无MCP状态服务明确表示未提供；旧版服务无该REST路径时显示读取失败，不把它当作没有问题。

## 存储、协议及覆盖范围

- Recorder维护独立于样本会话的最近100条preserved/uncertain记录，当前配置内各设备共用上限。删除录制样本或50段会话淘汰不清除核对记录。超过100条移出最早记录，返回全局dropped计数；按设备筛选不会把全局计数伪称为该设备计数。
- 记录只属于本进程当前配置连接。配置reopen重置显示记录/计数，并用进程内scope标记排除旧配置活动会话与迟到结束记录；即使新旧设备ID相同，也不把旧记录或日志归到新设备。没有数据库结构变更、迁移、持久核对队列或崩溃恢复；重启后不从当前值猜旧问题。已有旧会话仍可通过原录制查询/停止查看，此前配置的归属警告会保留。
- 完成时另写既有`WARN/recorder`日志，含录制ID、设备ID、结果及原/录制间隔；日志失败不影响done、不重试恢复，内存核对记录追加“日志未保存”。此记录不是硬件读回或永久审计保证，日志可被已有清理接口删除；Web提示不依赖解析日志。
- 新增只读MCP `get_recording_interval_status {device_id}`。返回available、deviceId、checkedAt、current（name/mode/intervalMs或null）、active、notices、retention（scope=process/limit/dropped）。主MCP provider暴露同一只读函数供API使用，不新建Recorder或启动服务。
- 新增GET `/api/monitor_objects/:id/recording-interval-status`，只读配置元数据及内存记录；无POST/恢复接口。校验正安全整数ID、返回结构及设备归属。服务不存在返回available=false；异常/不一致返回通用500，不暴露内部异常。当前设备不存在时current=null，仍可查看保留的对应记录。
- 前端/MCP/API共用纯DTO校验/不可变复制，不引入新依赖；前端不导入主应用启动/后端存储/硬件代码。核对GET不写配置或日志，不影响39阶段的间隔写入身份。

旧REST更新仍无条件，旧客户端彼此仍可能覆盖。39阶段的跨连接保守失效、无自动重试/跨进程调度/退出恢复等规则不变。新状态提示不等于这些限制已解决；运行实例未更新。
