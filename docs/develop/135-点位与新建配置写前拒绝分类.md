# 点位与新建配置写前拒绝分类

基线`39a09f638607a526c8e56036117bda5e12303a2f`，初始工作区干净。本轮沿用[134号设备编辑契约](134-设备保存写前隔离与结果未知区分.md)，核查并修复点位编辑、新建设备、新建分组三个入口。旧无条件点位更新、分组编辑、告警、导入等其他入口未扩展。

## 复现

真实内存配置连接经合成COMMIT/ROLLBACK异常进入隔离，随后通过实际HTTP路由、App.request、保存回调及编辑器模拟hooks发起独立写入。三个入口原先都未生成并识别写前拒绝标记，因此统一提示结果待核实；点位原事务故障后的下一请求亦如此。基线4组断言失败，属于三个入口及一个点位组合场景，不当作四个独立产品缺陷。

原有输入在失败后仍保留；这次补齐明确拒绝分类，不将既有草稿保留称作新功能。首次原事务可能在COMMIT前失败，也可能已经COMMIT但确认报错；两者必须继续未知。

## 行为与兼容

- 点位条件PUT`/api/registers/:id/settings`在调用updateRegisterSettings之前检查本地隔离元数据。原GET、400编号检查、已知校验/冲突、成功warnings和原事务异常catch保持。
- 新设备POST`/api/monitor_objects`在createObject之前检查，拒绝时不运行deviceSlaves.sync；新分组POST`/api/monitor_objects/:id/groups`在createGroupWithRegisters之前检查，拒绝时不创建组或默认点位。
- 仅版本1、phase=quarantined、failure=connection-quarantined产生503及`{version:1,code:'CONFIG_WRITE_NOT_STARTED',outcome:'not-applied',error:...}`。其error文本沿用设备编辑的“本次保存未执行”，创建界面按操作显示“本次创建未执行”。只说明该请求未进入写方法，不证明设备/组存在、输入有效、旧请求未提交或后续可以安全重放。
- body业务校验之前确认隔离会优先拒绝；点位URL编号校验仍在前。配置状态方法可选，旧provider不提供时保持原调用路径，不能得到明确未执行结论。没有根据普通503或抛出的旧隔离异常猜测结果。
- 将设备编辑已有的完整错误元数据识别提取到轻量共享configurationWriteBlocked；点位、设备编辑、新设备及新分组按同一严格规则使用。HTTP适配器仍为134号版本，未扩宽识别。字段缺失、未来版本、旧隔离码、不匹配outcome、500等状态或返回丢失均未知，不自动取消、重试或回退旧写接口。
- 新设备和点位错误留在现有编辑器，失败不走成功关闭/刷新回调。新分组保留输入，明确拒绝有中英文提示；原创建成功后通知warning、通知/同步失败的未知结果继续沿用。输入只在当前页内存，不承诺刷新/关页恢复。

新前端遇旧服务端普通503或500仍未知；旧前端遇新明确拒绝仍保守未知。POST成功返回形状及旧body默认值未变，没有引入幂等键，也不能替外部客户端保证不自动重试。配置恢复仍须管理员处理，本轮不重开任何连接。

## 隔离测试

新增config-write-entrypoints，共5组，安全白名单137套：

1. 点位写前隔离：实际路由→实际HTTP适配器→保存helper→PointSettingsEditor模拟hooks；未执行提示、输入保留、关闭确认取消、只发一次请求。
2. 新设备写前隔离：抽取实际POST及App.addDevice回调，真实DeviceModal模拟hooks；保留名称/地址，不关闭、不刷新、不报成功、不运行同步。
3. 新分组写前隔离：实际POST和GroupModal模拟hooks，保留名称，不报成功；中英文分支均覆盖。三组均有prepare/exec哨兵，零SQL及通知/运行时计数不变。
4. 对三条流程分别覆盖普通503、未来version、旧CONFIG_TRANSACTION_UNCONFIRMED、不匹配outcome、500携带相似字段，以及明确拒绝响应在返回客户端前丢失：都保持未知，每次手动提交只有一次请求。
5. 点位COMMIT执行前失败、COMMIT已完成后确认失败且ROLLBACK失败：原请求500/未知；下一请求已知隔离才明确未开始，未将原请求误判未执行。

另独立重跑device-draft-close、group-create-active、group-create-atomic、point-edit-conflict和device-write-quarantine，均退出0。两个抽取真实组件/回调的旧夹具仅补共享函数依赖，没有放宽原通知、原子创建、响应丢失或草稿断言。严格services检查通过。

API只使用Fastify.inject，不加载CLI主入口或监听端口；SQLite仅内存，设备地址/串口字段为合成元数据，运行时钩子仅计数。未访问真实服务、数据库、设备或模型。
