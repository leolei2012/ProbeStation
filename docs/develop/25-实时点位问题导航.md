# 实时点位问题导航

状态：已实现，离线检查通过；真实浏览器未验收。2026-11-06，基线`8cccf5c`。

## 复现与选择

原实时表格只有名称/地址搜索和“只看异常/过期”。该勾选只判断过期或解码不完整，没有包含告警触发。纯mock复现：来源2的uint16值200、质量good、时间新鲜，规则`>100`已触发，但旧异常筛选返回false，反而把该行隐藏。点位较多时缺少直接定位触发点的流程。

本轮提供明确的状态导航、范围计数和来源/ID搜索；筛选与行内红色告警复用一次求值，不另定义阈值或采样行为。

## 使用

- 设备“实时数据”中，按“全部点位 / 需关注 / 行内已触发告警 / 数据异常/过期/暂停 / 行内规则结果待定”切换。
- 搜索名称、分组、类型等关键词，多词同时匹配；`id:123`或`#123`精确匹配点位ID，`0x0001`精确匹配地址，`slave:2`或来源下拉筛从站。普通数字仍为关键词搜索，不保证只匹配地址。
- 按钮数量先应用当前搜索/来源，再分别统计状态；切换状态不会使其他按钮数量消失。各状态可重叠，“需关注”是并集，不能把按钮数简单相加。
- 筛选期间匹配分组临时展开，折叠按钮暂禁用；清除全部筛选恢复原折叠状态。分组摘要保持完整组的质量/时间，不按筛选后的子集伪装整组健康。
- 主动改变搜索/来源/状态时重建表格滚动容器，从结果首行开始，避免沿用大表底部滚动位置错过匹配点；缓存刷新不改变该键，不主动重置滚动。清除筛选恢复折叠偏好，不恢复旧滚动位置。
- 行名称悬停可查看ID、FC和地址。筛选无结果保留所有控件，可清除恢复；来源从配置中消失时解除失效的下拉筛选。

筛选只保留在当前实时表格组件内存，不保存配置、不暂停/恢复采集、不修改规则、不读历史、不调用模型，不新增API或轮询。观测/配置模式和原操作按钮仍沿用原流程。

## 判定边界

- 已触发告警使用原`readAlarmValue`和`alarmMatches`：当前配置来源、完整同批、质量/时间有效后，比较未换算、未舍入的原始解码数值，64位整数保持bigint。倍率、偏移和文字小数位不改变规则。
- 数据异常沿用当前点位健康与解码不完整状态，包含缺字、过期、坏质量、设备/分组暂停或通信错误。它不是所有协议、配置或物理异常的完整诊断；配置结构问题可使用另一个“点表检查”页。
- 规则待定只统计**已载入且属于有效显示点位的规则**无法求值的情况，可能与数据异常重叠。没有载入的规则不能猜测；清单未载入或读取失败时有明确提示，0不能解释为无告警。失败时保留原已载入规则，不改变原规则缓存策略。
- 被前一多字点覆盖的行（可能包含有意的语义定义）在“全部”保留，其他状态仍沿用原行内求值策略，不把它作为独立有效显示点。相关规则需核对顶部摘要和点表配置；筛选不是所有后端告警的完整计数。未修改覆盖布局或恢复这些定义。
- 新模型严格拒绝未确定的配置来源借用旧兼容缓存。该回归曾失败（借来源1的200触发未知来源点），加上与顶部告警一致的有效来源保护后通过；显式匹配来源的旧键仍兼容。
- 这是当前页面缓存的显示求值，不是服务端告警事件计数、自动PASS/FAIL或历史判定；顶部摘要/表格独立请求规则时可能短暂处于不同版本，本轮不增加事务快照或修改后端规则引擎。
