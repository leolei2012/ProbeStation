# 录制样本容量与提前结束说明

2026-11-06，基线`ea3590b`，初始工作区干净。仅本地开发、真实ConfigStore内存库和mock采样/时钟/运行处理验证；不打开用户数据库，不启动主应用/MCP监听，不部署/重启服务，不操作设备/串口/PLC，不调用模型，不推送，不安装依赖。

## 风险与选择

原Recorder只限制最近50段会话，未限制每段样本或总保留量。长时长、大点表和多并行录制都可无上限增加samples，定时结束后还会继续留在内存。先用生产默认构造与单次200001个合成原始字事件复现：断言要求最多200000，旧实现实际200001而失败。不是修改协议地址范围或告警阈值，而是为录制服务增加明确的保留容量保护。

本轮默认每段最多保留200000个原始样本，当前Recorder/MCP服务实例全部设备、全部会话（含已结束保留）合计最多500000。多个MCP客户端共用该实例，不能为每个客户端各算一份。构造器可注入较小正安全整数限额供隔离测试；MCP不新增提高限额的参数或无上限模式。

## 达上限的行为

- 每次结果只把剩余容量内的匹配样本依原顺序复制进会话；有匹配样本无法保留时，该会话提前结束，quotaTruncated=true，completionReason为sample-limit或storage-limit。保留此前数据，不为腾容量额外删除旧录制（既有最近50段淘汰规则仍适用），不假装完成请求时长或整个触发窗口。
- discardedSamples只统计导致结束的当前事件中已知匹配但未保留的数量，后续事件不继续录制，也不能计算未观测的未来数量。最后一个事件可能在多字中截断，不能补0/跨批拼字；仍需原有同来源/area/时间/完整批次与质量验证。quotaTruncated=false也不证明业务完整性、触发成功或自动PASS/FAIL。
- 刚好到上限、没有匹配样本被拒绝时不误报截断，继续等请求结束或下个事件。无匹配来源/地址、其他设备事件不消耗本段容量。
- 触发前窗口先清理过期/无效时间样本并归还容量，再计算本次可保留量；保持原触发候选独立于录制地址的规则。即使本事件已触发但采样容量不足，也明确提前结束并清掉新安装的触发后计时器，不冒充完整窗口。
- 容量满时拒绝新开始，在改变间隔/建会话前报错，提示先list_recordings核对并删除已结束录制。共享容量按现有会话/事件处理顺序分配，不承诺各会话均等配额。
- 删除录制和最近50段淘汰会归还对应样本容量；滚动触发窗口清理也归还。停止本身不删除样本。不会为了开始新录制而额外静默丢弃用户已有完成数据。

提前结束沿用39阶段的间隔归还：同设备仍有其他活动会话时共享，最后结束才尝试原身份条件恢复；用户后来改间隔仍保留当前值。样本上限写WARN/recorder日志并在会话保留说明，日志失败不影响结束、不重复恢复。已有40阶段间隔核对记录仍独立，不因删除样本而消失。

## 完成状态与兼容

新增会话/列表字段：sampleLimit、completionReason、quotaTruncated、discardedSamples。完成原因包括duration、trigger-window、trigger-timeout、stopped、deleted、sample-limit、storage-limit及configuration-changed；done只表示这段录制已经停止。

MCP工具名及原参数、原根字段不变：开始返回status、completion_reason、quota_truncated、sample_storage（每段/总上限、保留/剩余数）；get/list_recordings带上述camelCase会话字段；stop/delete_recording新增completion_reason、quota_truncated、discarded_samples，原ok/ID/间隔恢复结果保持。开始/触发工具描述预告默认上限，get描述要求检查完成原因，避免旧消费者把done当作完整结果。旧客户端若只读samples/status不会自动理解新字段，须自行升级；本轮未部署运行实例。

## 配置身份切换

检查容量终结路径时发现：此前只隔离了核对记录，旧活动录制仍可能在配置reopen后接收同编号新设备样本，也阻塞新录制开始。现在在准备、读取、结果处理及结束时核对进程内配置scope，旧活动会话以configuration-changed结束、取消计时器、保留原样本、撤销旧句柄；不写当前配置、不把旧日志/核对记录归到新设备。通知回调中切换配置也不会给已终结会话再安装计时器，开始回复带明确done/原因；MCP跳过把它记录为新配置中的“开始成功”。当前主应用无在线工作区切换入口，此处保护的是保留的ConfigStore.reopen能力；未增加切换配置或采集服务功能。

没有给底层poller事件新增配置来源身份，因此不宣称能够识别新会话开始后从旧采集器迟到的同编号报文；普通设备连接字段编辑也不等同于配置reopen的scope切换，录制期间物理连接来源改变的完整样本归属仍需独立检查。旧配置已保留样本继续计入服务总容量，只有删除/既有淘汰才释放，不静默清除。

## 容量边界与验证

这里限制的是Recorder所保留的原始样本数，不是字节级RSS上限；不包括采集器批次、临时数组、序列化输出、外部调用者持有的引用及每段单条触发证据。服务退出不保存内存录制。未新增落盘录制/分页下载；大段完整JSON读取仍有传输与客户端内存成本，长录制需控制点位/时长，或使用已有历史查询/导出。

新增安全套件test-recorder-storage，生产200001边界先失败后通过；小限额隔离回归覆盖同设备/跨设备全局容量、刚好上限/无匹配、已知丢弃计数、容量满开始不改周期、触发前清理、独立触发证据/新计时器取消、触发窗口/超时原因、安全恢复/并发值保留、日志失败、50段淘汰/删除/重复删除及通知回调重入删除计数、配置重开同ID及通知中切换、非法构造参数无订阅。扩展生产MCP注册器mock回归验证开始存储信息和停止/删除完成原因。全部使用内存库、mock事件/时钟/运行处理，不开socket或访问真实配置。
