# 只读近期运行日志查看

2026-11-07，基线`7628878a6063fb6b660bda58a40bbfd081a227bd`，初始工作区干净。根AGENTS.md/.agents仍不存在，核对README、设置页、原/api/logs和ConfigStore.listLogs。此次新增便于实际排障的只读查看器，未运行主应用、读取真实日志/配置/历史库、打开监听端口、连接设备/串口、调用模型、安装依赖、部署/重启/推送。

## 需求证据与范围

设置原“运行日志”区域只有清空按钮，前端没有读取/api/logs的入口；后台已有按ID倒序取最近记录的只读GET，适合查看程序错误而无需先清空或依赖控制台。本轮复用原端点，不扩展后端接口/数据库/保留清理策略，不把source或消息里的设备名称当作可靠设备身份。

## 正式流程

设置→数据→运行日志增加“查看近期日志/收起日志”，默认收起，不发日志请求；打开后GET固定limit=200，手动重新读取，没有周期轮询。离开该设置区域/关闭查看器会取消等待读取，迟到响应不发布。现有清空动作及接口仍保留在原位置，仅在其请求正常返回后增加重读标记，已展开的查看器撤销旧读并重新GET；没有自动清空或新增写方法。

显示原ID、后端时间文本、level、source和完整message；不把未知级别改成INFO、不猜旧时间的时区或设备归属。新读取完成时间是浏览器UTC接收时间，不能当日志产生时间。所有内容按React文本渲染，不把HTML/链接执行或解释。

级别支持原始未知/空值，关键词空格分词、忽略大小写并按字面匹配ID/时间/级别/来源/消息；筛选只在本份快照内，不发请求，不宣称搜索完整历史。每页20条，表格横向可滚动，消息保留换行和长文本。全服务标记不会随当前选中设备变成设备专属日志。

恰好200条仅提示“已达读取上限，可能还有更早日志”，不能证明已截断或全部读完；超过200条的异常响应整份拒绝，不静默切片。更早日志也可能已被原策略清理。本次为空只表示该快照没有记录，不据此判断设备/历史健康。

## 只读读取与异常

RuntimeLogsRead启动/订阅/SSR不读，重复点击合并有效在途请求，10秒超时，关闭/重读代际隔离；旧finally不能清除新读，迟到成功/失败不能覆盖恢复结果。取消只撤销页面等待，不承诺中断后端工作。

解析要求数组<=200、正安全ID严格倒序/无重复和原字段字符串，接受空时间/级别/来源/消息及非ISO时间，复制并冻结，不保留未知额外字段。异常响应整批拒绝，失败/超时保留上次完整数组与接收时间，明确标上次快照/未核实；首次未读取或失败不能显示成空日志。GET使用no-store，错误显示固定类别，不展示HTTP错误原文。

## 限制

这是有限近期快照，不是归档查询、实时告警或日志完整性证明；全服务指本次后端接口的返回范围，不跨工作区合并，也没有服务/工作区身份认证。外部切换后须重新读取，不能将旧快照归因于当前设备或工作区。无总量/游标/服务端条件筛选，未改旧REST对其他limit参数的兼容行为。没有新增鉴权/日志内容脱敏，原日志正文按现有权限读取并在本页显示；没有复制、导出、自动上传或助手发送。200条限制行数不保证消息字节数，超长正文仍会占内存。

现有清空请求的错误/结果不明、审批/并发保护未在本轮改造；不要把只读查看器当作清空成功证明或自动重试许可。真实浏览器点击、粘贴/滚动布局及真实后端数据未验收，mock/SSR通过不代表运行实例已可见。
