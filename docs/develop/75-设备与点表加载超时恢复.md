# 设备与点表加载超时恢复

## 范围与复现

基于干净的`c2b46b460fdd6f6a88efcaea6b49ba1ceebf58d4`，停止继续服务端一致性基础设施工作，转向实际主界面配置加载。没有AGENTS.md或仓库.agents规范可读；保留全部此前提交，未推送。

已核实App.refreshDevices/refreshRegisters使用LatestConfigRead隔离旧请求，但实际request/fetch及正文解析没有等待上限。若设备清单或某组寄存器请求永不settle，正常失败回调永远不到达，顶部重试入口也不显示；点表首次加载可长期停留在未读取状态，同设备刷新则一直保留旧快照。

新增回归先从实际App源码提取refreshDevices回调执行，GET注入永不完成的mock。按测试缩短的等待窗口，本应发布timeout错误，却没有任何错误回调，断言失败。不是只用手写等价逻辑模拟，也没有访问真实服务。

## 已接入的改动

- config-read新增小型只读适配readConfigRequest，复用现有runRequestWithTimeout，默认10000ms；含fetch、JSON解析或HTTP错误正文读取的完整Promise。超时取消子signal并立即settle，即使provider忽略abort，迟到结果也不重新发布。
- App设备清单和readDeviceGroups的每次GET明确经过该适配。设备/点表各自记录timeout或failed，恢复成功才清除；选择另一设备时重置该设备点表错误，沿用现有cancel及身份判断。
- 每个HTTP请求单独计时。之前已成功的组不占后续组预算，正常但总时长超过10秒的多组读取仍可完成；某次超时即停止后续请求，不发布已读部分图。旧完整快照保留，首次失败不当成有效空图。
- ConfigLoadNotice直接替换App旧通用失败栏，分别说明设备清单/点表超时或失败，双语、role=alert和明确重试按钮；提示旧内容未核实、未读不代表空、重试不重复保存。空响应真实成功时正常清除错误，不留假告警。
- 未改变LatestConfigRead类、readDeviceGroups的原组合/取消语义或其他消费者默认行为；没有给保存、删除、录制、设备连接或写寄存器增加取消/自动重试，也不调整任何采集/告警阈值。

这提供等待上限和手动恢复，不承诺停止后台全部工作、全设备图具有服务器事务一致性或当前后台定义未变化；此前导出一致性审计结论保留。

## 回归与预览

`scripts/test-config-read-timeout.ts`加入显式安全白名单，实际执行App当前刷新回调与真实request函数体，仅注入mock fetch/Promise：

- 设备清单挂起→timeout/abort→成功重试/连接映射→迟到旧结果不覆盖；HTTP失败、明确空列表恢复。
- 点表第一组挂起停止后续GET；第二组在第一组完成后挂起，不发布部分图，保留上次完整图；再重试恢复。
- 选择变化/取消不向新设备发布旧错误；每个请求都有新预算，模拟连续成功多组的总耗时超过单次上限仍通过。
- 正常JSON及HTTP失败text正文挂起均超时；预先取消不发GET；写API帮助函数保持原路径。
- 实际提示组件双语SSR、无错误不显示、两类来源及主App重试/属性接线。测试缩短超时只在注入环境，生产默认仍10秒。

`npm run preview:config-loading`生成`output/playwright/config-loading-preview.html`，复用实际读取适配/错误提示，以本页合成数据演示正常、失败、挂起、12秒迟到、空列表、仅一类失败、关闭重开、中英及窄屏；不等同完整App。

预览沿用现有生成器：JS/CSS内联、CSP connect-src none，不启动服务器，不接触数据库/硬件/模型。文件已生成不代表浏览器已打开或视觉验收通过。本轮发现的连接工具中没有新增可用的受支持浏览器自动化路径；遵守既有浏览器安全拒绝，不重试原生Edge或换路径绕过。真实DOM交互与窄屏视觉仍需人工核对。
