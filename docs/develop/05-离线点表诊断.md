# 离线点表结构诊断

2026-11-06，基线 cdb8500。本功能仅读元数据或显式指定的 JSON，不导入/恢复或修复配置，不连接设备、串口、历史数据库或模型。

## 直接使用

在项目根目录执行，无需启动主应用：

```powershell
npm run diagnose:points -- "C:\路径\probestation-config.json"
npm run --silent diagnose:points -- --json "C:\路径\probestation-config.json"
npm run diagnose:points -- --help
```

第一个命令给可读报告，第二个为纯 JSON（用 npm --silent 去掉 npm 自身日志）。文件必须显式提供且扩展名为 .json；没有默认数据库路径、自动扫描目录、导入或文件覆盖行为。可用现有设置页导出的 format=probestation-config/version=1 备份；也可用仅含 devices/groups/registers 对象数组的结构图。含备份标识时版本不支持则拒绝，不假定未来格式兼容。

退出码：扫描完成且无错误为0（可能有警告）；有结构错误为1；文件/JSON/输入格式或参数失败为2。报告含 scope=point-table-structure、ok、complete、summary（扫描数量、错误/警告、潜在覆盖占位数）及 issues（代码、严重度、位置、相关设备/组/点位ID）。不输出连接凭据或完整配置。

新代码也提供只读入口：

- REST：GET /api/monitor_objects/:id/point-diagnostics，扫描完成200，即使 ok=false；无效ID400，设备缺失404，读取失败500。
- MCP 和内置助手：diagnose_points {device_id}，沿用助手设备会话范围。不查询最新缓存/历史、不改变采样周期，不自动生成修复提案。
- 纯合成隔离测试版提供同一 GET；AI/写操作仍禁用。

本轮只做 Fastify.inject、注册器/fakeFetch 和离线子进程验收，没有启动/重启测试版或部署到实际9090实例，原运行实例不会自动获得此功能。

## 错误与警告

| 级别 | 规则 |
|---|---|
| 错误 | 非正安全整数/重复配置ID，设备/组引用不存在或不唯一，点位与组的设备/功能码不一致 |
| 错误 | 组功能码非FC01/02/03/04，组起始/长度非法或超过0–65535，现有读取协议校验不接受的从站/请求 |
| 错误 | 不支持的dtype，点位地址非法/溢出，起始不在组内，未被前一有效多字点覆盖的点宽超组尾 |
| 错误 | 显式quantity元数据不是正安全整数；不拿其数值代替dtype字宽 |
| 警告 | 当前运行代码将缺失角色/从站默认为master/1；只提示默认行为，不写回或补样本来源 |
| 警告 | 编解码器可识别的旧_LE等后缀拼写，现有备份校验却要求规范-LE |
| 警告 | 同源同区同址重复/不同配置定义；可能为有意的不同视图，不自动删除/判为错误 |
| 警告 | 被前一有效多字点覆盖的有语义定义，或覆盖定义自身字宽超组；不把已有占位布局全部判坏 |
| 警告 | 同来源不同组的有效多字区间部分重叠，各组响应独立，缓存多字可能暂时未知 |
| 警告 | 同设备FC/地址有多个定义，现有语义导入只取第一个匹配，无法唯一定位 |

多字宽度直接使用 registerWidth：16位1字、32位/q31为2字、64位4字，BE/LE/hex/bin沿用codec。整组可超过单请求125/2000长度，poller已有拆读，因此不把126字分组直接当协议错误。源范围按当前协议/本地从站1–247校验；更宽的历史来源元数据字节范围不等于当前可配置请求范围。

默认无别名、单位、枚举或换算语义的int16尾随行，位于前一个有效宽点覆盖范围时兼容计数，不单独警告。同起始地址的重复行不算尾随占位。覆盖是“前点取得完整有效字时”的结构性关系，无法代替实际采样质量判断。quantity 缺失的旧备份仍可诊断，不要求按dtype回算；合法非默认quantity保持原样。

来源、设备与数据区分别隔离：不同从站相同地址不是物理重复冲突；但无来源语义导入仍有确定的匹配歧义，所以可能只有 IMPORT_MATCH_AMBIGUOUS 警告。本地slave模式采用设备自身编号，忽略采样不使用的组从站号。暂停的组也检查结构，便于启用前发现问题。

## 兼容与限制

诊断不调用完整备份恢复校验器，以便报告其未覆盖的关系：例如组[0,2)、uint32从1开始，起始在组内但完整宽度到3，现有备份校验可接受，诊断会报 REGISTER_WIDTH_OUTSIDE_GROUP。完整备份字段、连接参数、报警策略、枚举内容、原设备真实类型/倍率意图不在本轮完整校验范围；ok不保证备份可恢复、设备在线、值可信或PASS/FAIL。

没有诊断原始历史或回填NULL来源，也无法从已导入配置恢复丢失的原文件意图。重复/不同视图可能有意，只有用户确认后才能另行修改；本功能没有自动修复接口。诊断不改变现有JSON/语义/MBP/MBS/XLSX导入规则。

只读检查已核实两个独立导入风险：语义导入按FC/地址取首项；MBP多窗口导入可能将全部点位挂到首组。合成MBP内存回归能报告后者的功能码/组不一致，本轮没有修复导入或导入任何真实配置。

## 实际验证

安全清单共29组。新增test-point-diagnostics覆盖边界/冻结输入/旧元数据、默认占位/重复定义、跨源跨区和重叠、10000条重复定义完整引用、内存备份与合成MBP导入、只读API失败，以及新临时目录内真实CLI子进程（输入文件不变）。test-mcp-source/test-assistant验证生产handler/fakeFetch的只读边界；test-history-integrity验证纯隔离装配的诊断GET。

CLI只导入纯诊断模块，不导入ConfigStore、驱动或应用启动器。测试配置库只用:memory:，历史/隔离装配沿用新临时目录；没有真实设备、串口、模型、生产数据迁移或服务操作。没有新增UI控件，既有浏览器视觉和实机验收限制不变。
