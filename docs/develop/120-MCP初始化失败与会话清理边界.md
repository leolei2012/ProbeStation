## 先复现的三个问题

只新增测试、生产代码保持基线时，分别运行registration、connect-reject、uninitialized，三项均退出1，证据保存在mcp-lifecycle-before-*.log。

- 工具注册同步异常逃出POST end事件回调，断言doesNotThrow失败；真实HTTP回调未捕获时可能导致进程异常退出。测试只用合成错误，不使实际服务崩溃。
- SDK start/连接返回拒绝时，仍调用handleRequest，观察次数1而非0。原实现分开启动connect与请求，没有等待连接成功。
- 实际SDK在Accept不满足时返回406、未分配session ID；关停仅遍历session map，未调用这个transport的close，观察次数0而非1。该例证明所有权遗漏，不据此宣称每个拒绝请求都会留下活动定时器或永久内存泄漏。

## 最小修复

把来源/初始化判定、工具注册、transport构造、await connect和handleRequest纳入已有track任务。工具注册或连接失败由原HTTP错误路径处理；连接成功前不处理请求。关闭期间新请求沿用503，连接等待结束后若已关闭则返回503，不把主动关闭当初始化失败。

另外维护HTTP transport所有权集合，从构造后即登记，不依赖session ID。onclose同时解除所有权和会话索引。失败的新连接立即关闭；SDK拒绝初始化且没有session ID时，在请求完成后关闭。正常已初始化会话保留原有状态与重连行为，现有会话某次请求失败不因此一概删除。

closeTransport用WeakMap缓存同一个关闭Promise，防止请求失败与整体关闭重叠时重复close。关闭错误单独保留，依赖关闭仍可观察原始对象；关闭期间尽力继续处理其他transport、HTTP listener和在途任务，再用已有throwCleanupErrors去重/聚合。请求初始化和清理同时失败时保留两种错误，不以清理错误替换原操作错误。

所有工具名称/schema/说明/注解、注册函数和工具处理函数体不变，Config/默认端口、采集、录制及外部响应格式不改；本轮无数据库迁移、新依赖、新服务或自动重试。仍沿用既有400/500/503与SDK的406等错误策略，不新增协议字段。绑定失败仍通过原日志和清理错误报告，未新增MCP就绪接口或自动重绑。

## 验收边界

真实HTTP客户端、实际套接字断开、SSE长连接/代理/跨进程行为和部署环境尚未验收；light-my-request是流模拟，不是网络验收。工具失败测试覆盖选定同步/异步只读路径，不代表全部工具、硬件和外部模型错误已穷举。初始化请求正文仍沿用原有缓冲/解析逻辑，本轮未增加请求大小上限或连接超时；长期不完成的自定义SDK任务仍可能延迟关闭，不虚称有限时强杀。

关闭失败夹具在SDK实际关闭后抛出合成错误，验证onclose先移除索引时仍能报告原错误、继续其他清理；未穷举SDK关闭前失败或同时多故障，不保证任意失败下资源全部释放。公开createServer()供其他调用方创建的非HTTP服务端仍由调用方负责close，本轮所有权集合仅管理插件自身创建的HTTP transport；内存客户端夹具在finally显式关闭两端。

真实数据库启动清理、真实设备、用户在用服务均未操作。本轮不改变主程序信号处理、全局health/ready契约或已有采集退出策略。
