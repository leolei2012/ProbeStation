# 配置刷新顺序与设备切换

状态：已实现，完整离线检查通过；浏览器验收未完成。日期：2026-11-06。

## 已验证的问题

设备/点位编辑后会手动刷新配置，配置通知也会触发刷新。原设备列表没有响应顺序保护；原分组/点位只检查设备ID，同一设备的旧请求晚返回时仍被接收，能把较新的名称、单位、类型等显示回旧值。

使用两次同设备模拟读取，新请求先返回“saved unit”，旧请求后返回“old unit”，原仅检查当前设备的逻辑最终显示旧值，失败回归确认问题。

## 改动

- 设备列表与分组点位各自使用独立的 `LatestConfigRead`，只有最后一次仍相关的请求可以提交结果或错误；新读取发送旧请求的取消信号。卸载/切换时取消，旧成功/失败不回填。
- 分组读取在开始前和发布前都核对选择。旧设备的保存回调不能发起一次过期读取并取消当前设备的读取。
- 分组快照带设备ID；选择新设备的首次渲染就隐藏旧设备的分组，无需等待effect清空。
- 分组及其全部点位读取完成后才发布；取消后不再发起后续分组GET，失败不发布半份配置。字段和值原样保留，不重算点宽、倍率或来源。
- 列表与点位的加载错误分开保存，任一仍失败时保留重试提示；成功的一边不再清除另一边的错误。

本轮只改浏览器配置GET的调度与状态，不把写操作放入取消器；不修改后端、数据库结构、采样、告警或设备配置，不新增依赖/权限。

## 限制

这保证浏览器请求顺序与选择归属，不代表服务端事务快照或配置版本校验。配置图仍由多个GET组成，期间服务端可以变化；WS消息与HTTP响应也未增加统一版本。本轮不新增读取时限，HTTP取消不保证强制中止后台查询；同设备刷新失败时仍保留上次已接收的数据并提示重试。

实际浏览器快速编辑、设备切换、配置通知重叠、重试提示和卸载流程尚未验收；此前浏览器连接受限，本轮不重试受限原生Edge或扩大权限。未部署、重启采集服务、操作实机或读取/修改真实配置与历史数据。
