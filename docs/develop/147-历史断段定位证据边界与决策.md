# 历史断段定位：证据边界与决策

基线 9102d1422aa5ecb95b73b0ae2102297dac39550c，工作区起始干净，AGENTS.md/.agents 不存在。本轮只读审查生产代码，用内存库和进程内只读路由证明数据边界；未实现断段/故障定位界面，未增加生产协议或未接入基础设施。

## 现有链路与可证明的事实

生产入口为 HistoryView → historyQueryPlan → GET /api/data/object/series → registerCurve → DuckDBStore.queryRegisterCurve → CurveSampler → HistoryChart/historyLineStarts，使用选定设备、配置从站和点位定义解码。现有搜索、曲线资格解释、质量汇总、缩放及 A/B 对照并不是完整断段事件清单。

| 字段/行为 | 能证明 | 不能证明 |
| --- | --- | --- |
| PollPoint: timestamp、area/address、quality、batchId、slaveId | 已写入的一字记录及逻辑来源/响应身份；旧行身份可能 NULL | 应当采了几次、为何没有行、物理设备身份、当时实际调度/启停/点表代际 |
| decodeHistoricalSample | 对当前定义检查缺字/重复、质量/字域、混批/来源、非有限值；旧身份可保留可查看值并标未验证 | 硬件通信失败原因；旧身份缺失不自动等于坏值 |
| summary.sourceSamples/validSamples/invalidSamples | 当前查询原始流按点位与时间解码后的数量，先于显示降采样 | 原始字行数、预期采样次数、缺测次数、故障次数或时间占比 |
| sourceGapMs | 当前查询原始时间间隔正值中位数 ×3 的绘图阈值 | 历史设备配置的固定周期、绝对断线阈值；它会随查询范围变化 |
| segments | 降采样前逐解码样本按间隔阈值或不可绘制值递增的段号，在返回的保留点上保持 | 所有段的首尾/无效时刻。一次大间隔又无效可递增两次，段号差不是故障次数 |
| gapMs | 返回显示点间隔推导的兼容绘图参数，旧响应无 segments 时仍使用 | 原始采样间隔；不能据此生成缺测/故障结论 |
| samples 的 null、verification/integrity | 当前定义下不可绘制或批次/逻辑来源未核实等状态；计数可覆盖全部解码流 | null 的具体原因，响应没有逐点 reason；unsafe 64 位等显示限制也可能 null，不能一律称坏质量 |
| 前端 curveValue 的物理量换算 | 非有限换算结果不绘制，原始字与原始质量汇总不变 | 空线或断线不一定来自原始样本/设备；也可能仅是显示换算溢出 |
| complete=true / 空结果 | 该查询按现有语义返回结果，空结果没有匹配样本 | 整段时间都曾采集、没有清理、设备健康；完整查询不等于完整采集 |

Poller.pollNextGroup 成功才写 quality=good 的原始字；驱动连接/读取异常进入 setGroupError/自动恢复路径，没有在这条路径插入对应坏质量历史行。poller/group-error/group-ok 经 API 广播为页面状态事件，当前曲线响应没有带上可关联的持久化启停、连接失败与恢复时间线。因此不能从无行推导通信故障，也不能区分低频、轮询调度变化、暂停/未采集、服务未运行、清理或其他没有持久化的原因。本审查未声称其他运行日志绝对不存在，更未读取真实日志。

## 可重复的离线证据

新增 `npm run audit:history-breaks`：实际 ConfigStore/DuckDBStore 均强制 :memory:，设备设为停用，仅注册只读曲线路由并 app.inject，不监听端口；不导入主入口、驱动、采集器、模型、浏览器或用户路径。所有自建资源通过公开 close 清理，失败保留原错误和清理错误。

1. 坏质量、缺低字、同一多字的不同 batchId：三份不同原始输入的完整曲线响应完全相同，都是 source=3、valid=2、invalid=1，不能从现有响应恢复具体原因。
2. 11 次采样含 5 次无效，低显示预算返回 3 点、其中仅 1 个 null，绘图起点数 2，最后原始段号为 5。总计数正确，但不能准确列出五次无效的全部时刻或每一段边界。
3. 同一批存储时间为 0/1/2/12/22/32 秒，全范围 sourceGapMs=30000、仅初始一段；查询至 12 秒则阈值=3000、出现第二段。两次均未降采样、无效样本均为 0，是查询口径变化，不能称设备故障。
4. 每分钟一次的五个正常样本只有一个绘图段，阈值 180 秒；查询首端 60 秒、尾端 300 秒没有返回样本，但响应不能判断这些时间本应采样。空结果仍 complete=true；单点没有可估计间隔，sourceGapMs=null。
5. 缺 batchId 的旧单字仍保留可绘制值，valid=3、unverified=3、invalid=0，不能把未核实批次混称断段或质量故障。
6. 原始数值 10 的三次有效采样，倍率换算溢出后前端全部为 null、没有可画线，但原始质量汇总仍 valid=3/invalid=0；不可据空图判定通信故障。

## 最小设计与推荐决定

现有数据足够做“当前显示断线索引”，最多说明当前返回样本之间怎样画线：保留前后样本时间、标明只是显示边界、原因未记录/间隔估计/保留无效点；旧响应无法验证原始分段，查询首尾缺数和全空不得补造边界。它不能声称完整定位、故障起止、缺测次数或实际通信状态。本轮不把这个受限索引作为完整断段定位交付，也不改变当前兼容绘图策略。

推荐下一步先在当前原始解码流上设计只读、可选且有界的证据元数据，再接导航：

- 只记录 `不可绘制观测` 与 `观测间隔超过本查询估计阈值`，分别保留实际观测时刻、前后真实样本时间、阈值/算法口径、可确定的解码原因。未知保持未知，不映射为通信故障。
- 与曲线/质量汇总在同一解码流中生成，不对降采样结果反推，不另做无法配对的查询。标明查询范围、定义/来源上下文、边界被查询范围截断与否；前后无样本一端保持 null，不假定故障从查询边界开始。
- 必须有数量预算、总数和明确的截断标记，避免每个原始样本一条事件造成无界内存。没有快照/续读契约前不承诺完整分页。兼容旧服务时缺字段仅提示未提供，不回退成故障推断。
- 导航只由用户点击触发已有时间窗口查询，沿用取消、迟到响应和配置上下文保护；重新缩放可改变统计阈值，不能把前次估计当作固定故障。真实来源、暂停/失败原因和历史配置的可信判定另需持久化生命周期/调度证据及产品策略，本轮不猜、不新增迁移。

这是一份设计建议，不是已实现 API；生产代码、数据库结构、采样及绘图均未改。不需要用户为本轮审计批准硬件操作或真实库迁移。
