# 导出配置只读事务快照

## 第一阶段与边界

基于干净的 `2d3ef98df14f46faa4eed7c4683dfa4ece5f5ea1`，从68号评估选择可独立验证的第一步：只实现配置层一致读取，不改变现有HTTP/MCP/Sink接口，也不接入条件导出。保留已有提交，未启动主应用、工作区切换或设备服务。

新增 `ConfigStore.getHistoryExportConfiguration(objectId)`，返回 `HistoryExportConfigurationSnapshot`：version=1是结构版本，configurationScope是本ConfigStore实例/打开周期标识，device/groups/registers是固定SELECT投影的整台设备配置。包括空组、多从站同地址、point.quantity等元数据；不加入规则、日志、固件或其他设备，不合成来源、不修正原始配置、不解码或读取历史。

普通配置字段修改不旋转scope；相同文件的不同ConfigStore实例也有不同scope。它不是内容revision、全局共享版本、物理身份、workspace epoch或时序库租约。未来条件导出仍需要规范定义指纹和配置/时序库配对生命周期，不能只比较这个scope。

## 读取与失败行为

先严格校验正安全整数设备ID，在配置批量恢复或此能力已阻止时拒绝。BEGIN后在同一个SQLite读取事务中完成设备、全部分组和点位查询，复制/冻结每个对象及数组；COMMIT成功才返回。enumJson仍为原字符串，0/NULL/quantity等不重算。SQL范围通过绑定参数选择设备，不接受任意路径或SQL。

BEGIN不成功时不回滚别人的事务。读取或COMMIT异常时尝试ROLLBACK，不返回半份结果；正常回滚后可重新读取。若回滚也失败，抛出AggregateError，旋转scope并停止该能力，直到显式成功重开；不吞异常或继续提供可能过时的快照。reopen开始即失效旧scope并暂时阻止此能力，打开成功才解除。只新增内存状态，未修改schema或迁移步骤，也不改变旧读写方法语义。

该方法没有await，事务不跨历史库查询；不会触发notify、清理、轮询、连接、重连、串口或模型调用。新方法尚未由任何运行入口调用，旧导出依然保留68号审计指出的限制。

## 仍未解决

本方法只保证一份配置图的读取一致性，不冻结之后的配置，不证明历史样本属于这些定义，也不阻止其他连接修改。不新增点宽、重复定义或组/点一致性校验；后续条件协议还需验证投影，不能把一致快照直接当作合法配置证明。读取期间WAL中的写方可以提交，但本次事务仍看到其建立的读视图。现有SQLite运行模式或锁竞争下可能失败，应让调用方处理错误而不是回退散读。

完整版本保护仍未启用：缺少工作区/时序库epoch、读连接代际、preview及同一collect副本校验、能力和成功回执。下一独立步骤应先在mock/临时库验证配对生命周期与切换失败，之后才组合条件导出；不能先将新方法结果与旧GET拼接就宣称原子性。前端仍是a97b51d的已知变化保护，未知后台变更缺口保留。

未修改界面，因此本轮没有新UI验收；原浏览器盲区、真实工作区并发和设备均未验证。未推送、部署、重启、操作实机、调用模型或修改真实用户数据；完整构建若更新本地dist，不代表运行实例已验收。
