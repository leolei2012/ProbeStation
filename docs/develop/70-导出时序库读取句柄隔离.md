# 导出时序库读取句柄隔离

## 本轮范围与证据

基于干净的 `c3fcc979866ef77f60e525c0454979cc3c51d857`，继续68/69号方案，选择只解决可独立验证的时序库读代际。旧API、Sink、配置快照、工作区切换及前端不改接入；不凭单独预检宣称整体一致。

修改前执行实际DuckDBStore构造/reopen/导出读方法，仅替换native初始化、连接及flush/cleanup为mock：在新连接尚未就绪的重开期间调用旧queryObjectForExport，随后得到替换连接的200，而打开前假数据为10，断言失败。说明旧未绑定读路径不保护此窗口；该复现不连接真实数据库或设备。旧路径仍保持兼容，此缺口不因新增可选方法而自动消失。

## 新内部契约

captureExportReadHandle只读取实例状态，初始化就绪且未被生命周期门禁阻塞时创建冻结的 `{version:1, storeScope}`。WeakMap保管当前代际与ready连接Promise，原生连接不暴露，也不打开/查询/flush/清理数据库。句柄必须是本实例创建的原对象；伪造、拷贝、JSON往返或另一实例的对象都会拒绝。它不是授权令牌，也不是保持连接存活的租约；调用方丢弃后可GC，不阻止旧连接关闭。

queryObjectForExportWithHandle是新增的显式路径。参数范围/从站在任何await前复制，固定该句柄记录的ready；等待写队列后、连接后、SQL前后及行转换完成后都核对所有权与代际。若scope/ready已换或正在重开，则抛出固定ExportReadHandleError，code为EXPORT_READ_HANDLE_INVALID，不把旧响应当新库结果；旧SQL异常若发生在已失效代际也转为该错误。当前代际真正SQL失败仍保留原异常，不补空结果。空ranges也必须先有有效句柄。

reopen开始就旋转scope并撤销全部旧句柄。失败保持新能力不可用，直到成功重开；失败初始化也不可捕获句柄。普通写入/flush不变更scope，因此句柄不是内容版本、数据快照或已落库证明。初始未就绪不自动连接或等待重开来制造有效句柄。

共享底层读取仅增加可选拥有者检查：旧queryObjectForExport/queryObject签名、SQL文本、原始行上限、参数绑定、时间/质量/NULL来源/批次映射保持。未传拥有者的旧调用不会被新增检查拦截；未修改schema或写入缓冲行为。

## 可控验证

新增显式白名单 `scripts/test-export-read-handle.ts`，只用mock和真实`:memory:`配置/DuckDB：

- 实际构造、reopen、读取方法配受控连接/队列/初始化/SQL屏障；不就绪或重开中拒绝捕获，重开开始即撤销旧等待，旧SQL迟到成功/失败均不返回，且不转到新连接发SQL。
- 参数在等待期间被调用方修改不影响已捕获来源；200001 lookahead及空范围语义；伪造/复制/跨实例/旧句柄即使空范围也拒绝。
- 当前代际SQL失败保留原Error对象，NULL来源/批次与旧查询一致；flush导致重开失败后拒绝新能力，成功重开才恢复；同路径重开和并发重开请求按原流程验证。
- fake实例保留自己的初始化/清理mock，异常清理恢复prototype时不会转去真实文件；所有假路径固定为`:memory:`，不接受用户地址。
- 真实内存配置快照及内存DuckDB：旧句柄正常结果与旧查询相同，重开后写入200，旧句柄拒绝、新句柄读200。配置scope仍旧，直接验证配置和时序库生命周期并未自动配对。

针对性套件及服务端类型检查退出0；本轮完整 `npm run check` 退出0，包含前后端类型检查、Vite构建、包体预算和93组安全测试。首屏JS为488396字节、gzip 161892字节，与基线相同；这是构建数据，不是浏览器加载耗时。完整检查的临时目录显式限定为仓库内 `.npm-cache/probe-test-temp`。没有创建或迁移用户库，没有启动主应用、poller/串口/PLC或模型，也不下载文件。

## 未解决边界

这是可选的单个Store读所有权，不是配置与时序库配对协议。Store重开完成而ConfigStore尚未重开时，仍可能捕获一个新store句柄搭配旧配置；本轮不为该组合签发版本，也未改变现有工作区顺序或清理流程。后续必须先建立覆盖整个切换过程的workspace epoch/失败门禁，再把配置快照与句柄一起校验，包含生成附件后的检查。

既有GET/MCP/Sink仍使用旧读入口，其未知后台变更/跨库风险保留；前端仍只有已知变化保护。直接使用新方法也不证明样本来源/完整性或生成PASS/FAIL，不阻止正常数据更新或清理。初始化或重开失败可能需要新实例/成功重开，未承诺任何自动恢复。

未改UI，无新增界面验收；真实工作区切换/完整配对和浏览器未验证。未推送、部署、重启采集、操作实机或修改真实用户数据。
