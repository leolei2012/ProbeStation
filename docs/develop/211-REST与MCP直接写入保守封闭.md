# REST与MCP直接写入保守封闭

> 状态：本地生产入口防护，2026-11-11，基于324f266；未部署。用户已明确接受影响现有自动化的接口限制。本轮不恢复GUI写入，不迁移真实库。

## 决策：无法证明绑定的入口从启动即关闭

208–210号验证尚未证明配置多写者、驱动最终提交和响应归属的完整安全链。因此没有采取“先允许一次、出错后靠本进程标志禁用”，也没有依赖通知、文件sidecar或配置库版本作为万能发送保护。新代码从服务装配时就拒绝下列所有新调用；配置变化及任何旧结果未知时同样关闭。

这比仅在变更/异常后封闭更保守。没有可变的enabled状态、配置项、环境变量、确认按钮、恢复端点或TTL；相同新代码的其他进程、会话重建与重启后仍拒绝，因而不需要一次可能丢失的“锁定状态写盘”。它不是针对仍运行旧代码或任意外部程序的跨进程硬件栅栏，也不是可由管理员随手确认解锁的恢复功能。

## 覆盖与兼容性

| 已封闭入口 | 新行为 | 未发生的操作 |
| --- | --- | --- |
| POST /api/registers/:id/write | 503，JSON code=DEVICE_WRITE_BLOCKED，Cache-Control:no-store | 不查点位/分组，不编码、不调用poller.write，不写成功日志；同时覆盖原主站和设备从站内存分支 |
| PUT /api/slave/values | 同上 | 不修改全局从站内存，不读取旧值作为写成功回执 |
| POST /api/ota/upgrade | 同上 | 不调用startUpgrade，不生成新升级任务 |
| MCP write_register / ota_upgrade | isError=true，text中JSON含同一code及恢复说明 | 在toolRegistrar注册时替换这两个回调；实际工具回调不执行配置读取、底层写或升级 |

HTTP路径和MCP工具名/输入schema保留，成功行为有意改变；原自动化依赖的写成功、数值校验400、找不到点位等结果可能变成统一拒绝。无效JSON、框架路由或MCP schema错误仍可能先被框架拒绝，不承诺所有错误均携带此code。`retryable:false`表示本服务不提供盲目重试路径，不是操作幂等回执，也不能禁止客户端自行重发。

统一说明明确：发送来源/结果尚未核实，勿重试；重启、重连、配置修改或确认旧结果不会解禁；此前在途请求及其他程序结果仍需另行核实。不返回虚构的设备执行结果、当前值、固件task_id或“所有旧操作已撤销”。保留旧请求已接纳后完成的隔离反例，不能因本轮入口关闭就声称旧设备没有变化。

## 恢复条件和剩余可达路径

当前没有解锁API。恢复必须另行评审并实现可验证的发送能力：可信配置实例/版本、所有实际通道拥有者、不可复用连接代际、紧邻字节接纳的条件检查、响应归属和未知结果隔离；还须受控处置旧进程/在途任务并核对实际状态。单纯清理日志、重启、重开数据库、等待一段时间或勾选“已确认”都不满足条件。本轮没有执行这些真实环境步骤。

- 只读监控/历史、配置编辑与导入、固件文件上传/列表/删除、OTA状态与abort、本地从站start/stop保留原语义。本轮不是所有配置写入的互斥/幂等改造，配置保存未知结果仍按既有保护处理。abort也不保证已发字节撤回。
- 新版本内置REST/MCP直接值写与升级启动已封闭；内部poller/驱动/DeviceSlaves/OTA类、raw socket及第三方插件直接调用没有新增底层栅栏，不能宣称所有程序入口安全。新工具或新路由未来加入时仍必须审查。
- 旧二进制、已装配的旧处理器、已加载旧页面指向旧后台、其他配置库/程序、外部Modbus主站仍可能写设备或从站内存；在途任务没有被本次文件修改取消。没有修改外部Modbus协议或打开任何实机端口。
- MCP工具名及旧描述不能视为当前可写能力；必须处理明确的工具错误，不降级到其他通道。此变更需要前后端/自动化发布说明，不能只替换本地文件就以为在用服务已更新。
