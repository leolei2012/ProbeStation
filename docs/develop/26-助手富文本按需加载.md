# 助手富文本按需加载

状态：已实现，完整离线检查通过；真实浏览器未验收。2026-11-06，基线`d6383a9`。

## 已核实的瓶颈与范围

原`AssistantMessage`静态引入`react-markdown`及`remark-gfm`，经始终挂载的助手面板进入首屏，即使用户只观测设备、没有查看助手正文。前轮构建主JS为536.35kB（gzip172.97kB），已有大于500kB的chunk提示。

本轮仅把富文本解析/展示模块变为动态导入，保持助手面板、会话恢复/后台状态、目录/来源、提案确认及配置行为的原装配。没有改变模型提供商、请求、工具权限、数据持久化或采集，也未调用实际模型服务。

## 用户行为

- 只有可见的助手正文使用富文本渲染器时才加载；用户、工具和执行结果仍直接显示，不触发该资源。关闭状态的助手不因已有正文加载解析器。
- 初次加载期间正文完整以纯文本显示，包含原始Markdown标记；不会留空或截断。流式正文继续变化，加载成功后使用当前内容，不回到旧快照。
- 资源加载失败或超过10秒，保留纯文本，显示“重试富文本显示”。手动重试只加载显示代码，不重发消息、不创建会话、不确认提案、不调用模型或设备。
- 同一页签内的多个消息共用一次在途加载，成功代码缓存复用。失败后新增消息/重新打开不会自行循环重试；任一重试会共同恢复。关闭消息只取消其订阅，已发出的代码导入可继续并被缓存。
- 富文本成功后沿用原GFM表格、代码和链接行为：不渲染原始HTML、图片只显示占位文字，外部链接保留`noopener noreferrer`。纯文本回退也通过React转义，不解释HTML。

动态导入无法直接取消，超时后旧结果不会覆盖状态；浏览器缓存了模块失败或旧版本文件已不存在时，手动重试也不保证恢复。不会为此自动刷新页面或重放业务操作。纯文本回退不是富文本渲染过程中任意异常的错误边界；原解析器语义及其他助手功能未重写。
