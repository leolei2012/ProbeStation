## 选择依据

在已有隔离源码上以 esbuild 的压缩输出归因检查静态依赖图，再用 Vite 正式构建及 manifest 静态闭包核实结果；归因数值不当作最终构建体积。自有模块中 App 仍最大（归因约 134.7 kB），助手约 12.1 kB，诊断清理约 9.1 kB，设备表单约 8.0 kB，分组表单约 7.0 kB，串口选择器约 3.7 kB。设备和分组表单只在点击新建/编辑后显示，但此前全部静态进入首屏。助手即使收起仍恢复会话和观察运行状态，直接推迟其挂载会改变生命周期，故本轮不动它。未拆巨大的 App 或扩大到全局焦点管理。

## 行为与代价

App 只静态依赖轻量 DeferredConfigModal；原 DeviceModal、GroupModal 及其表单专属依赖由两次独立动态导入提供。共享已存在的 DeferredResource：并发打开只加载一次，成功后复用模块；超时或失败保持明确错误，关闭后不会被迟到代码重开，重新打开不会自动重试失败，只有显式重试才重新请求界面代码。重试不携带保存数据，也不重放业务操作。

加载期间只有状态、关闭和失败重试按钮，不创建表单、草稿或发起配置读写。成功后使用当时仍打开的当前组件 props 显示原表单；原表单在首次显示时建立既有配置快照和草稿。设备页按原设备 ID 的 key 卸载，因此旧设备已关闭的消费者不会因模块迟到而重新出现。表单显示后沿用原保存函数、并发条件、未知结果提示、草稿确认和串口选择，模块资源变为 ready 后不会反复挂载/清空正在编辑的表单。

加载窗口支持中英文状态、Escape（避开输入法组合）、Tab 环绕、关闭按钮初始焦点。只在窗口实际移除、焦点落回 body、没有另一弹窗且原触发控件仍连接/可用时尝试恢复焦点；不会聚焦已卸载或禁用的控件。

## 自动验证与边界

新增 config-modal-loading 白名单，共 8 组受控组合：静态接线和 SSR 不加载模块、独立/合并加载与当前 props、失败与手动重试、关闭/设备替换与迟到代码、超时旧结果隔离、键盘关闭与焦点恢复约束、实际设备草稿/未决保存、实际分组显式提交及未知结果保留。通过实际组件函数、原编辑器和模拟 hooks 组合验证；不是 React DOM 或浏览器验收。首轮新测试因测试夹具把 React 18 的 ref 当普通 prop 读取而失败，修正为读取元素 ref 后 8 组通过；没有为通过测试修改业务保护。

包体检查继续按 manifest 的所有静态依赖累计首屏，不以文件数或单个文件大小规避预算。新增 source/manifest/HTML 三重门禁，设备/分组表单及串口选择器不得静态可达或被 HTML 预加载。保留 Markdown、设置、点位诊断和通信统计门禁。
