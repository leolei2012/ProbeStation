# 多从站相同地址来源隔离检查

> 状态：后端告警第一步已修复，完整隔离未完成｜2026-11-06

从 73413b5、干净工作区开始，只读源码及内存/mock 复现，没有访问真实配置/历史库、抓取设备报文或连接实机。

## 已核实模型与协议

| 环节 | 事实与风险 |
|---|---|
| 配置 | 点位属于 groupId，分组保存 slaveId；主站读取用分组 slaveId，缺失时既有代码默认 1。本地 slave 模式使用设备自身编号。 |
| 驱动 | FC01/02/03/04 read 方法有 slaveId 参数，TCP 客户端和 RTU 请求均使用此目标编号；驱动返回数据数组。本轮保留调用上下文，不猜测或修改协议，也不声称额外认证物理设备身份。 |
| 原 poller | 请求时知道从站，但 points 只保留设备/数据区/地址/值/时间/batchId/quality，来源丢失。 |
| 原后端规则 | 按数据区/地址/批次选完整字，完整 batchId 不能证明属于目标从站。 |
| 热缓存 | key 为 objectId:area:address，第二个从站覆盖第一个；快照没有来源。 |
| 冷库 | poll_data 没有 slave_id，flush、raw query、分页与曲线都未保留来源。 |
| 前端/助手 | 消费缺来源的快照与历史，前端 WebSocket reducer 也未保留 slaveId；新事件增加字段不等于全链路隔离。 |

## 复现与本次修复

同设备两个分组分别读从站 1、2 的同一数据区相同地址，值为 5、65536，两条规则都比较 >65535。旧 pollOnce 合并事件令两条规则均告警（实际 [1,2]，预期 [2]），回归先失败。

本次 readGroup 每字输出目标 slaveId，pollOnce/轮询沿用原事件结构传递。后端先选目标从站再选完整批，保持同从站重叠组兼容；其他来源不能触发/解除目标告警，多从站下无来源事件及无来源补字被跳过。去重签名增加目标来源，已知来源告警事件携带 slaveId。阈值、实际请求、批次身份及硬件调用不变。

scripts/test-slave-source.ts 通过 mock 驱动覆盖四个读 FC、pollOnce/轮询、32/64 BE/LE、误触发与误恢复、旧事件缺来源、跨从站同 batchId、混入旧字和修改目标从站后的去重；原单从站与同从站重叠分组回归继续通过。

另用内存 DuckDB 复现未修路径：同设备同址写从站 1 值 5、从站 2 值 100，热快照仅剩 100 且无来源；冷库两行来源均缺失，两条同址曲线均得到 [5,100]。这是待修缺陷，没有把错误行为写成必须保持的回归断言。

## 必须继续处理的范围

1. **来源持久化**：可空 slave_id 保存当时请求目标；原子迁移、类型校验、失败回滚/缓冲保留和全部 raw query/JSON 往返仅用临时库验收。旧行保持 NULL，不能用当前配置、默认 1、时间戳或 UUID 回填。
2. **热缓存/实时链路**：键增加从站维度，REST/WS 初始与增量/兜底、表格、曲线、前端告警及助手同步改造；旧 key 来源冲突时须未知，不能继续代表最后一个响应。
3. **历史消费者**：曲线、表格、导出配额/筛选、助手/MCP 需明确目标来源。旧 NULL 行只能作为来源未验证的兼容原始数据，不能归到某一从站或用于自动评估；同址无法归属时未知/明确拒绝。当前分组修改从站后，历史来源选择与提示也需明确。
4. **验收**：不同从站同址、同毫秒不同来源、部分更新、混批/缺来源、完整恢复、配置修改来源、重开/旧库兼容、API/WS/导出/助手一致性。单从站测试不能代替多从站全链路验收。

缺口是已存历史中的身份信息，无法从现有字段恢复。完整迁移和消费者改造未在本检查点实施；没有部署或重启服务。
