# 草稿确认焦点与键盘审查

基线f968f8a24acc44b4168c21edce70f8cce29d8fbd，开始时工作区干净。只做源码、模拟焦点/键盘、SSR及隔离构建；不启动主入口、不打开真实库或操作设备，不重试受限浏览器。

## 规范参考与发现

对照[W3C APG模态窗口模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)：窗口内Tab序列应保留在窗口，确认默认聚焦较安全操作；关闭后通常返回触发元素，触发元素消失时需有合理回退。此为设计参考，不是本项目已通过WCAG/辅助技术认证。

源码里DeviceModal已有部分Tab边界处理，PointSettingsEditor仅处理Escape；点位窗口最后控件上的Tab没有preventDefault，模拟断言false而期望true，失败。两个编辑器都仅按isConnected恢复继续编辑焦点，没有检查控件是否仍可用。

实际编辑器中从输入按Escape打开关闭确认，继续编辑按钮获得焦点；后台观察设备移除后输入所在fieldset禁用，继续编辑撤掉确认后，旧输入仍isConnected、其自身disabled=false，却属于:disabled。原focus调用无效，模拟焦点落在body而期望窗口关闭按钮，失败。[MDN disabled说明](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/disabled)支持fieldset会影响后代且禁用控件不可聚焦。这里使用受控模型，不把它说成实际浏览器复现。

## 修复范围

新增小型dialog-focus工具，仅支持当前两窗口的原生button/input/select/textarea及非负tabIndex；不是通用Shadow DOM/自定义控件焦点引擎。

- 两窗口共用Tab/Shift-Tab边界循环；中间控件仍走浏览器原顺序。已处理事件和Ctrl/Alt/Meta+Tab交回原所有者，不额外处理浏览器快捷键。
- 表单根节点新增ref及tabIndex=-1，平时不加入Tab序列。保存中全部控件禁用时聚焦根节点，Tab保持在窗口；请求完成后从根节点可进入首/尾可用控件。Escape保存中仍被原closeGuard阻止，不取消或重试请求。
- 继续编辑优先回原输入/按钮，但要求仍连接、属于本窗口且不匹配:disabled；否则回第一个可用控件，全部不可用则回根节点。不会把另一个窗口内的元素作为本窗口回焦目标。
- 保留确认初始聚焦“继续编辑”、字段禁用和原关闭状态机；Escape确认中返回编辑，输入法组合中的Escape不关闭。没有改变保存/导航/留存/删除协议。
- 双语正文精简，明确丢弃本地输入不发送保存/撤销，也不能证明之前保存结果；新增Esc继续编辑说明。原按钮名称、确认aria-label、外层dialog/aria-modal/title关联保留，未新增嵌套aria-modal窗口。

## 明确剩余问题

- 完整关闭编辑器后，父层多为清除显示状态，尚无统一的外部打开按钮回焦策略；本轮修复的是“继续编辑”回焦。触发按钮可能因设备移除/点位重排消失，本轮不猜测替代目标。
- 没有新增全页面modal栈、全局inert或跨窗口focusin管理。源码可表达多个窗口状态，模拟证明局部状态/事件独立，不等于真实叠层的topmost/背景虚拟光标已隔离；正常UI同时打开路径仍需实测。
- 设备异步移除但未打开关闭确认时的主动焦点修正没有单独统一处理；禁用控件的真实焦点修正、旧窗口与其他新弹层的所有权竞争仍需实测，不凭模拟加入全局抢焦点逻辑。
- 尚需受支持纯mock浏览器验收：真实Tab顺序、滚动/焦点可见性、键盘触发、原生select/输入法、焦点禁用修正、多个弹层和读屏中英文播报。没有绕过浏览器限制或把模拟结果称为真实验收。
- 原生beforeunload提示仍是尽力而为；保存结果未知、记录丢弃不等于请求取消或设备身份核实。无新持久化、自动恢复或硬件动作。
