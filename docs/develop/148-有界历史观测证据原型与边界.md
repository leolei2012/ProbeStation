# 有界历史观测证据：独立原型与生产边界

基线 ba4b9308142ce8f7a0ebb9e2b675b57c32ae4b72，工作区起始干净。本轮承接历史断段审计，只做合成数据原型，没有接入应用、路由、数据库迁移或用户界面。

## 原型是什么

显式运行 `npm run audit:history-evidence`，命令固定带 --synthetic。脚本不接受其他参数，没有数据库文件、地址或 URL 选项。仅使用公开 DuckDB API 建立 :memory: 数据库和同结构索引，不导入主程序、驱动、采集器、服务端监听、浏览器或模型。生产存储校验另用显式 :memory: DuckDBStore。

原型在 scripts 内复制现有分组 SQL 形状，并复用实际 decodeHistoricalSample 与 CurveSampler。在同一个原始解码流中同时生成曲线和证据，按 time/point ID 排序，单点同刻先间隔后样本状态；不是另查一次再拼接，也不是从降采样结果反推。固定小夹具的 samples/segments/sourceGapMs/summary/integrity 与实际 DuckDBStore.queryRegisterCurve 对照一致。复制实现将来可能漂移，不能作为长期生产契约或当前服务性能的证明。

证据只有三类：不可绘制观测、身份未核实观测、间隔超过当前查询估计阈值。保留可确定的解码原因、配置点位/从站、实际时刻、上一观测时刻和阈值；未知的前序边界保持 null，不补造查询首尾事件。不推算故障起止，不把长间隔、旧身份或缺行称为故障。一个观测可以产生两条不同证据，总数不是故障次数。

原型预算为 0–1024 条，测量使用 64 条；达到预算后只继续计数，不再保留事件对象。完整解码计数和曲线继续按现有语义处理。总数、保留数和 truncated 分开，不能用“已取完保留页”冒充原始证据完整。

## 分页、来源及隐私检查

分页只对一次成功扫描后冻结的有限数组切片，不使用数据库 OFFSET 或逐页重查。size 为 1–32，offset 必须是保留范围内的非负整数；末页、零预算、低于/等于/高于总数预算均检查。相同时间的不同点位/证据类型不会被分页去重或跳过。hasMoreRetained=false 且 truncated=true 时 sourceExhausted=false。

快照用进程内 WeakMap 绑定创建连接，并核对完整定义/查询范围上下文；复制对象、其他连接、关闭连接或变化的从站/定义不能续读。扫描后修改/删除原始表不改变旧快照，重查得到新的结果。此处只是实验中的连接所有权与不可变数组，不是可序列化 HTTP 游标、持久快照、鉴权令牌、跨进程或生产重开保护；旧快照仍是过去的观测，不代表当前状态。生产还需要明确保留期限、回收、上下文更新和并发关闭接线，不能照搬为服务契约。

覆盖同地址两个从站、缺字、坏质量、混批、旧 batchId、未知旧来源、重复字、非法字域，以及间隔与不可绘制同刻的情况；明确已知从站不继承另一个从站的异常。源质量与身份未核实分开，不把后者视为数值无效。首个缺字观测没有上一时刻，不虚构前序缺测。

对外页投影不含原始数值、原始质量文本、batchId、连接地址、串口路径、凭据或错误堆栈；用内部敏感哨兵验证没有泄漏。内部解码仍必须读取原始值和身份。点位/从站编号、时间、统计和原因本身仍是业务敏感元数据，不是匿名化；未来接入必须受与原始历史至少同等的权限与设备范围约束，不能以“只读证据”为由公开。原型没有 HTTP 入口，未验证代理、认证或真实客户端。

预取消和流处理中取消均不发布半份快照，移除取消监听；随后正常查询可恢复。实验回调触发取消不能证明真实 HTTP 断开时数据库能立即停止，也没有承诺后台 SQL 成本已消失。

## 查询成本与不能接入生产的依据

基准为 2 从站、相同地址的 uint32，分别每从站 1000/5000/20000 个时间戳，原始字 4000/20000/80000。每组预热后交替顺序执行三次“曲线”与“曲线+证据”，报告中位数。两模式是同一原型 SQL/解码/实际采样器中的开关，不是对真实服务做基准；曲线模式不分配证据对象，证据模式保留 64 条并持续计总数。初始化、写入不计入查询耗时。

5ms 采样的 RSS/heap 是同进程运行期观测，包含数据库分组/中位数、样本数组、输入夹具、分配器/GC 缓存，且会遗漏同步阶段峰值；不是严格峰值、事件增量内存、泄漏结论或生产容量保证。小规模热缓存耗时会受抖动影响，即使证据模式更快也不能宣称有加速。

反例：单个时刻 5000 个重复字，事件 cap=1，保留事件确实只有 1 条，但 SQL list 已物化 5000 字。窗口中位数/分组排序仍依赖整个查询范围，事件 cap 没有限制输入扫描、单时刻聚合、数据库原生内存或查询时间。大范围、热点重复字、大点表、高并发、冷库磁盘、取消延迟均未被本轮证明安全。

因此推荐保留实验，不接入生产。下一步先设计并验证原始输入/单组字数/查询并发/时间和内存的前置预算，明确拒绝而非静默丢字；再将证据生成与现有单次解码流整合，避免维护两套查询，并设计真实连接生命周期、分页回收及访问控制。旧数据身份不明继续未核实，不根据时间猜批次，不更改采集或清理策略。
