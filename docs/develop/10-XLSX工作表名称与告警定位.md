# XLSX工作表名称与告警定位

2026-11-06，基线20f0e7f。只操作合成内存工作簿和:memory:配置，不修改用户数据，不启动、重启或部署主服务，不连接设备。

## 已验证的问题与约束

当前安装的ExcelJS在worksheet.name中要求非空、最多31个UTF-16单元、无`\\/:*?[]`、首尾不能是单引号，History受保护，名称按小写比较不能重复。旧导出只替换非法字符并截断：同名、大小写差异、清洗后同名、前31位相同、保留名/前缀碰撞会抛错。

另一处实质风险在告警导入：原组名保留空格，告警查找却trim了组名。合成RO与“ RO ”同址不同从站，旧实现把后者的告警也挂到了RO，导入还返回成功。test-pointbook-names先在基线同时复现导出同名报错及此处错误归组。

## 页签只用于工作簿展示

sheet-names.ts分配器预留设备信息/告警规则/History，不区分大小写检查已用名。清洗非法字符、处理首尾引号、截断且不切断emoji代理对；冲突依次加_2、_3等后缀，始终不超31单元。普通唯一合法名称保持不变；相同有序分组集合的分配确定，不承诺用户增删/重排分组后页签仍相同。

原分组名完整保存在B1，分配器不改数据库名称。含普通首尾空格、引号、斜杠、超长或emoji的原名称仍在B1保留。空/纯空白、控制字符或无法保真表示的Unicode名称在导出前明确拒绝，不靠ExcelJS剥掉字符后生成另一名称；可用JSON配置备份保存完整配置。拒绝不产生部分文件或配置变更。

旧工作簿B1空的既有回退仍保留：采用当前页签名，但返回warnings提示缺分组名；纯空白名称报错，不在导入时任选一个现有分组。

## v2可选告警定位列

原告警页A–F六列保持原位，第G列新增可选表头“点位工作表”。新导出为每条规则填写实际分配后的页签名，分组列仍是原始组名。它是当前工作簿内的引用，不是数据库ID，也不从名称猜测从站。

| 输入 | 定位规则 |
|---|---|
| G有值且表头正确 | 页签（按ExcelJS大小写不敏感规则）+原始组名+FC+起址全部匹配，且只有一个点位 |
| 旧六列，或G留空 | 原始组名+FC+起址必须唯一；同名同址多组拒绝，不取第一个 |
| G有值但无表头/未知表头/只有空白 | 明确错误，不忽略选择器 |
| G过期、引用被删页或与原组名/FC/地址冲突 | 明确错误，不回退到其他匹配 |

组名使用字符精确匹配，保留空格与大小写；不再trim到另一个组。手工改页签名时需同步改G列；改B1原组名时需同步改告警A列。普通旧六列表仍可导入，但存在定位歧义时必须补G或改文件，不能把旧无身份告警猜成任一来源。旧版本应用不理解G扩展，不能承诺它能导入同名同址的多组文件；这类文件应使用本轮新代码。

同一页内同FC/地址仍可能有多个语义定义，G无法区分行。无告警时可保留这些定义；含告警时导出明确拒绝并建议JSON备份，导入也报歧义。没有引入未经定义的点位行号/永久ID字段，更不任选告警归属。

所有引用和格式校验都在配置事务前完成；错误返回0计数/errors，目标组、点位、告警和日志不变。原子替换、提交后warnings、从站/quantity/零倍率/完整范围规则保持09阶段行为。不是硬件来源认证或采样质量判定。
