# 条件数值写入端到端模型与决策

基于a52fd4e。只新增隔离审计脚本和严格类型覆盖，**没有接入生产接口、前端或驱动，也没有解决182号记录的真实写入来源风险**。现有警示继续保留。

## 有界端到端证明

`scripts/audit-guarded-write.ts --mock`建立内存ConfigStore、Fastify.inject候选确认/发送路由及唯一模拟发送sink。脚本拒绝其他参数，禁止listen、socket.connect和fetch；不接收地址、串口或文件数据库。没有启动主应用、采集循环或实际驱动。

确认阶段读取实际ConfigStore的完整组快照，冻结设备、从站、点位地址、类型、编码字及版本，返回只供模拟人工确认的一次性票据；确认不发送。发送阶段不接受另换value/source，依次核对接纳、队列后、连接后、驱动内部队列后的条件；连接按预期定义创建，不能刷新成新目标。模拟sink在最后一次检查与记录帧之间没有await或应用回调，这是本模型的线性化点，不是当前实际驱动已有的保证。

在受控单进程、变更均被观察、版本不复用、连接绑定可信、最终sink同步这五个假设下：TCP/RTU确认后、队列中、连接中和内部队列中改变从站、地址、类型、端点、ABA或运行时代次，均拒绝且零模拟帧。还覆盖票据过期、重复/并发重复提交、删除、库重开、能力不支持、驱动绑定不符、值零、确认后请求篡改；本地从站路径未建模，明确拒绝而非回退外部写。

## 明确反例与缺口

1. 保留接纳/连接后检查而故意去掉最终sink检查：内部队列期间改配置，旧版本仍发送。这证明仅前端、路由或采集器入口预检不能建立所需边界。
2. 故意抑制模型的版本观察，再把从站7改9改7：内容哈希和通知计数都不变，票据被接受。这个负对照证明方案依赖版本权威；不是声称现有公开ConfigStore更新必定漏通知。跨进程、私有SQL、静默恢复/替换及ABA必须有独立保证。
3. 实际采集器write等待后getDriver会重新取配置；当前ModbusDriver写方法不接收预期来源/版本或发送门。TCP在getClient连接await后才调用jsmodbus，RTU亦有共享通道和客户端生命周期；jsmodbus内部排队与底层socket/串口write尚未建立可验证的最终门。模拟sink并不能证明它们等价。
4. 当前getGroupSettings revision是内容哈希；recording范围/生命周期身份不是点位+分组+设备全部变更的跨进程单调版本。本模型新增的通知计数和runtime代次仅在脚本内，不是现有生产权威版本，也没有持久化或迁移数据。

因此推荐**不接入生产**。本轮仅交付可执行反例和有条件成立的候选证明，不再扩展未使用的运行时基础设施。

## 兼容及失败语义建议

| 边界 | 候选语义与仍需完成的事项 |
|---|---|
| 旧调用 | 原REST/MCP及旧写方法不改变。脚本以实际旧路由+spy核对仍返回原成功结构。旧调用仍不具备来源条件；保留兼容不等于具备安全保护。 |
| 新客户端遇旧后台 | 需要独立guarded能力识别/入口；缺能力或未知响应应停止条件写，不自动回退旧无条件接口。脚本只证明候选不支持时不调用旧路由，没有实现浏览器客户端。 |
| 确认票据 | 应绑定操作值、完整来源、授权主体、权威版本、运行时与期限，限制内存/并发并清理过期项；本脚本不是可上线的票据服务或鉴权实现。 |
| 发送前拒绝 | 模型能在唯一sink证明零帧时才回报not-sent；不能把普通503、超时或代理响应当成生产“未执行”证明。票据消费后不自动重放。 |
| 已发送且丢回执 | 模型返回unknown；重复票据不再次发送。真实硬件不能回滚，取消/断开不等于未执行。不得自动重试或把此设计称为旧接口幂等。 |
| 发送后配置改变 | 不追溯取消已发帧；若原回执成功，模型保留完成结果及原绑定。真实客户端还需要明确展示操作归属和未知结果。 |

最小后续工作应先证明真实驱动内部队列到最终发送的可控边界，并为受支持单进程/多写者范围定义权威版本与失效策略；未满足的传输/本地从站路径应拒绝新条件写。不要先添加生产路由，再以客户端预检弥补缺失的驱动或版本保证。
