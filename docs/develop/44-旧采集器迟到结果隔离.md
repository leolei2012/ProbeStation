# 旧采集器迟到结果隔离

2026-11-07，基线`817fda1`，初始工作区干净。仅本地开发、纯内存ConfigStore、mock驱动与注入的纯内存从站服务器；未启动主应用、MCP/HTTP监听、真实串口或设备，未读取真实配置/历史库，未安装依赖、部署、重启服务或推送。

## 复现

旧轮询开始读取A并停在mock响应Promise；把设备IP改成B后开始新录制，才返回A的99。对新录制样本数为0的断言在原代码失败：实际为1。43阶段只核对会话配置，新的会话已经绑定B，不能判断这次结果由A发起。原TCP缓存又只按设备ID，可能在未显式重连时沿用旧连接。

检查了PollingEngine的调度、RTU队列、getDriver/reconnectDevice/stopAll、一次性读取，以及DeviceSlaves的串行异步reconcile。已安装Cordis的emit实现逐个同步调用监听器；先前监听器可同步改配置/重开录制，因此只在emit前检查还不足以保护后调用的录制监听器。

## 实现

- 复用ConfigStore已有不透明来源条件及本连接修订身份。snapshot核对同时检查实时记录，不能用传入旧快照绕过当前来源检查；不新增持久列。普通名称、周期、超时及闲置传输字段保持兼容。
- 调度读取在进入RTU队列之前固定条件，排队后、连接完成、每批读取前后及发布前复核。失效请求不继续发送后续分批，不发布已攒字、不写store、不更新新通道故障/冷却/自动复位计数；未完成组不把部分字伪装成成功组。准备时无法核验则按当前调度周期延后，避免0延迟反复空转，不改读猜测的新目标。
- 引擎停止更换生命周期并清空到期队列；poller插件新增Cordis卸载清理回调，执行时调用stopAll，使卸载后的旧在途结果失效。每个设备的读取另有任务身份，只有当前任务能取消自己的在途标记。旧finalizer既不能写入新生命周期到期时间，也不能在同一生命周期内把新的在途读取误标成到期，避免重叠调度。已有I/O未被强制取消，返回后丢弃；不增加重试或放宽超时。
- 连接缓存另存实际TCP或RTU参数绑定；不匹配/已断开时释放旧驱动，再走已有惰性连接流程。待连接驱动拥有槽位，停止/重连或后来的连接占用后，旧connect即使成功也不能覆盖新驱动；失败同样不能变成新来源故障。
- pollOnce保留合并事件与断开/flush契约。已配置ID必须匹配该主站TCP目标，错误在创建驱动前拒绝；未配置临时ID可以沿用，但配置scope须相同且结束前不能出现同编号配置。失效明确抛出通用错误，不自动改读新设备。
- 从站reconcile在异步启停前后核对原条件，迟到启动结果不发布旧快照。从站内存及原先无batchId行为保持；注入服务器工厂仅为纯内存回归提供端口，不更改默认生产构造。
- 新增核心进程内AcquisitionOrigin：冻结ID、WeakMap私有条件，内部事件readOrigin引用它。录制在追加/触发前再核对，覆盖同一次emit中前面的监听器改配置、stop或reconnect后新建会话。复制或序列化不能伪造有效句柄；条件检查抛错按无效处理。句柄不保存到RecordingSample/分页/历史，API现有WS中继只发送objectId/points，不转发内部条件。

## 兼容边界

这不是物理设备认证，不识别相同参数下物理换机。跨进程/私有SQL绕过共享写入的A→B→A仍可能无法发现；持续变化可发现。本轮没有改变驱动内部报文匹配或校验，也不能保证第三方驱动把错响应标成正确当前请求时能识别。

正常同来源的在途读可以跨录制开始时刻返回，不把录制开始擅自改为“所有Modbus请求必须此刻后发出”；本轮隔离的是已失效来源/驱动/生命周期。点表语义和分组选择仍沿用开始时规则，未增加通用点表修订锁。

旧自定义/测试生产者没有readOrigin时保持已有事件兼容，不能声称这些外部事件也经过隔离。第三方同步监听器是否检查条件由其自行决定，emit不能撤回已执行的监听器；内置录制明确检查。无句柄数据不会被静默生成批次或写入新身份列。未新增自动PASS/FAIL规则。

每批增加配置核对，高频采样性能尚未实机测量。已有串口/网络超时、断开资源释放及从站状态显示仍需真实环境验收，本轮没有启动或更改运行实例。
