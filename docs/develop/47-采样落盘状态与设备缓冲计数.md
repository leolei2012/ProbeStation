# 采样落盘状态与设备缓冲计数

2026-11-07，基线`3c9196a`，初始工作区干净。本轮只读能力开发及计数修复，仅真实DuckDB内存库、Fastify.inject、纯客户端模型/SSR与静态mock预览；未运行主应用、未打开真实配置/历史库、未连接设备/串口/PLC、未调用模型、未部署/重启/推送、未安装依赖。

## 已验证的问题

Store已有失败后保留待写行、回滚不确定时阻止后续写入的机制，但错误只在内部状态/后端输出，数据管理只显示缓冲数，不能区分普通等待和已记录的写入失败。同时statsByObject的bufferPending使用整个服务buffer.length：设备1缓冲1行、设备2缓冲2行，查询设备1返回3；预期1的内存断言先失败。本轮使队列归属准确，并把已存在的写入状态作为只读提示提供给用户。

## 数据与服务边界

新getSamplePersistenceStatus(objectId?)同步读取本实例内存字段，不执行SQL、初始化/迁移、flush、cleanup、reopen或重试。旧getPersistenceStatus的pendingRows/error形状保持，供原内部诊断/测试使用；新公开状态只返回分类，不含异常对象、SQL、文件路径或错误原文。没有新增表/列、迁移、队列上限、重试策略或采样丢弃规则。

version=1，available表示是否提供能力；objectId=null为全服务，正整数仅筛选待写行。stateScope固定service：phase/failure/flushing/时间均为全服务，不能归因到所选设备。pendingRows按缓冲中数值objectId精确计数，globalPendingRows为总缓冲长度，计的是原始采样行，不是解码点、批次或丢失数。statsByObject.bufferPending采用同一筛选，全局stats保持原总数。

phase区分initializing、switching、ready、failed、blocked；failure为initialization-failed/flush-failed/write-uncertain或null。ready只表示已完成初始化且当前无记录的批量写入错误，可能仍有待提交行；不是“历史保存正常”的证明。flushing从非空批次实际开始到finally结束；lastCommitAt仅在COMMIT成功并移除对应缓冲后记录，空flush不假造提交/清除旧错误。失败保留缓冲及失败时间，实际成功提交后清除当前错误但保留最近失败时间；回滚不确定沿用既有阻止写入机制。成功换库会清空前库时间记录。

公开API为GET /api/storage/persistence-status，可选object_id，使用Cache-Control:no-store，完整校验字段和范围。不提供写方法、自动恢复或“立即落盘”按钮；没有能力时available=false，不能读取或响应异常时明确未核实。任意合法正整数ID均可过滤历史缓冲，不额外断言该设备当前存在/身份相同。

## 界面与读生命周期

数据管理页增加独立状态区，15秒只读刷新、10秒读取超时和显式重读。显示服务共享状态、所选/总待写行及UTC记录时间；初始化或未知不显示正常/保存成功，失败和读取异常有可见提示。即使选择无待写的设备，共享写入错误仍显示。状态不依赖可能较慢的历史总行数统计查询。

客户端按当前objectId实例校验响应，切换范围不显示旧范围结果；自动读取合并在途请求，显式新读可取消旧的只读等待，超时、取消、卸载和迟到回调不覆盖新结果。失败保留上次完整结果并明确标旧/未核实；异常响应整份拒绝，不拼凑健康状态。控件不显示服务错误原文。启动/订阅/SSR不执行读请求。

## 剩余限制

本状态只报告进程已记录的初始化与采样批量写入状态，不是数据库/磁盘完整健康探针，不覆盖保留清理、所有关闭/外部操作错误或历史完整性。COMMIT记录不是断电耐久保证，也不能证明某个点已落库；各统计请求不在一个事务快照中。初始化/结果不确定后拒写的后续样本不计入缓冲，不能据此推算丢失量。缓冲仍为内存且失败时可能增长，退出/崩溃可能丢未提交行；本轮不猜测限额或自动恢复策略。

没有新增助手/MCP自动判定或跨进程告警，没有修改保留清理行为、现有统计SQL或统计页原请求生命周期。下一项有依据的检查是设备级保留覆盖的显示：当前统计返回全局保留值，可能与设备覆盖配置不同；本轮不顺带更改删除/清理策略。
