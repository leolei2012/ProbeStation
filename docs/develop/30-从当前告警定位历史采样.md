# 从当前告警定位历史采样

2026-11-06，基线`ed33bb9`。只开发本地代码和离线验证，不部署、重启服务、接触实机或修改真实数据。

## 工作流与行为

顶部当前告警原来只有别名、原始值和比较条件，排查趋势需要手动记下点位、重新选择历史范围。历史页可能保留物理量模式，但告警使用未缩放的原始值，容易比较错量纲。本轮增加“查看采样前5分钟”。

- 当前有效命中的告警行显示配置来源、精确点位ID、UTC毫秒采样时间和批次ID是否存在，点击定位该点位的原始值历史曲线。
- 窗口固定为`[显示采样时刻−300000ms, 显示采样时刻]`，不是点击时刻、规则刷新时刻或第一次告警时间。已核实原存储查询端点包含`ts <= end`，因此不人为加1ms或查询未来。
- 来源选择与数值来自同一次源缓存取字/原有告警求值，通过不可变元数据投影绑定；不再次从另一个地址或从站缓存取时间。相同别名/地址的其他从站仍是其他点位ID。
- 点表或规则未核实/读取中不能定位。已暂停、通信故障、缺字、混批、质量异常或过期仍沿用原规则未知处理；时间超前、非整数毫秒、不同字不同时间、无法表示的日期不能精确定位。
- 多字定位额外要求明确相同非空批次ID和完全相同的各字时间。不取最小/平均时刻来猜一次采样。旧多字无批次仍保留原告警求值兼容，但禁用精确历史定位；单字无批次在来源和时间明确时可定位并标明“单字无批次ID”。没有回填旧批次或放宽任何联锁/校验。
- 点击再复核显示样本的时效，不因页面停止刷新而用过期值发起定位；失败显示禁用原因，新样本或条件变化后恢复。没有自动追踪跳转，采样/规则刷新不改变已打开的历史分析区间。
- 经现有历史意图入口切换到曲线、精确ID、原始值及表格第1页/新视窗。新的可选`valueMode`只在新意图应用一次；旧引用缺该字段时保留原模式，迟到点表或后台刷新不反复覆盖用户调整。重复显式点击仍产生新序号。

## 边界

这是只读定位，不是历史告警事件、首次触发时间、告警日志或测试结论。按当前点表解释历史原始值；设备/分组/类型在服务端并发变化时不提供配置版本锁或历史配置快照。来源/质量/批次标记继续由历史链路独立判断，不把当前样本的状态套给历史数据。

当前样本可能尚未flush到历史、已被保留策略清理或因其他原因无法查到，查询可为空。不会插入假历史、强制flush、启动采集或联系模型；仍使用原历史查询/取消/超时/重试/降采样逻辑。不保证所见数值一定出现在降采样图上。用户可核对UTC范围后调整或重查。

`readPointAlarmValue`现在委托同一求值后的元数据投影再返回原值，数值/来源/质量/同批/时间容差规则保持不变；新增定位有更严格的时间/批次要求，不改变后台告警。显式定位会沿用现有数值模式偏好保存机制切到原始值，其他浏览器偏好未增加。客户端缓存校验不是后端原子事务。
