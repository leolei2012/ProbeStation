# 手动观察清单与页面范围隔离

基于 f5dcc0bb666a3aea21d773a3a5a8c35bf17969d7，初始工作区干净。AGENTS.md 与 .agents 均不存在。本轮只改页面显示，不增加服务、依赖、协议、数据库或设备操作。

## 为什么需要

原实时表支持搜索、从站和 all/attention/alarm/data/unknown 状态筛选；搜索多个词为交集，不能直接固定分散在多组/多从站的几个任意点。实时曲线的选点最多 8 条且偏重数值绘图，冻结是静态观测。新清单用于持续查看任意少量实时行，复用现有 RegisterSelectModal 的搜索、来源标签、编号、地址和限额，不复制选点界面或增加另一套采样。

## 使用

在实时页“手动观察清单”选择点位并应用，自动开启“仅看观察清单”。最多 32 点是页面易读性限制，不是协议、采集或整张点表上限；可从 10000 点合成点表选择，既有曲线限额不变。

仅看清单与原搜索/从站/状态筛选取交集；原筛选计数及分组摘要仍按原有完整范围计算，清单单独报告已选数/匹配数。无匹配、清单失效或来源未核实时不回退成全部点，更不据此称设备正常/无告警。可以关闭仅看模式查看完整范围；“清除全部筛选”也退出仅看模式并恢复原折叠，仍保留手动选择供再次开启。“清空观察清单”同时清空并退出；应用空选择同样清空。

冻结只含当前真正匹配的行，包括未渲染/折叠行，依旧使用原 v1 JSON（包含实际点位和来源，不保存可恢复清单）。前后对照沿用原同范围/定义/批次规则，不把不同清单范围当成可比较的前后值。没有更改 captureLiveSnapshot 或比较器。

## 生命周期和失效

清单仅在当前 LiveTable 的 React 内存中；离开实时页、切换设备或刷新/关页会丢失，不写 localStorage、浏览器数据库或服务端。关闭仅看模式不清空选择。

复用实时快照的已加载配置上下文及每次变化生成的新 Symbol：连接、模式/来源、点表/数值含义等上下文变化后原清单明确失效，不因 ID 相同或 A→B→A 自动恢复。即使只改元数据也可能保守失效，需要重新选择；读数更新不会导致失效。失效清单不能继续显示旧行，新选点器不预选旧编号。打开选点器时配置变化会立即隐藏旧弹窗，迟到应用回调核对当前作用域后拒绝，不影响新选择。

上下文只是页面最后载入的配置，不能认证物理设备、后台未同步变更、跨库同 ID 复用或请求来源。既有配置读取失败/旧快照提示与设备连接状态仍独立显示；清单不证明在线、新鲜、健康或来源可信。断线、缺值、混批及告警仍由原行状态显示，不增加自动 PASS/FAIL。
