# 设备提醒与页面导航一致性回归

## 本轮审查

基于干净的 `d2f4326de86985eaf5d01c6867bc922bc77122e3`，保留此前全部本地提交。本轮先审视近期的提醒读取、设置按需加载、保留策略、诊断与日志清空及快照调用关系；没有启动主程序、在用服务或真实数据库。未发现需为这些流程新增功能的依据，选择修复一个已离线证明的跨功能导航问题，并补组合验证。

`GET /api/ai/issues` 对未运行从站会输出 `view: diagnostics`。App导航原样接收目标并递增token；DeviceView将所有diagnostics映射为标签3。可是从站的可用标签为0实时、1实时曲线、2历史和5点表检查，原始报文3及固件4被隐藏。已有角色变化effect只在device.mode变化时修正3/4，因此首次选择设备可能被它掩盖；对已选中从站重复点击同一提醒时，只有token变化，标签变成3而无对应内容。

修改前，从实际App源码提取导航effect和TabBar声明、用合成从站目标执行：选中3，可用[0,1,2,5]，断言失败。新增组合测试亦在未改生产代码时因“导航必须选择可用标签”失败。这不是从截图推测或真实设备试验。

## 最小修复

只在现有导航表达式增加从站角色判断：diagnostics对主站仍进入3，对从站进入0；history仍进入2，live仍进入0。从站概览已有自身状态入口，不新增不存在的诊断页。没有修改后台提醒规则、设备连接/采样、告警阈值或从站服务。

保留只依赖target.token的一次性导航；不把device.mode加入依赖而在后续配置刷新时重放旧目标。原角色变化effect继续防止切为从站后留在3/4。没有增加生产抽象、依赖、状态或新接口。

## 组合回归与验证

扩展现有安全白名单内的 `scripts/test-device-issues-read.ts`，使用已有TypeScript编译器解析真实App源码，仅执行经过审查的navigateData、两个导航effect及TabBar/target属性表达式，注入内存setter模拟相关依赖变化。不会导入整个App或挂载其组件，避免触发从站状态同步、设备请求或任何业务副作用。函数/属性边界变化时测试应明确失败并人工审查，不靠复制另一份映射当生产实现。

覆盖实际Fastify注入汇总返回的每条目标（含主/从站和同设备多提醒），穿过生产navigateData、设备ID作用域及实际可用标签：重复点击已选中从站、主站诊断、live、history；递增并覆盖外来token、不修改只读原目标；手动切页后普通重渲染不重放；主从角色变化清理非法标签且不重放旧目标；另一设备不接收该目标；历史点位ID、原始值模式和UTC毫秒区间不变。此前读取超时、取消、旧响应隔离、严格解析及双语SSR仍运行。

本轮针对性组合测试先在旧逻辑下失败，最小修复后通过；原实际源码复现脚本也从选中3改为选中0并退出0。随后完整 `npm run check` 退出0：web/services类型检查、正式Vite构建、源码/manifest/HTML按需边界与聚合首屏预算、90组安全测试全部通过。TEMP/TMP指向项目忽略的专用测试目录；包含此前历史/导出、来源与批次、告警、点表、录制、串口mock及编辑并发回归，本轮没有另增测试发现机制或依赖。

最终首屏JS为486580字节（gzip161262），相对此前486562（gzip161258）增加18/4字节，仍低于既有500000字节预算，未调整阈值；CSS产物hash未变。审查范围是近期调用与本次组合路径，并非逐条审计全部历史本地提交。测试只验证相关回调及依赖契约，不模拟完整React调度、浏览器事件顺序、焦点、DOM布局或辅助技术行为。实际浏览器验收受既有限制，未重试或绕过。

## 手测与尚存边界

后续在获准的隔离界面中，可配置暂停/未运行的模拟从站：先选中它，再重复点击顶部提醒，应停留在有效的实时概览；主站诊断仍进入原始报文，历史目标仍进入带原参数的历史页。用户手动切到曲线后，仅普通刷新不应自动跳回旧目标；明确再次点击才导航。不要为本测试启用真实从站监听或连接设备。

既有 `preview:device-issues` 的点击只显示本地导航参数，不包含完整DeviceView，不能据此声称已验收本次修复。完整页面挂载可能触发既有状态读取；本轮没有启动它，也没有改动那些后台行为。快照与代理切换配置库的生命周期绑定、旧无条件接口等已知边界未在本轮扩大处理。

未推送、部署、重启、操作实机、调用模型或修改真实数据。构建会更新本地dist，运行实例版本未核实。
