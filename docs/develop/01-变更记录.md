## 二、数据模型变更（重要，测试需关注）

### 1. 时序存储按「地址」键控（原 register_id）

- 冷层 DuckDB 表：poll_data(object_id, address, ts TIMESTAMP, raw_value DOUBLE, quality VARCHAR)。
- 热层用 objectId:address 复合键（地址是每设备独立的，不能只按地址键控，否则多设备同地址互相覆盖、实时值会「闪」）。
- 单设备快照用 store.getLatestByObject(objectId)。
- 旧 poll.duckdb 会自动迁移（register_id 列改名 address），无需删数据。

### 2. 类型 = 显示方式（存原始字、展示时解码）

- 存储/轮询都按原始 16 位字；寄存器类型（int16/int32/float32/hex32…）只是显示/解释方式，改类型不会改历史数据。
- 解码器在 packages/core/src/codec.ts：
  - decodeRawByAddr() 数值（曲线/告警/MCP）
  - formatRawByAddr() + formatRegisterValue() 显示字符串（实时表/历史/导出，hex/bin 逐字）
- 效果：32/64 位寄存器在实时/历史/曲线/导出四处一致（例如 int32 地址 0+1 显示 305419896，而不是两个 16 位字）。

## 八、OTA 固件升级（对照 docs/product/07 PRD）

### 上传方式决策

- **阈值 1MB 双通道**：<1MB 走 MCP `upload_firmware(content_base64)`；≥1MB 走 HTTP `POST /api/firmware/upload`（raw 二进制体，无 base64 膨胀）。统一返回 `{ firmware_id, size, crc32 }`。

### CRC32 对拍结论

- MB-RTU 参考工程（`.ref-MB-RTU/`）**不算 CRC32**，只透传（START 把 `fw_crc32` 大端放 req[7..10]，设备侧 `on_end` 自行比对）；`iap_demo.c` 里的 `0x12345678` 是硬编码假值。
- 对拍对象 = 标准 CRC-32/ISO-HDLC 已知向量，用 `crc.crc32() >>> 0` 验证：`"123456789"`→`0xCBF43926`、`"The quick brown fox..."`→`0x414FA339`、空→`0`、`iap_demo.c` 的 `fw[300]=i*7+3`→`0xDE0E57CE`。

### 实现

| 层 | 改动 |
|---|---|
| `packages/ota`（新） | `frame.ts`（CRC32/CRC16 + 0x41 PDU 编解码 + RTU/TCP 帧封装，均大端）；`engine.ts`（OtaEngine：固件上传/落盘 + START→DATA→END 状态机 + STATUS 断点续传 + 暂停/恢复轮询）；`index.ts`（插件，`ctx.ota`） |
| config | `monitor_objects` 加 `slave_id`（设备从站地址，OTA 寻址用）；新增 `firmwares` 表 + 固件 CRUD |
| modbus | `ModbusDriver` 加 `getRawSocket(slaveId)`（TCP 返回 net.Socket / RTU 返回 SerialPort），供 OTA 拼原始帧直连（绕过 jsmodbus 功能码封装） |
| poller | 加 `pauseObject/resumeObject/isPaused`（升级期间暂停该设备轮询）+ `getRawSocket` |
| mcp | 新增 5 工具：`upload_firmware`/`list_firmwares`/`ota_upgrade`/`ota_status`/`ota_abort` |
| api | 加 `POST /api/firmware/upload`（application/octet-stream raw 二进制）+ `GET /api/firmwares` + `GET /api/ota/status` + `POST /api/ota/upgrade` + `POST /api/ota/abort` |
| web | 设备表单加「从站地址」（slaveId）字段；「固件」Tab 从占位改为可用：上传固件（文件选择→raw 上传）+ 固件列表 + 一键升级 + 实时进度/中止 |

- 验证：`npx tsx scripts/test-ota-frame.ts`（CRC32 标准向量 + 帧编解码字节级对拍）、`npx tsx scripts/test-ota.ts`（RTU/TCP 完整升级 + 断点续传，用 fake socket 模拟 0x41 从站，crc32=0xde0e57ce 与参考工程一致）。
- 已知限制：真机验收需设备侧有 0x41 IAP 从站固件（MB-RTU 库提供）；`abort` 在当前块结束后才生效（非即时）；升级结束 `reconnectDevice` 清 jsmodbus 残留 0x41 响应缓冲。

## 九、RTU 串口轮询静默卡死修复（对照 MC_BASE 反馈 ProbeStation_feedback.md）

### 症状（反馈）

- RTU 设备（STM32G474 bootloader，9600 8N1，COM3）读不到数据，且**无数据、无错误、通信灯不闪**三合一静默卡死；
  但 .NET 直连 COM3 报 Access denied，说明 ProbeStation 底层已占用串口。

### 根因

- `SerialDriver.connect()` 里 `await new Promise(...)` 只靠 serialport 构造函数的 open 回调来 settle；
  当「原生已开、binding.open 的 Promise 不 settle」时 open 回调不来 → `connect()` 永久 pending →
  `getDriver()`/轮询全挂，且 `sp.on('error', () => {})` 把最后的兜底信号也吞掉。RTU 又按串口串行排队，卡死会冻结整条串口队列。

### 修复

| 层 | 改动 |
|---|---|
| modbus | `SerialDriver.connect()` 加 `connectTimeoutMs`（默认 3000）超时兜底：超时即 reject 并尽力 `close()` 半开句柄；不吞 error（open 阶段 reject、运行期告警）；`Config` 新增 `connectTimeoutMs` |
| poller | 连接失败冷却 `connectRetryMs`（默认 5000）：坏串口/坏地址不每轮重建连接，避免 RTU 队列堆积；看门狗 `watchdogTimeoutMs`（默认 30000）：启用且有分组但长时间无结果无错误时主动发 `poller/group-error`（`No response (watchdog)`）；`Config` 新增两项 |

- 验证：`npx tsx scripts/test-rtu-timeout.ts`（open 永不 settle → 超时 reject + 半开句柄 close；open 失败 → 错误冒出来；正常打开 → 不回归）、`npx tsx scripts/test-poller-watchdog.ts`（读卡死 → 看门狗标故障；连接失败 → 冷却期内只重连约 3 次而非 14 次）。
- 既有回归：`test-rtu` / `test-loop` / `test-group-fault` / `test-device-toggle` / `test-disconnect` 全通过。

## 十一、RTU 串口释放（对照 feedback 第 9、10 节）

### 需求

- RTU 设备停用/删除后不释放串口，COM 一直被占用；编辑设备触发 reconnect 时 `disconnect()` 未真正关串口。

### 修复

| 层 | 改动 |
|---|---|
| modbus | `disconnect()` 改为 `async` 并真正等待 `close()` 完成（serialport 的 `close()` 本身不返回 Promise，用回调包一层 + 2s 超时兜底）；`connect()` 开头改为 `await this.disconnect()` 避免旧串口未关就开新口 |
| poller | RTU 串口引用计数：`releaseUnusedRtuDrivers()` 每轮检查，当「最后一台启用、非 slave 的 RTU 设备」被停用或删除时，`disconnect()` 释放共享串口（覆盖停用 + 删除两种场景）；`stopAll`/`reconnectDevice` 改为 async 并 await 断开 |
| workspace/api/ota | 调用点改为 `await poller.stopAll()` / `await poller.reconnectDevice(id)` |

- 验证：`npx tsx scripts/test-rtu-release.ts`（disconnect 真正 await close；两台共享串口——停 A 不释放、停 B（最后一台）才释放）、既有 `test-rtu`/`test-loop`/`test-group-fault`/`test-device-toggle`/`test-disconnect`/`test-poller-watchdog`/`test-config-sync` 全通过。

### 诚实标注（PRD §3.5）

- 1ms 只是允许设置的下限，实际采样率 = `max(1ms, Modbus 通信往返时间)`（TCP 局域网 1~5ms、RTU 9600 约 40~50ms）。
