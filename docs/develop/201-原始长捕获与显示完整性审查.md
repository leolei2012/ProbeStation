# 原始长捕获与显示完整性审查

## 结论

未复现当前内置捕获链路静默省略单条 HEX 字节的问题，不修改生产代码。`ModbusDiagnostics.recordFrame` 拷贝收到的字节并记录实际 `byteLength`、完整 HEX；poller 只限制条数并过滤 RTU 从站字节，不裁单条内容；页面要求 HEX 长度与字节数一致，行文本仅添加空格。没有单条省略、折叠详情或专门的复制按钮。

现有提示已经区分后台有限缓冲与完整通信历史，达到条数上限提示可能有更早记录。字节块可能只有部分协议内容，甚至混合多帧；显示所有收到的字节不证明完整协议帧、设备来源或实际通信历史完整。短捕获已有 `FC?` / `err ?` 等未知显示与“不证明完整帧”说明，不把缺字节推断成网络截断、某个异常根因或零值。

## 尚未验证与后续边界

本轮专项验证的是组件可用文本，不是浏览器可见区域、手工选择复制、剪贴板、读屏或窄屏视觉验收；没有声称提供复制或展开详情功能，也不向剪贴板写入内容。没有新增下载、外部通信或自动操作。

256 KiB 单条通过不意味着2000条长捕获可安全同时渲染。现有缓冲只按条数有界，尚无总字节内存预算，本轮没有分配成百上千条长报文或做浏览器性能结论。若需要减少渲染，必须设计明确的已显示/未显示字节数和本页查看方式，不能用无标记的 slice/省略号替代完整数据；本轮不增加这类功能或协议字段。

后端若把内容及 byteLength 同时改成较短且一致的值，当前契约无法证明之前是否还有字节。不能靠页面预检证明设备或网络侧未丢字节；本轮也不增加推测性截断判定。

没有读取真实捕获或数据库、启动采集服务、连接设备、复制用户内容、覆盖在用构建、安装依赖、推送或部署。
