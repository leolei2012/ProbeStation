# 历史结果与点表上下文绑定

2026-11-06，基线`0512934`。仅本地代码、合成配置及mock/临时库验证，不部署、启动/重启服务、接触实机或修改真实数据。

## 已复现的风险

`HistoryView`原请求身份只有URL；设备ID、点位ID、区间、模式和页码相同时，改从站/数据类型不会改变URL，也不触发新的读取。后端曲线已经按请求时的点表解码，前端却用当前点表生成标签、倍率、单位与统计，可能把旧来源的值展示为新来源。

用真实`registerCurve`路由和内存Fastify注入（无监听端口），配置及存储接口全为mock：点位#101保持不变，同一URL从站1返回10，改为从站2返回200。基线不能区分结果身份，新增回归先失败（两个计划key均不存在），修复后通过。还复现未选点从16位改为32位覆盖所选点，API结果由有该点变为空，说明不能只看已选点的定义。

## 改动

- 客户端上下文投影设备ID/模式/从站、全部分组的ID/名称/来源/功能码/范围、全部点位的ID/归属/名称/类型/地址/来源歧义及比例/偏移/单位/枚举/精度。包含未选点，因为它们影响后端覆盖判断；分组边界也影响点位资格。
- 只投影已知标量，不带入任意扩展字段或采样。按ID排序、既有缺省值规范化，等价新数组/顺序变化得到相同key，不因普通配置读回反复取消/重查。启停、采样频率等不影响历史解码的状态不进入key。名称等展示字段变化也保守重读。
- 设备ID及点位所属设备、重复ID、非有限数和不支持的字段形状异常时不能建立上下文，页面提示重新读取/检查点表并停止该次查询。这里不新增协议范围限制、不修正配置；分组引用、点宽/重叠等完整语义仍按原诊断和历史规则处理。
- 每个计划的结果身份为URL、上下文和显式重查序号，只有URL发送给服务器。旧调用缺少新字段时保持原HTTP参数和缺省身份，未新增API、数据库列、后台轮询或依赖。
- 读取状态收敛到同一个所有者：loading取得计划，成功/失败/取消只能更新该计划。视图渲染立即核对当前计划，尚未运行effect清理时也不展示旧样本、质量计数或旧错误。开始新读即释放旧样本，只保留最后完成的上下文字符串作提示；取消/失败不回退旧值，空结果也是本次合法结果。
- 定义变化沿用原客户端取消、防抖与30秒读取期限并重查。显式同URL重查也先显示新读取状态，不把上次成功误作本次完成。实际取消不保证停止服务端SQL。
- 有效定义变化保留用户的完整时间及X缩放窗口，表格回第1页、Y范围自适应、悬停/拖动清理，A/B按上下文失效；普通同配置查询/缩放仍保留原A/B快照行为。未就绪/无效上下文时挂起并清理已卸载曲线的视窗，恢复后重新读取。
- 增加等待、上下文格式异常和“定义变化，旧结果隐藏”的说明；查询失败/取消时不会把“变化”提示误写为已重新查询成功。未就绪不冒充正在查询。

## 明确边界

这是客户端已知点表变化的结果归属保护，不是服务端版本锁、事务快照、身份签名或历史配置存档。服务器可能在客户端读点表之后自行变化，响应没有定义版本回显；此类未观察到的并发变化仍需核对，本轮不声称已解决。相同ID/相同定义但换了后端实例或工作空间也不能仅靠这些元数据辨认。

历史仍按当前点表解释，批次/来源/质量校验与自动判断规则不变。未修改采集、告警、录制、历史存储/迁移、导出、助手或配置写入。导出是独立读取，已有捕获条件及服务端当前定义语义不变，没有借本轮宣称导出具备配置版本锁。
