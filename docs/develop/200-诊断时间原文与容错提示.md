# 诊断时间原文与容错提示

## 证据与改动

通信统计的 `lastSuccessTime` / `lastErrorTime` 既有格式是可被 `Date.parse` 解析的字符串，并非严格 ISO 或日历校验。内置 `ModbusDiagnostics` 使用 `Date.toISOString()` 产生 UTC 标记；接口投影没有限制旧后台只能返回这种格式。

Node 24.18 的合成响应可接受 `2026-02-30T12:00:00.123Z`、`2026-01-01T24:00:00Z` 及无时区旧格式。界面本来保留原文，没有改显示成规范化日期，但只标为“末次成功时间”，缺少格式容错与时区核验说明。专项先复现提示缺失而失败，随后通过。

本轮只在通信统计的成功/错误时间旁增加中英文提示：这些是后台时间原文，仅检查可解析性，日历、时区和时钟准确性未核实，缺少时区不推断，不补精度。只要至少有一个原时间就显示；两个都缺失时仍为破折号，不生成时间。当前或保留的旧结果均保留提示。

不收紧解析契约，不转换、纠正、排序或改写时间，不增加报告字段、不改计数和连接判断；点表诊断的页面接收时间由本页生成，问题汇总的数值时间戳已有有限且可表示检查，不涉及字符串日历规范化。

## 隔离验证

- 4个测试进程本地时区（UTC、纽约、柏林、上海）乘8个字符串，共32种来源时间。覆盖畸形日历、24点、斜线旧格式、未标时区春季跳时、纽约与柏林秋季重复时刻、1位与9位小数。两种语言及本次/保留结果共128次实际组件静态渲染，验证原文、精度和不确定提示同在。
- 每个时区另用真实读取状态机模拟不可解析的响应：整份新响应拒绝、保留旧快照、私有错误文本不展示；后续有效读取恢复。测试结束恢复原 TZ，驱动/硬件副作用计数保持0。
- 两个时间均缺失的已有空计数路径没有新增时间提示，不将缺失时间补成零或当前时间。
- 失败与通过日志、完整检查结果仅保存在忽略的隔离证据目录，不包含用户数据库或捕获内容。
