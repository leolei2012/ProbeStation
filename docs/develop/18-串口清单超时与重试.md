# 串口清单超时与重试

状态：已实现，完整离线检查通过；浏览器和实际串口枚举未验收。日期：2026-11-06。

## 依据与改动

设备新增/编辑的串口控件在loading时禁用刷新。原 `SerialPortLoader` 直接等待fetch，若后端/网络/清单提供者一直不结束，就永久保留loading。使用故意忽略AbortSignal且永不返回的纯模拟提供者，注入5ms测试期限后，原实现仍无法结束，失败回归确认问题。

串口清单请求现在默认等待最多10秒。超时转为error、发送取消信号，中英文提示可刷新或手工输入；保留已填路径和旧清单，继续标明旧结果可能过时及原system/mock来源。不会自动选端口、连接或重试，也不改变路径校验及设备配置保存。

抽出已有历史请求的通用超时/取消生命周期，串口与历史共用。即使提供者忽略abort，调用仍能结束；卸载/更新请求保留顺序校验，迟到响应不回填。历史查询和导出继续使用30秒期限及原 `HistoryQueryTimeoutError` 类型/消息，不改变接口和业务语义。

本轮只限制浏览器等待；取消HTTP不保证终止后台已开始的系统枚举。未改后端串口接口、OS驱动、实际设备或采集服务。
