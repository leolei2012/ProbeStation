# 录制与触发录制的从站隔离

2026-11-06，本地 mock 验收；未启动设备、MCP/HTTP 服务或真实采集。基线 20e6a14，沿用前轮请求目标来源语义，不额外认证物理设备身份。

## 已核实问题

Recorder 订阅 poller/result，连续录制把原始事件保存在内存，触发录制增加前后窗口。原实现丢弃 slaveId/batchId；地址筛选及触发条件只匹配 area/address。两个从站相同地址会混录；触发使用 find 的第一个匹配值，可能被错误来源触发或影响 changed 基线。指定来源 1 的失败回归原先得到来源 2、1、NULL 三条且身份全部 undefined。

MCP 是唯一生产调用入口，没有 REST 录制入口或录制落盘/导入/恢复契约。录制会修改设备采样周期，属于有副作用的操作。本轮仅测试替身，没有调用任何运行中实例。

## 参数与兼容行为

| 输入 | 行为 |
|---|---|
| 无 addresses/slave_id，或旧空 addresses | 录全部来源；各样本保留身份；来源缺失保持 NULL |
| 顶层 slave_id，无地址筛选 | 只录该来源，未知来源不补齐 |
| addresses 中指定 slave_id | 按设备+来源+area+address 精确筛选，可在一次录制中选同址多个从站 |
| 地址省略 slave_id，顶层有默认 | 继承默认；每项显式来源可覆盖 |
| 地址和顶层都省略来源 | 当前配置唯一来源才解析；同来源重叠组可接受，无来源/多来源歧义拒绝 |
| trigger_slave_id | 独立触发来源，优先于顶层 slave_id；两者都省略时必须能唯一解析 |

解析配置只确定**期望选择器**，不赋值给实际样本。来源在会话创建时固定，分组之后更改从站不会令录制跟随新来源。本地 slave 模式用设备自身编号；主站用覆盖该地址、相同数据区的组编号。显式编号沿用核心元数据字节范围 0–255，不改变已有实际读请求的协议校验或广播限制。

输入使用 snake_case，get_recording/list_recordings 返回的内部会话/样本和解析后地址、触发描述为 camelCase。start 返回 recording_id 及解析后范围，方便核对。以下仅为参数示例，设备 ID 须先发现，不能照抄执行真实操作：

```json
{"device_id":1,"interval_ms":100,"duration_ms":10000,"addresses":[{"area":"holding-register","address":0,"slave_id":1},{"area":"holding-register","address":0,"slave_id":2}]}
```

从站 2 触发，仅录从站 1：

```json
{"device_id":1,"interval_ms":100,"slave_id":1,"trigger_slave_id":2,"trigger_area":"holding-register","trigger_address":0,"operator":">","threshold":100,"before_ms":1000,"after_ms":3000}
```

## 回放与触发边界

样本新增 slaveId（缺失为 NULL）、batchId（缺失为 NULL）、sourceVerified（仅说明合法来源元数据存在）。保留原始 ts/area/address/rawValue/quality，不重算已有身份。未知来源只在“录全部来源”模式保留供人工观察；非法非空源编号不录入。外部保存的旧录制没有身份时必须按未知处理，不从当前配置补为从站 1。内存录制不会在重启后恢复。

触发仍比较当前事件的**原始 16 位单字**；不按点位 dtype 合并，也不做倍率/偏移换算。要求目标从站唯一候选、good 质量、0–65535 整数字和有效时间，采样时间不得早于布防或目标前次采样。其他/未知来源既不触发，也不更新 changed 基线。目标重复候选或坏值清空 changed 基线，下一有效值重新建立；不猜哪一批先后。成功触发附 triggeredBy 样本作为来源/时间/值证据。

本地 slave 发布的已知来源单字可能没有 batchId，可用于原始单字触发，不制造批次。这不授予历史多字自动资格：回放按类型合并时，消费者仍需自行检查同设备/来源/area/精确采样时间、完整同批与质量。sourceVerified 不代表完整多字、质量、物理认证或 PASS/FAIL。

## 采样周期与验证

同设备同间隔可并行录制，最后一段停止才恢复最初周期；不同间隔或当前周期已被另改时拒绝追加。结束时若当前周期已改为别的值则保留该值。最近 50 段只淘汰已结束记录，全部活动时拒绝新会话，避免丢失定时器/周期所有者。停止、删除、超时沿用同一结束逻辑。

interval_ms/duration_ms 为正整数；before_ms/after_ms 为非负整数，均不超过 Node 定时器上限 2147483647。操作符仅支持原有 >、<、>=、<=、==、!=、changed，阈值须有限数。触发等待仍沿用原有 10 分钟上限。所有输入/来源校验在创建会话和改周期前完成。

- test-recorder：原连续/触发/前后窗口与定时结束回归，增加明确来源夹具。
