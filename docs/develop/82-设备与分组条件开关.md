# 设备与分组条件开关

## 复现与方案选择

干净基线`cff582f8aa8eaee78c7eae108910596e9ab6fb79`。81号审计已复现旧接口在响应丢失后人工再次点击导致1→0→1。本轮新增回归执行生产App的toggleDevice/toggleGroupPause及useOperation，实际POST/PUT路由、真实内存SQLite，故意不刷新画面：旧代码第二次后实际值1，预期保持0，断言失败。

单靠文案或GET预检不足以避免后台竞态；永久锁住前端也不能保护其他调用方。因此保留旧接口，新增小范围的条件显式SET并接入现有按钮，不做全局修订迁移、请求日志或新的硬件策略。

## 新增契约

- `PUT /api/monitor_objects/:id/activation`、`PUT /api/groups/:id/activation`，body仅`{expected,isActive}`，目标为数字0/1且与expected相反，非法值、额外字段、ID不匹配400；已不存在404，条件变化409。
- `expected: ActivationSnapshot`为`{device:DeviceEditBaseline,group:GroupEditGroup|null,isActive:0|1}`。device沿用既有编辑基线的ID、名称、角色、TCP/RTU连接和采样参数；设备操作group=null。分组操作含该组ID/objectId/名称/Slave ID/FC/范围/模式/当前开关，并绑定设备基线。分组父设备的启用状态、保留策略、运行健康和点位/告警不作为分组开关的前置条件，互不推断。
- ConfigStore.setActivation在BEGIN IMMEDIATE内读取、全字段比较、参数化SET和写回比较，然后COMMIT；不是先查再无条件写。写回若被触发器改动来源也回滚。BEGIN失败不会回滚外部已有事务，恢复批量状态中拒绝嵌套。
- 成功`{snapshot,warnings}`仅确认配置提交。原object/group通知在提交后尝试一次；设备沿用旧开关的从站同步钩子，组不增加新钩子。同步通知/从站同步异常返回已保存警告，不把已提交状态冒充未执行。异步消费者、连接或采集成功不由这个响应保证。
- 更新/写回/提交故障尝试ROLLBACK；未知500明确核对，回滚自身失败抛AggregateError。没有为全部配置接口增加全局故障封锁；未知事务不声称已恢复，测试仅清理其拥有的临时事务。

旧POST`/api/monitor_objects/:id/toggle`和`/api/groups/:id/toggle-pause`、ConfigStore.toggleObject/toggleGroup及旧返回形状逐字保留；旧客户端继续使用且仍具有原反转风险。没有数据库结构变更或真实库迁移。

## 页面接入

生产按钮从点击时实际显示的数据构造冻结条件及明确目标，发一次PUT。useOperation原同步锁仍阻止忙时双击。新增可选成功文本格式化仅供这两条调用显示warnings，原调用默认成功/失败流程不变；ActivationUncertainError单独显示结果待核实，不加“操作失败”前缀。

保存helper校验响应快照必须等于原条件加目标，warnings必须为字符串数组；未知传输/解析/5xx或畸形响应不刷新、不宣称成功、不自动重试。新端点404等明确拒绝保留原因，绝不回退旧反转POST。新界面需要匹配的新后端；未更新的后台会拒绝，不能假称兼容支持新行为。

刷新只是提交后的显示请求，不能证明运行成功；同步刷新回调异常显示已保存但需核对。后续异步读取仍由原加载状态处理。分组采用真实readDeviceGroups投影，显式绑定当前device.id，缺组时零请求，不会把undefined误作父设备开关。未改按钮布局、状态徽章或硬件读写协议。

## 实际回归

新增安全白名单test-activation-settings，前后端类型检查接入新模块。全程无API bootstrap、网络监听、串口、poller或真实服务：

- 同条件并发请求一条200一条409，仅一次通知及设备同步；来源/从站变化409；独立点位单位编辑不冲突；子点位/告警不改。
- 0/1边界及非法类型、本地/路径ID、缺失对象；畸形成功/未知错误不重试，旧后端404无降级；旧POST仍返回原Record并反转。
- SQLite更新失败、触发器改动写回、COMMIT执行前注入故障均回滚原状态且无部分通知/同步；显式新尝试可恢复。外部事务BEGIN失败不被回滚，回滚未知不报成功。

## 不承诺的保证

没有持久操作ID、单调修订号、请求幂等、防ABA、配置库代际/相同ID复用防护或跨客户端全局锁。若其他操作让完整值回到旧条件，迟到旧请求仍可被接受；用户刷新后明确选择相反目标也是合法新操作，不应称为重复请求已消除。旧外部REST/MCP反转仍可改变状态。此版解决的是条件未变时的即时过期重试及常见并发覆盖。

写请求没有新增自动超时、取消、重试或读回确认，挂起时保持原busy行为；网络未知仍需核对。没有部署、推送、重启采集、打开真实库、修改真实数据或操作设备。构建不代表在用实例已更新。
