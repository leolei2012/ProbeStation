# 存活与采样存储就绪检查

## 问题与兼容决策

基线`02acf5ef1c7965fe86a6ed05a7f950eb01a12cf5`，初始工作区干净。独立冻结副本的实际纯插件装配已证明：DuckDB初始化失败时API仍能ready，/health返回200/ok，而落盘状态blocked/initialization-failed、历史查询500。现有/health只是静态HTTP存活，不能用作采样存储就绪判定。

仓库调用方为scripts/acceptance.ts、test-api.ts及verify-server.ts，均使用原/health；没有发现需自动改写的外部监控配置。acceptance/test-api包含实机或写操作，不在本轮运行。直接将/health改503会改变既有存活监控行为，因此保留其路由、200、`{status:'ok',version:'0.1.0'}`和旧调用方，新增明确的就绪端点。API文档中原“健康检查”表述澄清为“存活”。

现有降级策略保持：HTTP/API可继续提供诊断，存储初始化失败不因本轮自动停进程、暂停采集、修复库或重启。发布和流量门禁必须配置/ready，仅探测/health仍无法判定数据存储正常；本轮不修改用户外部监控。

## GET /ready 契约

响应固定`{version:1,status,scope:'sample-storage',storage:{phase,failure}}`，这里version为探针结构版本，不是应用构建号。成功200，其他503，始终`Cache-Control:no-store`。

| 状态 | HTTP | phase / failure |
|---|---|---|
| 已核实的ready，无已记录故障 | 200 | ready / null |
| 原生初始化中、存储切换中 | 503 | initializing或switching / 原failure |
| 写失败、初始化失败、事务结果不明 | 503 | failed或blocked / flush-failed、initialization-failed或write-uncertain |
| 服务或此能力不可用 | 503 | unavailable / unavailable |
| 读取抛错或状态无法验证 | 503 | unknown / status-unverified |

使用原getSamplePersistenceStatus()及parseSamplePersistence的严格全局协议，不接受设备过滤，查询参数不改变scope或掩盖其他设备造成的共享故障。未暴露SQL、路径、错误原文、队列计数或密钥。不兼容的异步实现直接判unknown，不等待或采信其结果，仅消费拒绝以免产生未处理异常；对应拒绝回归已先失败后通过。

这是同步内存元数据观察：不打开连接、不运行查询、不写“探针样本”、不flush/cleanup/reopen，不重试或取消业务请求，也无新增定时器。健康排队或正常提交中的flushing不等于不可用，pendingRows可大于0仍200；持续故障不会被GET清除。成功提交、初始化完成或安全重开后，原状态变ready即可200，不做额外恢复动作。

## 范围及运维限制

200只代表本次观察到采样存储已完成初始化且无已记录的阻塞/写故障；不主动探测配置库及其它插件，也不是持续磁盘写入探活、容量/延迟/积压阈值、所有历史完整、两库历史配对或设备已连接的保证。尚未反映到元数据的外部故障可能要等下一次业务I/O才显现。配置库或API初始化直接失败时端点本身可能不可访问，同样不能判就绪。

初始化失败需要调查后重建相应服务；现有store不会由就绪GET自动自愈。新就绪端点未改变启动屏障、旧监控策略、配置条件开关的ABA/ID复用边界或未接入的导出配对方案。

真实浏览器、完整硬件插件监听、主入口端口预检、实际长期采集和真实库升级/降级不在本轮验收范围。未推送、部署、重启采集、打开真实数据库、枚举/打开串口、调用模型或安装依赖。
