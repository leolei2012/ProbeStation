# 开关版本兼容与身份边界复核

基线`4e1cddb262090ada53242c6b8c4a3ddf33d6b97f`，初始工作区干净。本轮只用内存ConfigStore、Fastify.inject、实际App回调/useOperation及真实旧/新路由函数复核，不启动完整应用、监听或接触真实配置。

## 版本矩阵

测试中的“旧后台”只注册当前源码中逐字保留的两个旧反转路由；“新后台”在其上注册新增activation路由。“旧调用”验证原POST契约，不加载历史浏览器构建；“新界面”执行当前生产App函数及真实分组读取投影。它是所涉及开关链路的契约验证，不是所有历史版本或真实浏览器验收。

| 前端调用 / 后台路由集 | 实测结果 | 实际影响 |
|---|---|---|
| 旧POST / 旧后台 | 两次200，1→0→1，仍返回原Record | 原反转行为不变，无新增保护 |
| 旧POST / 新后台 | 同上 | 仅升级后台不会保护旧调用方 |
| 新App / 旧后台 | 仅一次PUT，404，不刷新、不发POST，库及运行钩子不变 | 安全拒绝，不是功能可用；需配套后端 |
| 新App / 新后台 | 一次PUT，200，目标0和原通知/同步/刷新 | 原条件保护及warning路径继续由82号回归覆盖 |

因此新旧混用不会自动走危险的反转回退，但新前端搭旧后端时开关暂不可用。生产主入口存在静态前端与API版本不一致的可能；本轮没有部署、重启、缓存清理或在用实例版本检查，不能说用户当前实例已经获得保护。

## ABA及ID的实证

设备和分组分别使用真实新接口验证：

- **即时重复仍拒绝**：原条件1→目标0成功200，原请求再发409，无第二次写入。
- **值ABA仍接受**：用新条件显式恢复到1后，再发最初的1→0请求200；产生一次通知（设备另有一次mock同步）。不只是比较函数相等，而是旧请求实际改变配置。没有请求ID或单调版本，不能识别这是旧意图。
- **正常删除不复用**：原对象删除后用相同字段创建，AUTOINCREMENT产生更大ID，旧路径404，新对象保持1且没有额外通知。不把正常删除等同于ID复用。
- **当前备份恢复为追加**：仅导出并恢复测试自己生成的内存备份；原ID及原行保持，恢复得到新ID。对原ID的旧条件只作用于仍存在的原行，不改变新增克隆。当前restoreBackup不是替换原库或重用原ID，不能将其虚报为已复现的复用入口。
- **库重开仍接受旧条件**：同一ConfigStore/API处理器reopen(':memory:')，新库重建出相同ID和字段，旧请求200并改变新库中的对象。主程序未启用Workspace切换，此测试不声称存在当前界面换库入口。
- **独立库也接受相同条件**：两套不同内存配置实例各有相同ID、字段及状态。A的旧快照送到B的新接口200，A保持1、B变0。若ID和开关值相同但来源IP不同，则409、无写入。风险需要字段也匹配，不是任何同ID都会被接受。

跨实例案例对应旧页面面对新配置实例时的能力边界；没有实际替换用户DB、重启服务或操作任何设备，也没有证明物理设备被误操作。

## 一处兼容的最小修复

分组ActivationSnapshot必须有group。复核发现：缺少group但device对象又带isActive的畸形混合快照，会被可选group的捕获函数临时当成设备快照，随后访问group.id抛TypeError，实际接口500。测试期望写前400，原代码失败。

parseActivationSnapshot现在对kind=group且缺少group立即拒绝400。只增加一项前置校验；无新字段、无响应改变、无库迁移，合法旧activation请求和旧POST继续兼容。缺失/null/数组/空对象分组均400，零通知且原开关保持。它修复的是错误分类与身份形状校验，没有解决ABA或库代际问题。

## 为什么不叠加局部令牌

现有导出scope是内部能力的库打开周期标识，不是所有对象写入的版本；普通开关/编辑不会递增。仅把它附在新activation请求能覆盖部分重开场景，却仍不能防值ABA、其他连接或旧接口写入；复用导出blocked状态还会把开关能力耦合到无关导出故障。只在setActivation内递增版本，同样漏掉旧toggle、编辑、导入及其他写入方。

完整方案需要明确库代际、对象/字段修订和旧写入方如何参与，或持久请求身份与结果记录；新增必填字段会拒绝现有合法activation请求，可选字段则只能保护明确支持的新调用方。没有充分依据将这些变化称为兼容且简单的小修，本轮不添加未接入/不完整的身份基础设施，不迁移真实库。

建议配套测试版继续明确标注条件保护边界；若要求覆盖ABA和库替换，另立一轮设计所有写入入口、版本协商及持久化策略，不能以GET预检、字段哈希或前端锁替代。
