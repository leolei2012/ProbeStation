# 设备编辑冲突与分组风险评估

2026-11-06，基线`4cac52b`，开始时工作区干净。仅本地代码、合成配置、内存库、独立临时库及mock验证；不启动/重启服务、访问真实配置或历史、连接设备/串口/PLC、调用外部模型、部署或推送。不新增依赖、列或迁移。

## 选择范围的证据

设备窗口提交全部表单字段，旧PUT无条件更新后再重建连接及同步从站。内存库回归先打开旧IP快照、另一次更新IP、旧窗口改名保存，实际把新IP恢复为旧IP，断言先失败。通知/重连/同步还可能在配置已提交后抛错，使客户端把已保存看成失败并重复保存。

分组风险更深：现有`updateGroup`会按定义数量缩容，删除点位及其告警，扩容会补建定义。只比较组行不足以判断子点位/告警有没有在打开后被别人修改，本轮先交付设备编辑保护，分组仅评估。

离线内存复现两例：组原数量1，另一操作扩到2并给新增点位建告警，旧窗口把数量1随重命名发回，新增点位与告警被删；另在1→4扩容第二次建点注入异常，组数量已是4，但只有2个定义。评估过程仅触及该次创建的内存库，未改变任何真实配置或分组业务实现。

## 已实现：设备编辑

- 新增`PUT /api/monitor_objects/:id/settings`，体为`{ expected, changes }`，仅设备编辑改用；新建、旧PUT及其他调用保持兼容，不自动回退到无条件保存。前后端须同时支持新接口，旧服务404时不会偷偷降级。
- 正式设备表单抽为`DeviceModal`，挂载时冻结打开快照，后台刷新不会更新预期。TCP/RTU、主从模式、输入/默认值、焦点约束保留；RTU隐藏端口也取打开快照，不取后台新props。错误留在窗口并保留草稿，保存中锁定重复提交；需要先记录修改、关闭刷新再重新编辑。新建仍走原流程，不声称新增设备有并发保护。
- 快照包含ID、名称、角色、TCP/RTU连接字段、从站、采样周期及超时。保守比较整份表单，即使只打算改一个字段，其他表单字段变化也会拒绝。`connected`、`isActive`、历史保留值不在窗口提交范围，不作快照条件也不写回，因此并发启停/保留更新可独立保留。
- `BEGIN IMMEDIATE`内读当前值、核对、校验、参数化写入、读回及提交。冲突409、设备不存在404、非法输入400；这些路径不写入、不通知、不调用连接处理。数据库失败尝试回滚，回滚异常明确待核实，不声称未保存。
- 新接口拒绝未知字段/缺快照/空更新/错误ID/非法数值，按原表单约束检查角色、连接方式、整数与可选值；TCP主站保留主机名能力，从站继续用配置库既有校验（含有效监听IP/RTU参数）。不归一化用户的原条件、不猜默认值、不扩大硬件行为。
- 提交后一次通知，异常返回警告。API再按旧顺序尝试连接重建及从站同步，分别捕获失败，返回`{device,warnings}`及200“配置已保存”，不把运行应用异常变为假保存失败。失败的重建不会阻止后续同步尝试；测试全部注入mock，没有装配真实poller或从站服务。
- 前端只发一次有条件请求，核对返回身份、发送字段及警告，保留已保存警告。异常结果/网络中断视为待核实，不自动重试或退回旧PUT。

这里保证的是元数据条件提交与明确结果，不保证运行状态已经应用成功。连接处理不是数据库事务的一部分，后续并发编辑可使它读取更新的配置；其原等待时长未加新超时，不提供硬件侧事务/持久幂等。旧值改回原值、重建完全相同定义、跨工作区相同ID和内容无法用快照辨认。旧API、MCP、导入等仍可后续覆盖，不是全平台修订号或授权机制。

## 手动模拟检查

项目目录执行`npm run preview:settings`，手动打开`output/playwright/point-settings-preview.html`。同页保留点位原测试，并新增正式设备表单；设备、端口、冲突与警告均合成，串口fetcher固定注入mock清单，不枚举系统端口、不打开串口。资源内联，CSP禁网络，不读写库或启动服务，关页停止并丢弃状态。

1. “编辑模拟设备”改名/改采样参数保存，检查页面内存结果；切RTU查看两个模拟端口，手输路径后刷新不丢输入，再取消或保存，均不连接设备。
2. 打开前勾选“其他用户修改设备IP”，只改名保存应显示409，草稿保留，页面内存保留模拟新IP。先记录修改、关闭，取消冲突选项后重开，应可正常保存。
3. 勾选“配置已保存但连接应用失败”，保存后应关闭窗口并保留已保存及模拟警告，不显示未保存或自动重复保存。
4. 改主从角色、TCP/RTU、空/非法数字、取消、键盘及360px窄屏；同时回归同页点位设置，不能同时打开两个编辑窗口。
