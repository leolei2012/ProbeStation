## 发现

没有在本轮模拟路径复现按需加载覆盖新设备选择、重放业务操作或绕过已有设备/点位草稿保护。加载层只保存代码资源，不保存设备或草稿；组件实例的实际 App 分支类型及设备 key 决定是否继续存活。未加载表单前没有新草稿；已有其他编辑器的登记仍参与导航判断。

**分组表单本身没有共享草稿登记，这是既存缺口，尚未解决。** 受控挂载实际 GroupModal，修改组名但不提交，再调用实际 App 设备选择回调，选择可切至设备 2，没有确认或只读留存；没有发送写入。GroupModal 在本次基线与拆分前父提交的 git blob 均为 `2a5d9f4925129bfb63c5e32d9ec72c072d70ba59`，不是本轮加载引入。日志使用独立 LEGACY LIMIT 标记，测试“通过”表示重现并记录边界，绝不表示分组导航或关页保护已通过。分组仍可能因切设备、切页或关闭而丢失未保存输入，保存期间的离开也不能类推为已受共享保护。

修复该缺口需要确定分组在实时页卸载、取消关闭、保存未决/未知、后台设备移除时的草稿归属与只读留存行为；只在加载层加一个确认会遗漏已加载表单及失败恢复路径，因此本轮没有添加局部伪保护。建议下一轮单独处理分组完整草稿生命周期。设备/点位的原有保护不因此降低。
