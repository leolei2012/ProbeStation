# 设备窗口草稿关闭保护

## 选择与证据

基于干净的`b055deabe96d5c0b21a3ba3bbb28cdb2bf1a1a0f`，继续实际使用流程改进，未扩展导出基础设施。已核实57号草稿关闭保护仅在PointSettingsEditor中使用；DeviceModal虽有保存中的busy及并发基线校验，×和取消仍直接onClose，修改设备名称/IP/RTU参数后会无确认丢弃输入。新旧功能不重复：本轮只扩展到设备新增/编辑窗口，不修改分组窗口。

先用实际DeviceModal函数和其输入/关闭事件进行可控复现：修改名称后点×，close回调调用1次，预期应先保留输入等待确认（0次），断言失败。随后接入复用的本地确认逻辑，原回归通过。没有操作真实设备表单或调用保存API。

## 已接入行为

- deviceDraftFields把全部14项现有原始输入保存为冻结的打开快照，逐字比较当前值；默认值完全沿用旧UI，不做trim/数字解析或自动修复。无改动、逐字改回原值时直接关闭；空输入/前导零/空白及隐藏传输字段的本地改动仍受保护。
- 复用既有PointDraftCloseGuard，不复制状态机。×、取消和窗口内Escape进入相同requestClose：有修改先询问，继续编辑恢复原输入，明确放弃才调用onClose。确认中Escape回到编辑，输入法组合中的Escape忽略，不传播到外围窗口。
- 复用PointDraftDiscard，仅增加可选label用于设备确认的无障碍名称；原点位默认标签、文字及行为不变。询问时禁用普通字段、关闭和保存，焦点意图移向“继续编辑”；恢复后尝试回到触发控件。
- 保存使用同步locked ref阻止任何主动关闭和重复提交，确认中Enter也不能保存。保存失败保留草稿，继续/放弃均不发送重试或撤销；放弃不能证明前次未知保存是否生效。成功保存仍由原App onSave回调关闭，不新增onClose调用或请求。
- 打开快照只建立一次，后台props变化不会把本地输入当成已保存，亦不会给未动的本地快照制造假修改。切换角色产生的地址等原有联动也计入草稿；未改这些联动本身。

这只保护窗口自身主动关闭，不是持久草稿：不拦截浏览器刷新/返回、整个组件被父级卸载或页面关闭，不写localStorage、不自动保存。不改变已有输入校验、设备来源/并发基线、保存载荷/接口、设备连接、采集或串口枚举；未启动主程序。

## 自动验证与UI限制

新增安全白名单test-device-draft-close：用真实DeviceModal源码/事件函数配小型确定性hook驱动，注入状态/ref/effect和模拟document。执行名称/串口编辑、×/取消/Escape/IME、继续/放弃、改回/空/新建/角色联动、后台props刷新、确认中提交和保存锁；验证保存失败保留、原保存载荷/expected基线、成功父级关闭契约、放弃不重试或撤销。逐项检查14个字段改动/恢复与打开快照冻结。

该驱动是逻辑回归，不是真实React DOM或浏览器；焦点ref仅模拟意图，未验证实际Tab、滚动、React提交批次、原生表单校验或IME行为。另有真实组件SSR及中英确认标签测试，SSR不保存/关闭/枚举端口。旧点位草稿及设备并发编辑回归重新运行，避免复用造成回归。

`npm run preview:device-draft`复用现有静态生成器，输出`output/playwright/device-draft-preview.html`。使用实际DeviceModal和仅本页mock保存/端口清单；明确标模拟、不枚举系统端口，不启动服务/数据库/设备/模型。资源内联、CSP connect-src none；真实浏览器视觉和交互仍未验收，遵守原浏览器限制，不重试原生Edge或改路径绕过。

手测：先无改动关闭，再改名称/IP或切RTU选模拟端口，分别用×/取消/Escape请求关闭，检查继续保留和明确放弃；改回原值应直接关。确认中Escape回编辑，Tab仅在可用控件间；保存等待4秒期间关闭无效，模拟失败后仍可继续/放弃且无再次保存。另测新建、空/非法输入、长串口路径、中英、窄屏和输入法。预览选项在关闭窗口后切换。
