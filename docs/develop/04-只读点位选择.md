# 只读查询的精确点位选择

2026-11-06，基线 fbfc48b。只读体验改进；不改设备写入，不启动监听、真实采集或模型服务，不访问真实库。

## 解决的问题

MCP read_register/query_history 和内置助手 query_history 原来只按设备、area、address 定位；不同从站同址会明确拒绝，但调用者没有参数来消除歧义。失败回归传 slave_id=2 仍返回 isError=true，无法读取已知正确目标。现在三条路径共用 core/register-selection.ts，以当前配置和显式条件唯一定位。

| 场景 | 调用方式 |
|---|---|
| 当前设备、area、address 唯一点位 | 原参数继续可用，不必增加字段 |
| 不同从站同地址 | 增加 slave_id |
| 同从站同地址有多个类型/倍率等语义定义 | 增加 register_id 精确选语义 |
| 两个条件都明确 | 可同时提供，必须指向同一点位/当前配置来源 |

device_id、area、address 仍必需，register_id 不替代这些字段。slave_id 为整数 0–255，与核心请求目标元数据范围一致；不改变实际协议或广播校验。register_id 为正安全整数，须从配置列表或返回候选发现，不猜测。

以下仅为参数示例，ID 必须先发现，不是对实际设备执行请求：

```json
{"device_id":1,"area":"holding-register","address":0,"slave_id":2}
```

历史查询也适用同样选择器：

```json
{"device_id":1,"area":"holding-register","address":0,"register_id":42,"slave_id":2,"start":"2026-11-06T00:00:00Z","end":"2026-11-06T01:00:00Z"}
```

MCP 历史仍是原始单地址接口，保留 limit/offset；助手历史仍按相同时刻完整同批解码多字、只让已验证 value 参与统计。没有修改这些消费契约。

## 歧义与失败

错误结构含 error、code 和 candidates：

- REGISTER_SELECTOR_INVALID：无效数据区/地址，或 slave_id/register_id 的类型、整数边界无效；不把字符串或 NULL 强转成编号。
- REGISTER_NOT_FOUND：当前设备/area/address 下没有同时满足所有条件的点位；不会放弃错误条件并改查其他源。
- REGISTER_AMBIGUOUS：仍有多个匹配，返回候选的 register_id、group_id、slave_id、alias、data_type；仅当前设备该地址的配置，按来源/点位排序。用户/明确上下文未选定时不能任选第一项。

MCP isError=true，text 为上述 JSON；内置助手工具返回同一结构。错误在读取缓存/查询历史前返回，助手不为失败结果生成分析来源链接。设备会话范围在助手中先校验，点位 ID 不能越过设备或数据区/地址限制。

## 身份与兼容边界

选择器依据**当前点位配置**，决定目标，不改变历史行身份。分组从站已变更时，旧的 slave_id 与现点位不一致会明确失败；不会按点位 ID 默默改查旧条件之外的来源。需要直接查看旧原始来源时，现有 REST raw 查询可显式选择 slave_id，仍须按返回身份判断。

显式选择不能把旧 NULL 来源或缺批次数据变成已验证值；当前跨源同址无法归属的 NULL 行仍未知/不计自动统计。原始行保留 NULL，已知源和未知字不补齐。配置本身缺少来源时，点位 ID 也不能推断为从站1或授予自动资格。请求目标编号不是额外物理身份认证。

成功响应保留原有主体；MCP 原始历史顶层增加所选 slave_id/group_id，逐行 slave_id 仍是采样原始值。旧唯一调用兼容，错误文本从笼统字符串变为结构化 JSON，依赖解析错误正文的客户端需适配；isError 标志不变。
