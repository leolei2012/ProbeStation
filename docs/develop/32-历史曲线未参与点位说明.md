# 历史曲线未参与点位说明

2026-11-06，基线`289d43d`。只在本地开发、合成配置/mock/隔离测试验收，不部署、启动或重启服务、接触实机、修改真实数据。

## 工作流问题与行为

原曲线API在数值查询前排除十六进制/二进制格式、被同组前项跨度覆盖、点宽越过组末端等定义，响应不解释这些点。HistoryView仍显示“已选”，空曲线最先落入“没有历史数据”，用户难以区分点表资格与真正无记录。

- 曲线页只在存在未参与项时显示说明：所选/可参与查询/未参与数，逐点的配置来源、功能码、地址与精确ID，原因及覆盖定义ID。原因可筛选，每页20项，有完整总数，不截断底层结果。
- 全部不满足曲线规则时展开原因，明确“未发起曲线读取，不等于没有历史数据”，不请求无效曲线、不显示取消/无历史的误导性结果。空选择仍沿用未选点位提示，不查询整台设备。
- 混合选择仅向曲线接口发送可参与ID，原先API最终会保留的点位和顺序不变。图、图例、A/B及原始点回退也只使用这些点；排除项不会被临时可用的相邻字重新画出来。元数据普通刷新和只增减排除项不必重查相同曲线。
- 用户全部选择保留，用于暂存条件、表格与原导出。表格入口只切换显示模式/回第1页，不替换点位、不写配置。表格是否有数据、值是否有效，仍由实际查询和历史质量规则决定，不承诺能找回记录。
- 无任何可参与点时卸载图并清理旧视窗，恢复可参与项后从完整区间读取，避免旧缩放条件与新图轴不一致。仍沿用既有上下文、请求取消/期限和旧响应隔离。

## 保留的选点政策

新增纯函数`planHistoryCurve`，API与前端共用；无I/O、无样本读取、不修改输入。前端使用已建立的客户端点表上下文；API保持原响应格式、未知点位400、设备404以及省略/空选择契约，没有增加协议字段或迁移。

严格保留原顺序：逐组处理，同组按地址稳定排序；先判断是否落在先前跨度内，否则更新跨度，再检查是否超过组末端、hex/bin格式、是否被选择。因此未选项、非数值项、越过组末端的项仍可能覆盖后项；说明会给出其ID，不暗示覆盖者已经绘制。不按名称另选、不自动释放后项、不新增来源/功能码优先规则。

这里只解释现有曲线资格，不替代点表完整诊断或协议合法性校验；原组起始地址以下的历史兼容行为也未擅自改变，范围/引用/混合功能码等需通过“点表检查”核对。缺分组/缺精确ID可解释，但API对不属于设备的请求仍按原方式拒绝。客户端与服务端未观察到的并发配置变化没有版本锁，本轮不声称解决。

“可参与查询”不等于有数据、可表达的数值或质量有效，不代表自动通过/失败。未改变来源、批次、质量、64位精度、历史解码/存储、采样、告警或录制策略。所有修改真实配置的动作仍由用户原流程明确执行。
