# 设备删除与替换导入写前拒绝

基线`c40157b6ebe95b5bd808afdbd69311bf57f87198`，初始工作区干净。本轮审查删除、开关和导入，优先修复整台设备级联删除与XLSX点表替换两个高后果路径的明确写前拒绝提示。继续沿用134/135号的版本化请求拒绝标记，不改事务、删除范围、替换语义、恢复、幂等或采集策略。

## 行为

设备DELETE在调用deleteObject前，XLSX POST在校验Buffer后、调用Sink.importPointBook前，仅读取本地配置状态。只有version=1、phase=quarantined、failure=connection-quarantined才503返回CONFIG_WRITE_NOT_STARTED/not-applied/version1；不调用SQL、删除、导入或从站同步。不依据捕获到的旧事务错误推断请求结果，不自动重开。

设备拒绝error明确写作“本次删除未执行”，并强调先前结果另核实。App仅在请求阶段1、Error包含134号HTTP适配器完整元数据时按明确拒绝展示；普通503、不匹配标记、500、丢响应继续未知，成功后页面刷新失败仍按原成功回执另提示。复用既有严格识别器的非空返回，不使用其保存操作措辞。

删除前只读留存机制不变：即使明确拒绝，旧编辑器也保持停用，不自动恢复到同ID设备；本页保留原始草稿记录，供人工核对。该请求未执行不代表设备仍存在，也不能证明先前删除是否已提交。

XLSX拒绝额外返回report={groups:0,registers:0,errors:[本次导入未执行及核查说明],warnings:[]}。这是服务端在导入尚未调用时生成的真实零写入报告。uploadPointBook仅在HTTP503、完整标记及合法零组/零点位、至少一项错误报告同时成立时返回报告；页面按既有rejected/导入未完成展示原因，不再混作未知。没有在客户端凭503合成零计数。标记缺失/未来版本/旧隔离码/outcome矛盾、缺失或矛盾报告、500以及响应丢失都保持原未知路径。原200验证拒绝、成功warnings和完整结果保留。

旧前端遇新503仍保守未知；新前端遇旧服务端503也未知。只在写方法调用前明确拒绝，原提交/RELEASE确认失败及回滚失败依旧未知，不增加取消、自动重删、重导或旧接口回退。
