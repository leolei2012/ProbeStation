# 点位调用与助手提案条件保护

## 选择依据与实现

上轮清单留下三个用户编辑入口：行内别名直接PUT旧CRUD且后台刷新覆盖草稿；点位MCP没有同字段/来源条件；助手虽先核对单字段、消耗一次性提案，但核对与写入分离，来源改变也不会被核对。此次沿用已有SQLite条件事务，未新增持久版本、数据库迁移或编辑权限。

- 点位条件协议增加`alias`。`getRegisterSettings`在同一读事务中取点位/分组/设备来源，GET `/api/registers/:id/settings`返回`{expected}`；保存仍用PUT同路径的`{expected,changes}`。写锁覆盖核对、字宽校验、更新和实际读回；读回偏离请求时回滚。只比较点位身份/来源及要写字段，省略枚举不比较也不重写，允许并行改其他语义字段；别名/类型本身是点位身份，改变会使其他旧编辑冲突。
- 行内别名使用正式条件接口。原有失焦/回车保存路径保留，开始编辑时的条件冻结。控件仍挂载时，刷新发现同字段/来源变化会保留输入并阻止保存；冲突/失败/未知响应都不会自动重试。15秒超时会结束等待并显示结果待核实，迟到响应不改结果。显式“放弃草稿并重新载入”只读当前一致快照，成功才丢弃草稿，读取失败仍保留。清空仍写NULL；保存期间禁用输入，保存成功后的刷新失败不会伪装成保存失败。未编辑的大枚举不进入别名序列化比较或请求。切换设备、退出配置、折叠/筛选使行卸载时不跨页面保存草稿。
- MCP新增只读`get_register_edit_snapshot {register_id}`，返回`{register_id,expected}`。`update_register`保留原工具名、snake_case变更字段、enum对象映射及结果根记录字段，但执行时必须携带原`expected`；schema将其标为可选以兼容旧调用的错误解析，运行时缺失返回`isError:true`、428、`CONFIG_PRECONDITION_REQUIRED`及`next_tool`，没有自动取当前条件或降级。冲突409，不写配置、不记录成功日志、不触发运行处理。成功附`configuration_saved`和`warnings`，点位修改只更新元数据。
- 助手提案范围不变：device名称/采样周期/超时，group名称/启停，register别名/单位/倍率/偏移，仍必须人工确认。提案创建时同时保存实际before值及原条件；确认通过相应条件事务写入，撤销条件由该次提交返回的快照生成，不能在通知后读当前值来放行旧撤销。条件随原会话文件持久化，但从UI响应及模型工具结果中剔除。缺条件的旧提案/旧撤销要求重新发起，不补新条件放行。保存执行中状态无法持久化时不写配置；已提交后的通知/日志失败保留applied/undone，展示警告。

设备条件沿用完整编辑字段，分组条件沿用全部点位/告警图摘要，比较比助手单字段更保守；遇到冲突须重新审阅。撤销可恢复原有NULL、空单位、零倍率等合法旧语义，不把提案输入的较窄规则套到原值。会话文件与SQLite仍不是跨存储事务：提交后会话落盘失败会通过会话error提示，重启可留下applying/undoing而不能自动重放，需人工核对；没有承诺全局幂等。

## 兼容与未覆盖入口

旧REST PUT `/api/registers/:id`、`/api/groups/:id`、`/api/monitor_objects/:id`仍保留。外部调用没有提供此前快照，服务器不能还原其读取时刻或意图，仍可能最后写入者覆盖；不能偷偷改走这些入口绕过MCP/界面冲突。旧版本服务缺settings/快照工具时应报告版本限制，不自动降级。

窄状态命令、Recorder间隔恢复、删除/创建、导入与备份恢复没有因此统一获得条件保护。值快照/图摘要无法检测改后又恢复原值的ABA，复制库身份及旧外部程序来源也未解决；条件保护不是鉴权。此次没有更新`192.168.90.137:9090`实例。
