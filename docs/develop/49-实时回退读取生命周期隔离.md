# 实时回退读取生命周期隔离

2026-11-07，基线`0f4b3a6d1249683e35d2cd67fe84bd108937e37c`，初始工作区干净。检查根AGENTS.md/.agents仍不存在；核对README、web/store现有快照与客户端请求契约。本轮选择不同于近期告警、录制、持久化状态和保留策略的实时断线工作流。未启动主应用/HTTP/WS监听、访问运行实例或真实库、连接设备/串口/PLC、调用模型、安装依赖、部署/重启/推送。

## 已验证风险

App原fetchFallback在通道未connected时每5秒启动一个GET，没有在途合并、超时或请求身份检查。用修改前App.tsx原函数文本、受控Promise和mock依赖离线执行，两请求先后发起，新快照300先返回、旧快照100后返回，实际接受顺序为[300,100]；“最后应为300”断言失败为100。没有发起真实fetch或WebSocket。

原逻辑只在响应时检查stopped/当前是否connected，不能区分“断线→连接→再次断线”或设备A→B→A；旧轮结果可能在当前仍断线时被接受。旧失败也可能覆盖当前恢复提示。慢请求每个5秒tick继续积累，挂起时没有明确读取失败。

## 修复边界

新RealtimeFallbackRead持有所选设备、通道可用状态与本地generation。每个有效上下文只允许一个逻辑在途读取，周期tick合并，不反复重启慢请求。读操作使用现有runRequestWithTimeout，默认10秒；超时发AbortSignal并结算，即使mock/provider忽略取消，迟到结果也不再发布。正常浏览器fetch收到signal；取消只撤销页面读取，不能保证后端工作终止，更不表示停止采集。

选择变更（包括null）、通道connected状态变化及dispose均增加generation并撤销旧读；A→B→A或断线→连接→断线也不会复用旧身份。不变的设备/通道状态不取消慢读。旧请求finally按实例身份核对，不能清除新请求的在途标记；丢弃的读取不会发布成功或失败。

App把选择与状态变更接入该模型，选择后清除旧回退成功/失败标记。没有选设备、通道已连接或卸载后不发回退GET。10秒超时/当前失败沿用原“保留最后结果，正在重试”提示，后续5秒tick可以恢复；已有值继续按原采样时间/质量/过期规则显示，不因请求失败清零或伪造新采样时间。空快照仍可正常接受，rawValue=0、quality、timestampMs、batchId、slaveId和多从站键均原样传递。

不改REST端点、缓存键、快照/采样批次协议、硬件轮询/采样时间、告警、写入、WebSocket重连退避/心跳/看门狗阈值或设备启停。不按客户端时间戳猜数据来源，也不添加新的样本有效性判定。
