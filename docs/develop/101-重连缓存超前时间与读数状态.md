# 重连缓存超前时间与读数状态

## 证据与边界

基线`4dd492a3896ce41d8ad0383b707648c864ee3ea6`，开始时工作区干净。无AGENTS.md或仓库.agents/skills。本轮继续核对恢复阶段读数，没有扩展流式实验、硬件重连或告警功能。

实际实时曲线sampleCurve和告警读取readAlarmValue已经拒绝大于页面now+1000ms的采样，但共享pointHealth只检查now-timestamp是否超过旧值阈值，负差值被当作未过期；ageSeconds和设备页顶部又将负年龄clamp为0。结果是同一个未来样本在曲线/告警中未知，却可能在表格显示新鲜、0秒前，且无告警规则时甚至不进入“数据问题”筛选。

用真实App WebSocket effect和缓存路径，模拟先收到正常样本、断开、页面时钟回退60秒、创建新socket并收到原缓存快照。现有曲线不生成点、告警读数null，而原pointHealth.stale=false，新回归在该断言失败；原5组连接状态测试通过。这里的时钟变化是纯测试参数，没有改用户/系统/设备时间，也没有推断时间偏差一定来自哪一端。

## 最小修复

pointHealth沿用曲线/告警现有的1000ms容忍，任何组成字超过页面当前时间+1000ms时不再判新鲜，年龄为null。原始值、timestamp/timestampMs和缓存保持原样供检查，不清空、不回填或重写采样，也不改变历史解码、batchId/来源策略、服务器时间或告警阈值。

新增sampleAgeSeconds供共享健康结果及设备页最新采样年龄使用。顶部保留三种含义：没有样本仍是“尚未采集”；时间超前则显示中英文“采样时间超前，年龄未核实”；可接受时间继续按原方式显示相对秒数。原始时间展示仍保留。阈值内的+1000ms仍沿用原曲线/告警容忍，+1001ms才未知，不自行新增或收紧业务策略。

表格、分组摘要、数据问题筛选和冻结快照都使用pointHealth，因而保持一致；冻结JSON仍使用原schema和键，仅stale/ageSeconds由错误的新鲜/0改为true/null。快照始终automaticEligible=false，不表示PASS/FAIL。readAlarmValue此前已有相同未来时间拒绝，修复只使健康判断与其一致，不改变该类样本已返回null的行为；曲线与后端规则代码未修改。
