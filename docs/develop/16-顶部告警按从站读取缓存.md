# 顶部告警按从站读取缓存

状态：已实现，完整离线检查通过；浏览器/实机验收未完成。日期：2026-11-06。

## 已验证的问题

实时表格已使用 `sourceSample` 按设备/从站/数据区/地址取值，`AlarmPanel` 顶部摘要和规则状态却仍读取 `设备:数据区:地址` 兼容键。当前存储发现同址有多个来源时，会删除该兼容键，仅保留来源键。因此目标从站已有有效数据、行内已触发时，顶部可能仍提示等待有效数据。兼容键只有另一个从站时，旧实现也可能用错来源显示触发或正常。

将原顶部取值逻辑提取后，纯快照中来源1=10、来源2=200、没有兼容键，来源2回归先得到null而失败，修复后得到200。内存DuckDB存储写入两从站同址数据，再序列化热缓存，也验证该路径。

## 改动边界

- 顶部告警通过 `readPointAlarmValue` 先确定当前配置来源，再复用现有 `sourceSample` 和 `readAlarmValue`，与实时行内取值策略一致。
- 主站使用分组从站，本地从站使用设备从站ID；无效/缺失配置来源返回未知，不默认分配从站1。
- 兼容键仅在样本明确标识目标来源时可用；其他从站、NULL来源、其他设备或数据区不能补齐目标值。
- 现有时效、质量、多字批次、未来时间检查保持不变；缺字/混批/故障/暂停仍为未知，完整有效数据恢复后继续判断。未更改旧无批次ID样本的既有兼容规则，不宣称本轮重审了全部历史/自动判断策略。
- 不修改比较阈值、规则CRUD、后端事件/日志、缓存/数据库结构或采样行为；本轮修复的是浏览器告警显示，不涉及实机或真实配置。
