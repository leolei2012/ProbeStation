# MBP多窗口导入归组

2026-11-06，基线01813c2。只开发和内存验收，没有导入用户文件、读写真实数据库、连接设备或操作运行服务。

## 预期与复现

仓库已有格式是XML ModbusPoll/Data块、INI Window段和MBS二进制头。以前解析输出groups/registers平面列表，应用层创建所有组后把全部点位写入groups[0]。合成INI两个窗口FC03/FC04复现：FC04点位的所属组却是FC03，回归先失败3!==4。同FC不同范围、同名/同址窗口也不能安全地按名称/地址匹配归属。

没有仓库跟踪的真实MBP/MBS导出样例或原Python解析器可进一步核对厂商变体。本轮依据已实现字段和记录的约定，不声称完整支持所有Modbus Poll版本。

## 修复与兼容

- ParsedRegister新增groupIndex，0-based原始Data/Window索引，不是数据库ID。解析时保留，写入时映射对应新组；MBS为0。纯解析结果的groups/registers/warnings结构保留，字段为增量；外部重新构造点位时需保留groupIndex，缺失时拒绝而非猜首组。
- 同名/同FC同地址/重叠窗口各建独立组，不合并、不根据范围推断。INI同名段按出现顺序保留并提示，不再因对象键覆盖而丢掉前段。
- XML逐字建立点位、Cell/Formats映射不变；32位格式提示仍采用原始int16。INI仍每窗口一条定义，Quantity是组读取跨度，不自动展开多点。入库点位quantity元数据仍为原文件导入默认1；没有按dtype回算或改变备份quantity契约。
- MBS头中已明确解析的slaveId传给新组，不再丢回createGroup默认1；mode=read_write和既有名称启发式保留，不改变目标设备自身编号。
- MBP仍使用现有默认从站1，并在warnings中说明；未推断未验证Slave/Unit字段。INI地址换算沿用旧实现（0/1及40001/30001引用），未重释10001等其他编号、编码或厂商变体。缺真实格式证据时应先核对，不把默认值描述成已发现物理来源。
- 新导入是追加，不覆盖已有设备、组、点位和告警，也不触碰历史。已错误归组的现存配置不自动迁移或重导入。目标/组启用状态的既有创建规则不变，本轮没有实际触发运行设备。

## 写入与错误

ConfigStore.appendImportedPoints先验证完整窗口图，再BEGIN IMMEDIATE写入。只支持当前读取分组FC01/02/03/04，检查现有从站/协议约束、0–65535地址范围、正整数长度、groupIndex、点位类型/功能码与完整字宽；可跨多个PDU，不把整个组限制为125/2000。XML使用已安装fast-xml-parser的验证器拒绝不完整XML；非法数量在生成大数组前拒绝，不猜为默认值。

事务内抑制逐行config事件，成功后仅一次scope=import/id=目标设备的通知，监听者看到完整图。组/点位写入或提交失败回滚，不留下新半组且不通知；回滚本身失败会明确报“结果不确定”，不能自动重试。同步的提交后通知回调失败不能回滚已经提交的数据，会返回“已提交/勿重复导入”警告。空文件/无窗口保持0计数和警告，无写入通知。

原服务import(objectId,filename,content)同步返回groups/registers计数及warnings，REST包装保持原格式。错误由现有服务错误通道返回；无效输入在写入前失败。不改变JSON备份恢复、XLSX点表或importPoints语义更新流程；后者按FC/地址取首项的多源歧义仍是独立待办。
