# 点位设置并发冲突保护

2026-11-06，基线`ce3ab13`。只开发、合成数据、内存/独立临时库与Fastify inject验收；未启动或重启应用、未访问真实配置/历史、未接触设备或模型服务、未部署或推送。不新增依赖、列或迁移。

## 已复现的问题

点位设置原来保存窗口里的全部类型/单位/倍率/偏移/小数位；即使只改倍率，也会发送旧单位。用内存库打开快照、另一次更新单位后保存旧草稿，回归断言期望保留新单位，实际被改回`null`，先失败。上一轮只解决未编辑枚举保留，并没有给标量和明确枚举编辑加并发条件。

## 本轮保护范围

新增`PUT /api/registers/:id/settings`，请求是`{ expected, changes }`。仅正式点位设置窗口改用此接口，禁止自动降级到旧无条件PUT。新前端需要同时支持该接口的后端；旧服务返回404会提示失败而不偷偷覆盖，运行实例本轮未更新。

- 点击打开时冻结原点位及分组/设备来源的独立快照；后台配置刷新不改变这份预期，不自动把新值当作用户已经审阅。前端分组读取保留原来被投影丢掉的`mode`；缺少必要上下文时阻止打开，不猜默认来源。
- 点位身份核对ID、设备/组ID、别名、功能码、起始地址、原类型，以及本次写入字段的原值。分组核对ID、从站、功能码、起始地址、数量和模式。设备核对ID、主从模式/从站、TCP/RTU连接参数。设备/分组名称、启停、采样周期不作版本条件，其他从站同地址点的独立编辑也不冲突。
- 新接口只允许`dataType/unit/factor/offset/enumJson/decimalPlaces`，拒绝未知写字段、缺快照、空更新、ID不一致、非法类型与非有限数。零倍率保留；类型范围继续在事务内按原API上界规则校验。未擅自增加采样、点宽或来源策略。
- `BEGIN IMMEDIATE`锁覆盖读取当前值、比较、范围检查、参数化写入、读回及提交。条件不匹配返回409；点位不存在404；输入错误400；这些路径不写入、不发布变更。数据库失败尝试回滚，回滚失败明确为结果待核实，不声称未提交。
- 成功返回`{ point, warnings }`。提交后只通知一次；通知异常返回已保存及警告，不把已经提交说成未保存。前端核对响应身份、发送字段及警告格式，再显示成功。网络/异常结果不自动重试或降级。
- 冲突错误保留编辑器里的全部草稿，说明先记录需要的修改、关闭窗口、刷新配置再重新编辑。没有强制覆盖或静默合并按钮。

## 与上一轮枚举保留兼容

未编辑枚举仍真正省略`enumJson`，比较时不把这份旧枚举作为写入条件，因此其他人的并发枚举更新可以与标量保存共存，且保留服务端新枚举。明确编辑/清空枚举则必须匹配原枚举，冲突拒绝整份保存。原文、分页、撤销、校验错误行位置及失败草稿保留沿用上一轮。

前端也不把未编辑枚举原文重复塞进请求快照，避免大原文使其他字段保存超过现有请求大小限制；该未使用的快照字段在线上对象中置为`null`，不等于清空操作，因为`changes`中没有枚举。只有明确编辑时才携带真实原枚举条件。此边界新增失败→通过回归，再用110万字符异常原文及真实内存API验证小请求可保存其他字段且原文不变；未扩大Fastify现有大小限制，明确编辑整份大映射仍受原请求体限制。

当前编辑器仍提交整组标量，所以别人改了其中任何一个标量，即使本次用户只打算改另一个，也会保守拒绝；尚未自动计算标量最小补丁。新接口本身允许真实的部分更新，只核对实际写字段及身份/来源，不伪装成三方合并。

## 不覆盖的并发问题

这是当前值条件更新，不是持久化修订号、授权机制或工作区全局身份。某值改动后又恢复原值、删除重建完全相同定义、跨工作区恰好相同ID和内容等无法靠该快照辨认。成功提交后发生的正常后续写入也不会被阻止。

设备/分组编辑、旧`PUT /api/registers/:id`、MCP、导入/恢复等现有调用仍保持兼容，没有统一加条件；这些调用后续仍能覆盖配置。不要将本轮称为全平台防并发覆盖。点表读取仍非服务端跨接口事务快照，打开时客户端混合快照通常会在服务端比较时被拒绝，不提供新的全局版本保证。

UI/API保存遇到网络断开或异常500仍可能结果待定，没有持久化幂等键；应先核对配置，不自动重复保存。保存行为只更新元数据，不发仪器写指令，本轮未变更硬件侧行为。
