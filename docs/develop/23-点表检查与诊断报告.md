# 点表检查与诊断报告

2026-11-06，基线 `2ddbf76`。本轮为既有只读结构诊断增加日常可用的Web流程，不增加诊断规则、自动修复、后端接口或依赖。

## 为什么做

原诊断仅有CLI、REST、MCP/助手入口。操作者发现历史未知值或导入后想核对点表时，无法直接在设备页区分点宽越界、重复定义和有意的多视图。本轮在设备页增加“点表检查”，支持查看、定位和交付完整报告，不需要调用模型。

## 使用

1. 进入设备的“点表检查”页，首次进入读取一次已有 `GET /api/monitor_objects/:id/point-diagnostics`。主站和本地从站都可检查。
2. 查看错误、警告、分组/点位及兼容覆盖占位数量；零问题显示明确空态，不标记PASS。
3. 按级别、代码、说明、点位/分组名筛选；数字或 `#ID` 精确匹配关联点位、组或实体ID，不作地址猜测。
4. 展开“关联点位”，使用配置来源、名称、类型或精确 `#ID` 定位；相同名称始终显示来源/FC/地址/ID。当前页面找不到的ID保留，不映射为其他点位。
5. 问题和关联点位各按20条分页，互不删除数据。清除筛选恢复全部问题。“下载完整诊断JSON”始终包含所有问题，与筛选/分页无关。
6. 修改点表后重新检查。当前界面读取到不同的设备模式/从站/分组/点位配置时会清空旧面板并重新读取；切页取消在途读取，没有定时诊断或自动重试。

刷新时不把旧报告当新结果显示。失败、无效/不一致报告、10秒超时有不同提示，可显式重试；不回显未校验的错误细节。旧响应、切换设备或卸载后的响应不能发布结果。后端尚无该接口时也只显示失败，不回退到硬件探测。

## 报告与定位边界

- 原规则保持[离线点表诊断](05-离线点表诊断.md)定义，错误与警告分开；重复定义可能有意，不自动合并/删除，不改变采样、阈值、联锁或真实配置。
- 这是**配置结构**检查，不读取实时缓存、报文或历史，不代表设备在线、数据质量良好或测试通过。`ok`仅表示原诊断器未发现结构错误。
- 报告是一次配置读取结果；浏览器请求/接收时间不是服务端事务水位。当前界面关联标签可能与该报告快照不同，面板明确提示。此轮不提供点击即修改、硬件操作或历史可信性推断。
- 前端校验scope、complete、计数/严重度一致性、引用类型和设备范围。未知新增字段不会进入显示报告或下载；未来不兼容契约显示无效而不静默当作无问题。
- 下载格式 `probestation-point-diagnostics/version=1`，包含设备ID、浏览器请求/接收时间和完整原诊断字段；不附加连接参数、密钥、点位全表或历史值。不是配置备份，不能通过恢复备份入口导入。
- 数量/消息来自中文诊断器，英文界面翻译操作控件，保留原问题代码/中文说明。

## 离线手测

项目目录运行 `npm run preview:diagnostics`，生成 `output/playwright/point-diagnostics-preview.html`，可手动打开。只用固定合成配置、真实纯函数诊断器和正式面板；无请求、服务、数据库、模型或设备。关闭页面即可停止；本轮不启动/重启任何运行服务。

手测覆盖：错误与警告、级别筛选、搜索 `#48`、展开关联点位按“配置从站 2”或 `#48` 查找、问题与点位分页、筛空后完整JSON下载、无问题和空点表、失败恢复、无效报告、10秒无响应超时、英文控件、长名称和360px窄屏。实际App集成还需检查主站/从站入口、切页/设备、点表变更后的报告失效及重新检查。

本轮检查到现成Edge扩展，但工具的浏览器安全策略拒绝 `file:` 预览且明确禁止绕过，已停止该浏览器动作。未重试原生Edge、扩大权限、改安全设置或改用替代路径；因此真实浏览器点击、下载落盘、窄屏/视觉与完整App集成尚未验收。静态产物和SSR不等同于DOM验收。
