# 录制连接来源条件保护

2026-11-07，基线`81606a6`，初始工作区干净。仅本地代码、ConfigStore内存库、合成结果与mock事件/时钟验证；不打开用户配置/历史库，不启动主应用或MCP监听，不连接设备/串口/PLC，不调用模型，不部署/重启/推送，不安装依赖。

## 复现与目标

现有录制按objectId接收结果，只在配置reopen时识别scope变更，未检查普通连接配置变化。离线复现：设备IP从A改成B后，旧录制仍保存[1,2]两个合成结果，预期只保留旧来源前缀[1]的断言失败。本轮保护这段活动录制的连接配置条件，避免已观察到来源变化后继续混入结果；不猜测协议、不改变触发阈值或关闭校验。

## 来源条件与起止行为

ConfigStore使用进程内不透明句柄，冻结设备ID、角色、传输方式、默认从站字段及有效连接配置的签名/本连接修订身份。TCP比较IP/端口，RTU比较路径/波特率/校验/数据位/停止位/流控；不把TCP闲置的RTU字段或RTU闲置的TCP字段当成当前来源。名称、采样周期、超时、启停、历史保留、点位语义不属于本连接签名；不重解释原始样本或改动已解析的地址/从站筛选。

共享ConfigStore更新函数发现有效签名变化时更换身份，支持同连接A→B→A识别；相同有效值的保存不会仅因字段出现而结束录制。写入失败/回滚的变化尝试会保守撤销旧条件，不自动恢复旧身份。句柄不可通过复制对象伪造，删除设备/reopen使其失效，不新增持久列/迁移。旧两个参数的间隔获取保持兼容，Recorder始终传来源条件。

准备录制时捕获原条件，首次在`BEGIN IMMEDIATE`获取临时间隔前核对同一条件；这次核对发现准备期变化时返回409，不改周期、不创建活动会话。获取间隔通知或加入共享会话期间再变化时，录制会以done及明确原因结束，不再安装计时器或记录虚假的“已开始”日志。多个同设备同间隔会话共用最初来源条件，不借后来会话刷新放行。

录制接收config/changed的设备通知时核对；下一次poller/result接收前、开始新录制或停止/计时结束时也核对，通知缺失不会直接放行下一批。匹配失效为completionReason=source-changed，读取失败/缺少可核对句柄为source-unverified；均停止追加样本及触发，保留已有数据/计数，取消计时器。来源改变后不会再用该事件触发另一段旧录制。

这两类结束**撤销旧间隔句柄并保留当前周期，不自动归还**，即使A→B→A让旧值快照再次相同也不写回。状态为preserved（清理异常时明确待核实），现有录制间隔核对提示与WARN日志携带说明。用户检查当前来源与周期，再通过已有设备编辑的条件保存决定所需值；不会在事件处理里重连、打开串口、读取设备或恢复旧配置。

get/list/page和只读核对入口不为来源检查强制停止当前配置活动录制，也不因来源读取写日志；它们反映事件/结果/终结处理已经完成的状态。既有reopen对旧scope的终结规则保留。已完成录制不会因后来编辑连接参数而改写完成原因/样本。

## 兼容与未覆盖部分

MCP工具参数、已解析的slaveId/地址筛选、原始字与批次/质量字段保持，新增两个完成原因。间隔单字段修改仍可继续录制，结束时沿用39阶段保护；分组从站推断仍在开始时固定，不擅自改选新来源。旧REST写连接参数也经过共享更新函数，本连接修订生效，但旧REST客户端彼此仍无条件覆盖，不能说旧REST已有通用冲突保护。

这是**连接配置条件**保护，不是物理设备认证或poller读时来源证明：普通连接重连而有效值不变不等于身份验证；点表/倍率/类型后续变化也不在该句柄中。没有给poller帧新增读时配置身份，因此新会话开始后旧采集器同编号迟到报文仍需独立解决。外部SQLite/私有SQL的持续来源变化可在下一次核对发现，但绕过共享写入函数的A→B→A可能无法识别；未新增跨进程持久修订或猜测时间容差。

不使用全库data_version终止采样，因此别的连接仅写日志不等同于来源变化；间隔归还仍保留39阶段更保守的外部提交规则。本轮没有真实库迁移或实机来源验收，运行实例未更新。
