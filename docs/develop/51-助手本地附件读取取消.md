# 助手本地附件读取取消

2026-11-07，基线`755b58b05aad8764a37921d2d3be242df6df0805`，初始工作区干净。核对README、AssistantPanel、本地FileReader流程、服务端附件解析及现有大附件回归；根AGENTS.md/.agents仍不存在。本轮未启动主应用/监听端口、打开真实配置或历史库、读取用户文件、调用模型/外部服务、连接设备/串口、安装依赖、部署/重启/推送。

## 已验证问题与选择

原addAttachments用Promise.all并发读取，没有可取消操作，也未保留FileReader引用。一个文件失败后，界面退出readingFiles，但其他文件继续读取；大文件耗时期间用户无法中止本批。使用基线原函数文本、仅做TS语法转换、mock FileReader和状态回调离线复现：首文件onerror后busy为[true,false]，仍在读取的第二个文件abort调用为0；预期1的断言失败。没有打开真实文件。

服务端和既有测试明确支持较大附件、多个附件，本轮不猜新的限制策略；没有新增任意文件数量或字节上限。不调整服务器bodyLimit、附件内容校验、模型容量或计费策略。

## 实现与行为

新增本地AttachmentBatchRead：先完整检查所选批次的支持扩展名和有效非空文件大小元数据，再启动读取。保留原PNG/JPEG/WebP MIME补扩展名和粘贴图片默认名。元数据不通过时本批不打开任何reader；这不是图像签名/UTF-8内容校验，服务端原验证仍有效。

每批有独立AbortController/身份，重复调用不会并发启动新批。所有文件成功后按原选择顺序一次性追加；一项失败会中止仍在读取的同批文件。取消立即释放忙碌状态，不部分追加，不删除先前已有附件、不改输入文本或原文件。新批开始后，旧批的迟到成功/失败/finally都不能追加或清除新锁。

FileReader适配器只读取用户传入的Blob，监听load/error/abort，接受base64 DataURL；完成后释放事件回调和abort监听。取消先结算本地等待、再调用reader.abort，不依赖浏览器是否继续派发abort事件。已经取消的回调即使迟到也无效。组件卸载静默取消；effect重新装配时按模型实际状态复位忙碌，不把旧读取带到新设备组件。同步reading标记也用于发送前检查，避免只依赖React下一次渲染的禁用状态。

正式界面新增“正在本地读取附件，尚未发送…”及“取消读取”，按钮type=button，不提交聊天表单。取消后沿用既有提示区说明已有附件保持；发送/移除/粘贴文本等原流程保留。不调用模型、上传或删除文件，选择附件本身仍只是本地准备；正常发送行为由用户原发送动作决定。

## 剩余限制

仍使用并发FileReader和base64内存，成功读取的大附件会占用草稿内存；没有新增流式上传、进度百分比、持久草稿、资源配额或自动超时。挂起读取由用户取消，不按任意时长擅自拒绝大文件。服务端图像签名、UTF-8及所选模型能力检查可能在发送时失败，本轮不预先声称内容/模型兼容。

取消仅作用于本地本批读取，不撤回已有发送、不中止正在运行的模型任务、不改变会话/提案写入语义。已完成批次仍按原发送后清空规则处理；聊天网络请求和上下文恢复生命周期未在本轮改造。文件名仅作显示和原附件协议元数据，不当作本机路径读取。
