# 阻止写入的交互与无障碍组合验证

基于fec9d2d。没有发现新组件重新发送数值的可达路径；本轮只补最小语义关联、移除已无用途的成功回调，并扩展隔离验证。185号界面风险缓解的范围不扩大，生产来源绑定仍未修复。

## 发现与最小修改

原WriteModal的label没有htmlFor/输入id，阻止原因没有被输入框或禁用按钮引用；对话框也没有标题/描述关联。本轮使用React useId建立稳定的标题、原因和输入标识，补label与aria-describedby，声明dialog角色及标题关联。没有加入未经验证的焦点陷阱、全局键盘拦截或aria-modal保证。

新界面已移除发送函数，但实际WriteModal JSX仍传入不会使用的onSaved回调，内容会显示写入成功。新断言在旧组件失败；本轮去掉这一死参数和回调，不宣称旧组件此前仍能发送，也不影响旧页面保留的回调。关闭和阻止按钮明确type=button；阻止按钮继续disabled且没有发送/键盘/提交处理器。

| 迟到确认 | 新弹窗参数不再包含onSaved，组件没有确认请求、成功定时器或发送逻辑。未声称能撤销旧页面的既有回调、旧代码或后台操作。 |
| 在途旧请求 | 实际Fastify旧写路由＋内存配置＋受控pending spy：接纳后显示新阻止组件、改变从站，再释放旧目标；旧请求仍返回成功，新界面保持禁用和输入，未发新请求或显示写成功。证明“不追溯保护”的边界，非硬件回滚。 |

所有UI写适配器只连接进程内实际路由和唯一spy；若新界面发请求就会被计数。独立旧REST调用仍可写spy从站9，旧MCP/后端/驱动文件未修改。新界面不影响采集、只读曲线/历史、观察清单或配置写入；相关既有回归随本轮检查执行，仍不代表全套浏览器操作已验收。
