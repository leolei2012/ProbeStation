# 告警编辑、删除的原规则核对

2026-11-07，基线`70993ee`，初始工作区干净。仅本地代码、内存配置库、专用临时双连接库、Fastify.inject及mock；未启动主应用、采集/串口/PLC或实际模型，未读取真实配置和历史库，未部署、重启、推送或安装依赖。

## 已证实的问题与范围

告警窗口以当前规则填充草稿，后台每10秒刷新规则列表，但保存与删除仍只按ID执行。离线复现：打开阈值100后，另一编辑改成200，旧窗口提交150会成功把200覆盖；预期409的断言先失败。删除确认只存ID且跟随当前列表绘制，会把后来变化后的规则直接删除。

本轮只保护规则自身内容：ID、目标点位ID、比较符、原始值阈值、提示。不是点位dtype/地址、设备连接或分组来源修订锁；不改变告警比较含义、阈值范围、采集或硬件行为，也不新增自动判断。

## 契约与实现

共享captureAlarmRule冻结明确字段的原始副本；后台刷新不替换原条件。更新、删除使用新settings端点，不让旧客户端静默落到新的不完整契约。更新changes仅允许operator/threshold/message且非空，不允许由此改选点位；阈值维持有限数，允许0、负数与原有大数；提示保留NULL/空字符串及原200字符上限。界面沿用原先的提示trim/空转NULL行为。

ConfigStore在BEGIN IMMEDIATE下读取当前规则、核对全部原字段、执行更新/删除、读回确认、COMMIT；异常回滚且不通知，回滚异常明确待核实。删除仅该规则，不删除点位或其他同地址规则。提交后通知失败不会冒充写入失败，成功响应携带warnings；通用服务错误不返回内部数据库细节。

`PUT /api/rules/:id/settings`请求`{expected,changes}`，`DELETE`请求`{expected}`。响应`{rule,deletedRuleId,warnings}`；更新返回已核实rule及deletedRuleId=null，删除返回rule=null及原ID。400表示参数拒绝，404表示规则不存在，409表示旧值不符/批量更新中，500明确结果需核实。前端严格校验响应字段及预期内容，无自动重试、无旧端点回退。新增仍使用原POST接口，但校验返回ID和提交字段，异常不能当成功。

正式AlarmPanel编辑按钮冻结原规则；删除确认独立保留原ID/目标ID/条件/提示，即使列表刷新或消失也不改成新确认对象。冲突保留草稿并说明未执行；写入超30秒、响应丢失/异常或成功后读回失败，保留草稿且锁住直接保存/删除。只读刷新不解除该状态，不重复写。用户记录所需修改后明确放弃草稿，再从新读取的规则编辑。显式选择另一条当前规则也属于新编辑意图。

客户端等待超时会中止HTTP等待，但不能保证服务器没提交；迟到成功不会自动解锁或抹掉待核实状态。已返回成功后的读回即使报HTTP409，也按待核实处理，不能宣称原写入被拒。正在写和已完成尚未重置的操作也不能双发。

## 兼容与限制

旧`PUT/DELETE /api/rules/:id`及旧MCP告警更新/删除仍是无条件接口。新界面能识别它们造成的规则字段变化，但没有让这些旧调用彼此具备冲突保护。新增规则没有服务端幂等键，关闭重开/刷新或新的明确新增操作仍可能重复，待核实必须先读回人工核对。

本轮为值快照比较，不记录持久修改计数，A→B→A回到完全相同内容可能匹配；不宣称识别同值写入、跨进程完整历史、同ID历史来源或点位上下文变化。尤其同一点位改dtype/从站而规则未变时，本条件不检测，需独立升级；未静默猜测来源。
