# 按来源选择曲线点位

2026-11-06，基线7a8482e。本轮改进实时曲线及历史表格/曲线共用的选点流程，只使用合成点表、纯函数、静态渲染和隔离预览，不修改设备配置或采样行为。

## 问题与实现

原RegisterSelectModal只显示分组名、别名、地址和FC。同名分组下不同从站的“温度@0”看起来相同；点位ID只作为React key使用，用户无法用它区分。先将原组件原样提取后补SSR回归，基线渲染确实没有“从站2”，测试先失败。

RegisterPicker.tsx现在在组标题和点位行中显示当前配置从站，并在点位行显示#数据库点位ID。来源不明确显示“来源未知”，不补为1。HistoryView和LiveCurve两个入口都传本地slave模式的设备自身编号；此时不用未参与采样的组从站号来误导选择。

增加从站筛选，只有可选点位的来源才列入选项。搜索继续支持名称/分组/dtype，增加精确id:22或#22、slave:2、补零十六进制0x0000，以及空格分隔的组合条件。普通以#开头的名称仍可搜索。来源筛选与搜索仅改变可见列表，不清除其他来源已勾选的草稿。

“全选”改为“选择筛选结果”，明确只增加当前结果；“清空全部选择”仍清空包含隐藏项的全部草稿，语义没有偷偷变成只清当前来源。实时曲线原8点上限保留，达到上限不替换已有选择。无搜索结果时可“清除筛选”恢复全部候选，草稿保留；保存才把草稿交给原选点状态，取消不提交。

register-picker.ts只处理来源解析、过滤和受上限约束的集合复制；不发请求、不读写配置。当前从站是配置目标，不代表实时通信/质量已验证。原来源隔离、样本质量和自动判断规则保持已有实现。

## 可重复手测入口

在项目根目录执行：

```powershell
npm run preview:picker
```

生成output/playwright/register-picker-preview.html，直接用浏览器手动打开该文件。全部JS/CSS内联，connect-src为none，无数据库、API、设备、localStorage或服务端口，选择仅保存在预览页面内存；关闭页面即可停止。预览最多2个点以便快速触发上限，实际实时曲线仍是8个。生成器只覆盖带自身标记的旧预览，不覆盖同路径的其他文件；生成产物已忽略，不入提交。

建议手测：

1. 打开“选择点位”，确认两路同名温度显示从站1/#11和从站2/#22；勾选11后切从站2，11应保持在总选择数里。
2. 使用“选择筛选结果”，再切其他来源确认上限不会替换隐藏选择；保存查看页面“已应用点位”，再次打开后修改并取消，确认已应用值不变。
3. 搜索id:22、0x0000和一个不存在的名称；清除筛选应恢复候选和已有草稿。
4. 切预览角色到本地从站7，组原始编号1/2不应作为当前来源显示；未知来源模式仍可通过主站下“来源未知”筛选找到。
5. 勾“空点表”确认空状态；窗口缩至约360px检查长名称、省略提示、元信息换行和操作按钮。检查Tab/Escape操作及取消/保存焦点行为。
