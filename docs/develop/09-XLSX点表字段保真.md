# XLSX点表字段保真

2026-11-06，基线44e3320。只使用:memory:配置库、合成工作簿及现有安全回归的新临时库，不导入真实配置、不访问硬件、不更新运行服务。

## 依据与复现

现有v2工作簿第2行已明确包含分组从站、功能码、起始地址和数量；第I列导出点位独立quantity元数据。后者沿用ConfigStore/JSON备份已确认的正安全整数契约，不按dtype重算。实际点宽由registerWidth决定：16位1字、32位/q31为2字、64位4字，LE不改变宽度。

旧代码忽略从站及I列、用parseFloat(...)||1覆盖零倍率，并按最大起址减最小起址加1重算组跨度。它还调用updateGroup补建缺失地址，可能把稀疏点表变成更多占位点。合成组[100,108)、从站2、两点uint32@100/float64-LE@104、quantity分别8/9007199254740991、factor=0，先在旧代码同时复现四类不一致。

## 当前规则

Sink先用pointbook.ts将整本工作簿解析成带从站/完整范围/点位/告警的计划，再进入上一阶段的配置事务。任意格式/字段/范围错误均返回0计数及errors，不开始删除或写入。事务写入失败仍整次回滚；同步通知/日志失败的已提交警告规则保持不变。

| 内容 | 处理 |
|---|---|
| 分组从站 | 原值写入新组；显式值须符合现有读取协议1–247，不取目标设备编号代替 |
| 点位I列quantity | 1–9007199254740991的正安全整数，数字或十进制整数字符串；空/缺少可选列默认1；不改变实际字宽 |
| 系数/偏移 | 有限十进制数（支持指数）；保留0和负数；空系数默认1、空偏移默认0；拒绝NaN/Infinity/部分解析和十六进制文本 |
| 显式分组范围 | 保留起始地址/数量，包括预留头尾和gap；检查0–65535及每个dtype的完整覆盖，不自动缩小或扩组 |
| 未填范围 | 起始地址和数量必须同时空，按最小起址至最大完整dtype末端推导并给warnings；只缺一个则报错 |
| 稀疏/空组 | 只创建文件中明确的点位，不调用updateGroup补点；有合法显式范围的空组可以往返，无范围又无点的空页拒绝 |
| dtype/功能码 | 现有codec支持的类型（保留旧_LE拼写）；点位FC须等于组FC01–04；不猜未知类型或功能码 |

原v2布局与版本不变。第1行“分组”、第4行前8列及告警页表头需符合已记录的固定格式；I/J可选列只能缺列且数据也空，不能在未知/无列头下解释非空值。数据完全空的行跳过，只有无意义K列计数也不创建点。列位置不自动移动。非空非法值不会通过parseInt/parseFloat的前缀解析变成另一值。

兼容旧默认：从站缺失/空保持旧默认1、FC缺失/空保持旧默认FC03，均返回warnings要求核对；不是发现了真实物理来源，也不会改旧历史。范围推导同样返回warnings。当前Web会检查errors并刷新数据，尚未增加warnings展示；REST/MCP调用方应检查完整报告。

点位数量与采样范围分开。例：uint64@104、quantity元数据=9007199254740991，实际仍只需104–107四字，不能据此数量生成海量点或扩读。导出的长整数本来就以文本写入，Excel编辑时应保留文本，避免电子表格先发生有效位数舍入；本轮只验证ExcelJS库内往返。

## 保留边界

v2没有分组mode/isActive字段，导入仍按既有read/启用默认创建；“设备信息”仍仅供参考，不覆盖连接、设备从站号或暂停状态。本轮不新增未确认格式字段。告警仍按分组名+FC+起址唯一匹配，不能表示同名同址的多定义，歧义拒绝。分组名称清洗后碰撞的导出问题尚未处理。

别名/单位及枚举沿用既有裁剪/值=标签文本语法；枚举标签内的分号没有转义约定，不能承诺任意字符串无损，非法片段现拒绝而不默默清空。超出显式组范围的既有覆盖定义也会拒绝导入，不自动改范围。需要精确保留所有配置字段时仍优先使用JSON配置备份；本轮不宣称XLSX等同完整备份。没有UI改动或视觉/实机验收，未部署或重启服务。
