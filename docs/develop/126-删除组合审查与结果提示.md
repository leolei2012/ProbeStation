# 删除组合审查与结果提示

基线 f115150，开始时工作区干净。本轮仅使用 `.npm-cache/rv-ready-lLgroB/src` 独立候选、既有依赖、内存 SQLite 或新建的合成临时 SQLite。没有启动主应用、读取真实数据库、连接设备或覆盖在用 dist。

## 复现与修复

分组删除原先沿用通用操作错误提示。通过实际 App 删除回调、实际 `useOperation` 和从 API 源码提取的删除路由注册代码，接到 Fastify.inject 与真实 ConfigStore：后端删除已提交但响应丢失，仍显示“操作失败”；刷新回调抛错时，也未区别请求已经返回成功。英文通知失败还会显示中文原始错误，缺少英文结果待核实说明。

设备删除已有结果未知保护，但已成功 DELETE 后，刷新回调抛出 HTTP 409 仍被提前匹配成删除阶段的错误，丢失“删除请求返回成功、页面未同步”上下文。

最终回归在基线 App 上有 10 项失败断言、29 项原有正确行为通过；候选 App 上 39 项全部通过。最初一次绿色尝试暴露测试中“不能包含通用失败前缀”的断言写反，已修正并重新在基线、候选各跑一遍；不把测试断言修正误计为产品缺陷。

本轮只修改 App 两处删除结果格式：

- 分组请求阶段的非明确拒绝错误提示“删除结果待核实，可能已生效”，要求核对配置，不自动重复删除。
- 请求已经返回成功后，刷新回调错误明确为“删除请求返回成功，但页面未同步”。
- 设备的既有 HTTP 状态透传只在删除请求阶段使用，不再误分类后续刷新错误。

保留原确认、操作锁、草稿只读留存及 API 路径。不改变后端删除 SQL、范围、事务、通知、状态码或成功 JSON；没有加入重试或用读回结果猜测提交状态。特定 HTTP 状态仍透传原错误，不能据此推导数据库必定未变。

## 39 项隔离组合检查

| 类别 | 覆盖 |
| --- | --- |
| 两连接观察，12 项 | 设备、分组、点位各有独立语句旧行为对照、原子成功、SQL 中途失败、提交后通知失败。写连接的 DELETE 触发器调用测试函数，从另一个只读连接读取：旧独立语句可观察到部分结果；保存点成功/失败期间读取方始终看到原已提交图，最后才看到完整删除或原图。 |
| 锁竞争，1 项 | 新建文件库的 reader 保持事务/读锁，删除提交失败后无通知、无残留写事务、原行无损；明确释放 reader 后，测试主动发起另一次删除成功。这是测试显式恢复，不是生产自动重试。 |
| 嵌套事务，2 项 | 同一外层事务先修改无关设备、完成一次点位删除，再令分组删除失败，只撤销本次分组删除，允许调用者保留此前操作并提交；另一场景在外层通知失败后由调用者回滚，原图恢复。 |
| 分组界面回调，14 项 | 中英各覆盖响应丢失、提交后通知失败、SQL 失败、明确 409、刷新抛错、用户取消、等待期间再点击。检查提示、精确数据图、请求次数及刷新次数。 |
| 设备界面回调，10 项 | 中英各覆盖响应丢失、提交后通知失败、SQL 失败、普通刷新错误和 HTTP 409 刷新错误。检查一次请求、保留的只读草稿、旧编辑器禁止保存及选择状态。 |

删除图包含目标设备/组/点/规则，以及无关设备、同设备其他组、其他点与规则、日志和固件哨兵，逐场景精确比较。历史时序删除不在 ConfigStore 路径，本轮未改动时序库；不把 SQLite 哨兵验证说成真实历史数据验收。

旧行为对照只执行当前方法保存点内部的原 SQL 语句序列，不依赖 Git 历史，也不运行旧主应用。文件库使用公开原生 SQLite 接口，busy_timeout=0 仅设于测试库，使锁失败可控；清理前验证临时目录的绝对父目录、拥有者前缀、非链接类型，仅删除本次 fixture 目录。测试封锁真实 net listen/connect/fetch，未捕获到网络尝试或未处理拒绝。

## 仍需验收

本次是同步 SQLite 语句执行期间的两连接重叠读取、受控锁竞争及实际回调/路由组合，不是实际多进程、真实 HTTP 套接字、代理或浏览器点击测试。未改变异步刷新任务本身的错误处理；这里只分类删除回调能捕获的刷新错误。正常刷新成功不证明页面连接到的设备身份或数据库完整性。

外层事务的通知仍在其提交前发生，SQL 回滚不能撤回已送出的外部通知；本轮保留兼容契约，未增加提交后事件队列。未知回执、回滚自身失败、触发器外部副作用、跨会话重复提交、ID 复用/ABA 仍需独立设计，不能承诺幂等。

没有 schema、依赖、保留策略或采集行为变更，没有推送、部署、重启服务或真实数据库迁移。真实浏览器及在用设备均未验收。
