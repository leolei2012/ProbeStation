# 点位保存未知结果提示

## 复现及范围

基于干净的`d4da264c5c638bf43ca6fb9d56c37c4088c6d0f6`审查其他配置写入。设备/分组已将请求异常标为未知，点位saveGuardedPointSettings仍直接透传put异常。真实内存ConfigStore和registerPointSettings路由先成功保存单位/零倍率，再模拟传输抛出TypeError('Failed to fetch')；旧代码的待核实提示断言失败，原异常进入编辑器错误区域，缺少可能已保存的说明。

这轮只调整点位有条件编辑helper的请求异常处理，不改变API、SQLite结构、业务阈值、采集、来源或枚举契约，不处理其余写入。告警已有独立AlarmWriteGate未知结果阻断机制，这轮不改它。

## 行为

- 本地parsePointEditRequest仍在发送之前，非法输入原样拒绝，零请求，不误称为已发出的未知操作。
- 只捕获一次put调用的异常。沿用现有HTTP错误格式和分组/设备约定：400/403/404/409/413/415保留同一Error及原因；网络、解析、5xx及其余不可判定异常显示“保存结果待核实，请核对配置，勿自动重复保存”。HTTP 4000等不被误判成400。
- 发送地址、来源基线、未编辑枚举不重复发送、成功响应校验及warnings冻结均不变。既有PointSettingsEditor错误和草稿关闭保护承接提示，未修改组件代码或布局。
- 不自动重试、读回宣称成功、降级无条件写入、撤销或更新旧基线。人工再次保存仍走原冲突保护；本轮未增加跨请求幂等或禁止人工忽略提示保存。

未知结果并不证明已保存或未保存；明确的错误响应也不推断此前丢响应的请求结果。用户仍需记录草稿、关闭并刷新核对配置后再决定后续操作。
