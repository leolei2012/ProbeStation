# 配置恢复结果与重复操作保护

2026-11-06，基线 `70ee283`。只开发、内存库与mock验证，不读取真实配置，不启动/重启服务，不连接设备。

## 已复现的问题

`ConfigStore.restoreBackup` 原先在事务COMMIT之后直接调用变更通知，通知同步抛错就使REST返回500。纯内存复现：第一次显示失败但已新增1台设备，按原界面再次恢复后显示失败且已有2台。新增真实API回归先失败（实际500、预期200），最小服务端修复后通过。

原界面还会在网络错误后保留同一份可确认预览，容易直接重复恢复；关闭设置会丢失正在执行的状态。服务端恢复是新增独立设备，不是幂等覆盖，不能把“未收到成功”理解为“未提交”。

## 现在的行为

- COMMIT之后的**同步**通知失败返回成功计数、新设备ID和安全的`warnings`，明确要求刷新核对，不回显异常细节、不重试通知。事务内校验/写入/回滚保持原样，已有配置保留，新设备仍暂停。旧客户端可忽略新增字段；新客户端兼容旧成功响应缺失warnings。
- 前端预览验证格式、逐类数量与所选文件数组长度、设备列表字段。确认时同步消耗该份预览，React尚未刷新或连续触发也只发送一次恢复。恢复结束后，包括明确拒绝在内，均需重选文件和新预览才能再次确认。
- 成功报告保留文件名、设备/组/点位/告警数量、新增设备ID和通知警告，便于刷新设备列表核对。
- 网络异常、5xx、2xx但JSON/数量/ID不一致，显示“恢复结果待核实”，不声称回滚或未写入。仅现有请求保护/校验路径使用的400/403/413/415标为请求拒绝；未知失败保守视为待核实。
- **恢复写请求不附加AbortSignal、不设客户端写入超时、不自动重试。** 超过10秒只显示等待提示，继续等待原请求。关闭设置不会撤销请求；本页签重新打开设置可查看同一操作的待定或完成状态。
- 预览是只读请求（服务端只对隔离内存库试恢复），可取消并有10秒上限，文件读取也在该边界内；取消/超时/旧响应不会发起恢复或覆盖新预览。预览未确认时关闭设置会丢弃该份提案。

## 内存记录的边界

操作记录由浏览器页签内的`ConfigBackupFlow`持有，React视图只订阅。记录不写localStorage、配置库或磁盘，不上传到其他服务；私有恢复请求正文在确认时消耗，不放进视图快照，已读取的提案/结果快照冻结以免无意修改。

这**不是服务端幂等协议或持久化作业**：浏览器刷新/关闭、新标签页、不同浏览器或重启后不保留防重状态；响应一直不返回时，原请求仍显示等待。明确重选并再次确认也允许新增副本。因此待核实后必须先核对设备列表，同名提示仅供参考，不能证明同一备份已成功恢复。没有自动根据名称/数量推断成功，没有自动重放、撤销或启用设备，也不增加真实数据迁移。
