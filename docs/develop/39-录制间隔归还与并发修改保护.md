# 录制间隔归还与并发修改保护

2026-11-06，基线`1b5e777`，工作区初始干净。本轮只运行mock/内存库/新建临时SQLite库，不打开用户配置或历史库，不启动MCP或主服务监听，不部署/重启采集、不连接设备/串口/PLC、不调用模型、不推送、不安装依赖。

## 复现与修复范围

旧Recorder在结束时先读设备，确认当前间隔仍等于录制值，再用无条件`updateObject`恢复原值。回归在读取后插入用户750ms修改，旧实现仍覆盖成1000ms，断言`1000 !== 750`失败。仅将比较与更新放进事务仍无法识别用户写回同值或改后改回的意图，因此本轮同时补充写入身份。

ConfigStore新增进程内录制间隔句柄，原始值读取/临时间隔设置、最终核对/恢复分别在`BEGIN IMMEDIATE`事务内完成，使用绑定参数及事务内实际读回；失败回滚并报告，不降低原有输入/读回校验。第一会话记录锁内真实原间隔，避免prepare之后用户改动导致恢复旧值。原/临时间隔须为1..2147483647整数，不为非法旧值猜默认值。没有增加数据库列、表、触发器或迁移。

句柄归属于当前ConfigStore连接，保存在WeakMap，不序列化给MCP。核对内容为提交时设备编辑快照、该设备间隔写入身份及SQLite `data_version`：

- 本连接通过共享ConfigStore写入函数更新`pollIntervalMs`时，无论新旧值是否相同都更换进程内身份；回滚的写入尝试也保守失效。当前旧REST、MCP窄命令、正式设备编辑和助手均通过该函数写间隔，已核实没有其他生产直接SQL改间隔的路径。日后新增直写必须接入身份失效逻辑；不将私有db直接SQL访问冒充受支持接口。
- 其他SQLite连接的提交由`data_version`识别，不凭当前值相同就认为仍拥有恢复权。它不说明修改了哪一行/字段，因此**任何外部提交（包括别的连接写日志）都保守取消自动恢复**，保持当前值并要求核对。自己连接写日志、修改其他设备则不使本设备间隔失效。设备编辑字段变化也拒绝恢复；启停/保留时长仍是独立字段。
- 工作区reopen清空身份，即便新库设备ID和数值相同也不放行旧句柄。删除目标使句柄失效，不创建替代设备。恢复只尝试一次，成功、冲突或结果不明均不重取条件、不自动重试；复制/JSON往返后的句柄不具备所有权。

Recorder仍允许同设备同间隔的多个会话共用最初句柄，只有最后一个结束才尝试恢复；间隔/身份已变时拒绝新会话加入。共享句柄不会在后来会话开始时刷新。开始/归还期间阻止同一Recorder的同步重入。来源筛选、触发条件、10分钟触发上限、最近50段规则保持原契约。

## 调用方可见结果

旧工具名、参数、录制ID、`ok`及录制的原有字段保留，新增：

| 入口 | 新增结果 |
|---|---|
| start_recording / start_trigger_recording | warnings；开始后的通知/日志失败不伪装为开始失败，不诱导重复开始 |
| get_recording / list_recordings | intervalRestore及warnings |
| stop_recording / delete_recording | interval_restore及warnings；删除前也保留最终恢复结果供本次响应查看 |

`pending`表示录制仍持有待归还句柄；`shared`表示该会话结束时仍有其他活动会话；`restored`表示本次事务已恢复；`preserved`表示条件失效，未自动恢复；`uncertain`表示恢复执行/提交/回滚状态需核实。停止不存在ID的旧行为仍为ok=false，新增状态为null。重复停止不再执行恢复，计时器和手动停止/删除走同一终结路径。

**录制done/ok=true不证明间隔已恢复，更不证明硬件实测频率。** 冲突可能保留录制用的短间隔；必须展示/检查警告并人工核对当前周期。通知失败时DB已保存与运行应用状态分开。定时器内恢复异常不会逃逸为未捕获异常，样本/完成状态仍保留；不在后台反复写间隔。

## 兼容与剩余限制

旧REST `/api/monitor_objects/:id`仍接受无条件更新，响应契约不变。同连接旧REST写间隔会撤销录制的自动恢复权，但**旧REST客户端彼此仍可能覆盖配置**；此保护不是给旧接口补上客户端快照，也不改变外部调用语义。其他设备/点位的值快照、删除/导入等并发边界仍见38阶段。

句柄与录制会话均只在当前进程内，不是持久锁、跨进程录制调度或崩溃恢复协议。服务退出/崩溃不自动恢复临时间隔，也不根据持久行的同值猜所有权；未新增启动时自动写配置。多个进程/独立Recorder实例不共享会话排程，外部提交只会保守失效；需要跨进程协作应单独设计。没有为恢复覆盖用户改动的强制选项。
