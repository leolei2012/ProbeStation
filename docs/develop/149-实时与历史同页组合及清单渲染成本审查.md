# 实时与历史同页组合、清单渲染成本审查

基线 ef664f6fa09ae3e0d5ef7c7760a8b52e8f38479d，初始工作区干净，AGENTS.md/.agents 不存在。历史观测证据原型保持实验状态，本轮没有扩展它或增加未接入基础设施。生产改动仅限 live-watch-list.ts 的显示集合计算。

## 已复现的成本与修复

原 liveWatchResult 在仅看关闭时仍 new Set(matches)，仅看开启时扫描全部 matches 再筛选。LiveTable 与 LiveWatchList 控件各调用一次，因此即便未选择任何观察点，一次万点匹配集合渲染也遍历并复制 20000 项。新增实际父表达式/控件回归先失败：预期零整表遍历，实际 20000。

现在关闭仅看时返回原只读匹配集合，开启时遍历最多 32 个观察 ID，并在完整集合中查 membership；不遍历整表。两个调用方在仅看状态合计至多 128 次 membership 检查，无论匹配表多大。调用方只读 size/has 或投影分组，原集合不被修改。返回 Set 的内部迭代顺序可能跟随选择顺序，但实际表格和冻结仍按分组/点表顺序；反向选择 200/100 冻结输出仍为 100/200 已验证。

不改变过滤集合成员、筛选计数、点位/来源失效、冻结格式、比较规则或采集。没有新增持久化、请求、定时器或后台工作。

## 同页组合验证

现有 test-live-watch-list 从 11 扩至 14 组，本轮新增三个贴近实际入口的组合场景：

- 执行实际 LiveTable 父表达式及 LiveWatchList 控件，统计万点只读集合的迭代与 membership，验证未使用时不遍历/复制、32 点时工作量有界，集合大小保持不变。
- 用受控 hooks 运行完整实际 LiveTable 函数（行折叠子树/列控件作为叶桩，规则及列设置使用 mock），选择观察点并冻结两次，接真实比较组件；进入配置模式、修改点位草稿后取消历史切页，清单、当前快照、基线和草稿保留且不写配置。确认离开后按实际 DeviceView 条件分支卸载，返回重新挂载时清单/仅看/快照/基线为空，符合已说明的本页内存寿命。历史分支始终得到完整 40 点，历史 ps-regs-1 选择只在 mock storage 中读写，不被观察清单 100/200 污染。不是在真实浏览器里运行 App 或操作真实 storage。
- 执行实际 HistoryView 请求 effect、startHistoryQuery 与 reducer。离开历史页清理会中止信号并释放 queryTask，之后即使旧请求完成也不再更新历史状态，且不能改写重新挂载实时表的清单或冻结结果。使用受控 promise 和测试自有短计时器，无网络。

未复现新的同页状态串用问题，因此没有更改导航、草稿或历史逻辑。实时页临时观测在确认离开后丢失是既有明确约定，未虚称跨页恢复；取消导航时不丢弃。历史查询记忆与页面内观测仍相互独立。
