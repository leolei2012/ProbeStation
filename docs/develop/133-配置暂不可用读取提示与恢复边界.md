# 配置暂不可用读取提示与恢复边界

基线`7ae97f68b097330c1f3abfe0b01ac13e91757252`，初始工作区干净。本轮仅改前端设备/点表读取提示和无已选设备时的空状态，不改服务端协议、配置恢复、数据库或写入行为。

## 模拟复现

用AST抽取实际App.request及refreshDevices回调，注入返回配置隔离错误的模拟HTTP503：原分类只得到failed，缺少配置服务不可用的指导。原有LatestConfigRead已经保留旧快照且不发布空数组；本轮没有将既存快照保护称为新修复。

另抽取实际EmptyState做SSR，确认当设备清单尚未读出且读取失败时，原组件仍显示选择/新建设备的普通空状态。侧栏也无条件在devices为空时显示“暂无设备，点上方新建”，容易将未读取误解为没有配置。

两个回归分别先失败：503被分类failed而非unavailable；未核实的空状态仍渲染普通emptyHint及新建按钮。随后做最小修复。测试期间一条源码接线正则被箭头函数中的大于号干扰，已改用TypeScript AST核对真实JSX属性；该中间失败不是产品缺陷，最终目标日志为config-unavailable-target-final-2。

## 行为

- configReadFailure保留timeout优先，单独识别实际App请求适配器的`HTTP 503`错误前缀为unavailable；其他HTTP/网络/格式错误保持failed。不会从任意“503”文本或5030推断服务不可用。
- 顶部ConfigLoadNotice区分设备/点表的503，保留快照未核实、未读不等于空的说明。明确由管理员检查并确认恢复后再只读刷新；连接隔离/关闭都是可能原因，503本身不能确认隔离。刷新不解除隔离，不能用重复保存或导入恢复连接，历史写入结果仍需单独核实。
- 503提示的按钮写作“重新读取（只读）”，原回调仍仅执行设备与所选点表的GET，没有添加恢复调用、自动重试或任何写入。普通失败/超时的原按钮不变。
- 设备读取失败且无当前选中设备时，主空状态显示“设备清单尚未核实”，隐藏该处的新建设备引导；侧栏空清单同样显示未核实。成功读取空数组后清除错误，正常空状态及新建入口恢复。未改变侧栏主动新建入口的权限或服务端校验，也未实现全局禁写。

503分类依赖既有App.request的HTTP错误前缀；不扩展其协议或从响应细节猜测隔离。缺少结构化身份的旧响应只按HTTP状态解释。服务端部分受保护写接口仍将异常转为“结果待核实”的500，本轮不将其错误地描述为写前拒绝，也没有自动再次写入。

管理员可按[组合就绪契约](131-配置与采样存储组合就绪探针.md)只读核查`/ready/core`的配置及存储状态，不能用旧`/ready`或`/health`的200排除配置隔离。具体隔离及显式恢复约束见[130号](130-配置连接事务未确认隔离与显式恢复.md)；成功读取或探针ready也不能证明更早写请求的最终结果。此页不新增恢复按钮或后台操作。
