# 选点未同步配置边界与提示

## 当前事实与版本机制

基于c3f6ffe有界审查，不增加服务器接口、预检或版本基础设施。

| 路径 | 已有机制与实际边界 |
|---|---|
| 共享RegisterSelectModal | 输出Set点位ID，只调整查看范围，不写设备配置。pickerContext只比较页面传入的选项；后台变更没有进入props时，无法发现差异。 |
| 历史historyQueryPlan | contextKey和revision进入客户端请求归属key，不进入HTTP参数；revision是页面刷新代数，不是后台配置版本。 |
| GET /api/data/object/series | registerCurve按请求时cfg读取的设备/组/点位规划，store按这份来源解码。旧点位ID仍存在时不会与页面旧定义比较，也没有条件版本回执。 |
| GET /api/data/object/page | 返回原始记录，由页面按已加载定义解码；和服务端解码曲线路径不同，不能把一种错配结果泛化到所有历史读取。 |
| 配置编辑写入 | 分组settings使用事务内expectedRevision，点位等写入有expected基线。它们保护对应写操作，不会自动绑定历史查询或纯本地选点。 |
| 导出 | 实际旧Sink/GET没有expected配置条件，已有弹窗明确按后台定义生成。69–74号等审计/保留组件不是已接入的保护；本轮不扩展它们。 |

ConfigStore的历史配置snapshot.version是结构版本，configurationScope是打开周期身份，不是逐编辑内容版本；不能借用作为选点/历史请求的条件保证。通知和页面刷新有价值，但未收到通知/尚未刷新时仍存在间隙。刷新前预检再调用旧读取，仍无法把检查和消费绑定为同一操作，因此不实施这种伪锁定。

## 合成复现与保守提示

1. 实际选点组件保持旧页面props，只改独立合成后台定义的从站；草稿仍可输出旧点位ID。这是已知客户端能力边界，不是保护通过。
2. 复用实际registerCurve的Fastify.inject和模拟provider：后台源1→2后，用同一个旧plan URL再次查询，仍200、值由10变200；客户端用旧plan接收后contextChanged=false。无配置ETag/Last-Modified回执；contextKey/revision仍未传给后台。脚本明确打印`HISTORY UNSEEN CONFIG LIMIT`，退出成功表示边界被验证，绝不表示该竞态已解决。
3. 扩充选点弹窗中英文说明，并纳入对话框aria-describedby：仅使用本页已加载定义，不锁定后台；历史查询/导出前刷新并核对来源，刷新后后台仍可能再次变化。未自动重读、重试、写入或阻止原有本地选择。

当前保护仍保留：页面实际收到选项变化后，旧弹窗失效；等价刷新/排序不误拦截；取消不应用。实时曲线和观察清单还各自验证原始来源，不应因历史曲线的这个复现就宣称所有实时值会跨从站混显。新提示不是风险消除，也不保证刷新可以消除并发变化。
