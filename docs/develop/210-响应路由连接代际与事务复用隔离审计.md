# 响应路由、连接代际与事务复用隔离审计

> 状态：仅隔离审计与测试，2026-11-11；基于d141e8b。没有生产响应路由、驱动patch或GUI解禁。反例不表示已观察到现场故障。

## 最有价值的结论

- TCP保持同一客户端可区分相邻事务，但并非永远唯一：新客户端重新从事务号1开始；本轮通过65536次公开SDK请求确认4.0.10的事务号回绕后也能再次接受旧同号响应。不能用SDK Promise成功或事务号相同证明属于当前操作。
- RTU已有从站过滤。最初仅读rtu-client-request-handler会漏看modbus-client._onData中的unitId比较；实际完整SDK拒绝让unit7响应完成unit9请求，随后unit9响应正常完成。无需重复增加这层已有保护。CRC与unit相同仍不能区分同一从站的迟到旧响应；重建SDK客户端不会在RTU字节中产生新事务标识。
- 将接收回调绑定可信的真实连接拥有者/代际，可丢弃旧连接迟到回调并隔离旧解析器残片。仅新建SDK而继续使用相同传输，不应被当作新连接；若桥接层把旧字节误转发到新传输，即使代际过滤器本身正确，也无法识别这些字节的来源。
- SDK收到不同TCP事务号会OutOfSync拒绝，但本轮当前请求的模拟字节已提交。该错误不是“未发送”回执；仍需按未知结果处理，不自动重放。单位/CRC/长度/地址/FC06回显值等完整响应检查是必要条件，同来源且字节相同的旧响应仍有歧义。

| 桥接错误地把旧TCP字节作为新source数据 | 代际过滤器无法区分、SDK仍接受，确认来源标记必须由真实传输拥有者保证 |

GenerationBridge仅是脚本内的接收关系模型，不导出、不绑定真实net.Socket/SerialPort。source是测试提供的可信对象，不是网络帧携带的可验证凭据；它没有实现生产监听器装配、队列背压、连接认证、超时恢复或全协议解析。不能复制到产品后就宣称完成连接隔离。

## 下一步边界与失败关闭建议

1. TCP若继续原型，先用真实连接拥有者抽象保证接收、发送、销毁与不可复用的连接代际一起绑定。更换SDK必须伴随明确的真实连接生命周期，不能仅重置客户端计数器；事务号接近复用时应停止新条件请求，不能等重复后再猜回包。何时安全换连接及处理已接纳操作还须模拟证明。
2. 绑定操作ID和完整预期响应；维护发送接纳事实，OutOfSync、丢回执、解析异常均不得被改成可盲重试的未发送。超时/歧义后保持通道隔离，直到可以证明旧拥有者不会再提交、旧响应不会进入新接收路径；本轮没有实现恢复或数值写回滚。
3. RTU在允许任意迟到/重复的模型下，同unit、同FC及相同响应字节无法仅靠CRC、地址或本地时间证明所属操作。固定静默等待、清空浏览器缓存或只重建客户端均不足以提供该证明；不猜测现场延迟上限。继续保持条件写能力不可用，直到另有可验证的协议关联或经审查的物理/时序前提。
4. 所有写入入口、共享RTU、OTA/raw socket、重复端点与跨进程拥有者仍须纳入208/209号约束。可信配置版本不能替代可信响应来源。旧API仍未纳入新保护，本轮不改变它们；GUI保持禁写。
