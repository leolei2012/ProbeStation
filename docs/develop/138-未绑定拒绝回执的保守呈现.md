# 未绑定拒绝回执的保守呈现

基线 `6de91ede7cccfb2664a17280ceed90151eede4b4`，初始工作区干净。本轮仅修改已有配置写入回执的前端呈现与对应回归，不改变服务端协议、状态码、旧接口、默认采集、连接恢复或重试行为。

## 问题与处理

六条写入路径使用同一类 v1 写前隔离回执：设备编辑、点位编辑、新建设备、新建分组、设备删除和 XLSX 替换导入。合法回执没有绑定请求；当代理把已经成功提交的响应替换为先前合法拒绝内容，客户端无法确认它描述的是当前请求。严格结构校验只能排除矛盾字段，不能证明来源或阻止重放。

之前直接显示“本次保存/创建/删除未执行”，导入还会显示零写入报告及确定拒绝标题。现在完整合法回执只产生本地提示：“后台报告写入（或创建）受阻；回执未绑定请求，本次实际结果待核实。请管理员核查配置，勿直接重复操作。”分组英文界面及删除英文提示使用相同含义。导入不再把无请求身份的零计数回执当作实际导入统计；显示未知结果提示，不显示该回执的计数或确定未执行详情，不触发成功刷新。普通成功报告、校验失败报告、旧错误和不完整/矛盾回执的处理保持不变。

草稿保留与删除后的只读记录继续沿用既有机制；未增加持久保存承诺，没有自动重试、取消、重开连接或回滚。服务端拒绝对象未变，旧前端仍可能保留旧措辞，升级时应配套更新前端。新前端可消费旧服务响应；普通无标记错误仍按原有契约处理。

## 边界

这是用户表述的修复，不是重放检测。完整伪造/重放与真实回执仍无法从当前协议区分；没有新增请求 ID、签名、鉴别、幂等性或真实性保证。任意代理还可伪造其他成功/普通错误，本轮没有解决所有网络信任问题。管理员核查不保证能自动归因于某一请求。

未验收真实浏览器、真实 HTTP 代理/套接字、代理自动重试或真实设备。全部检查使用已有隔离目录与合成数据，不打开真实库、不覆盖在用 dist，不推送、部署或重启采集服务。
