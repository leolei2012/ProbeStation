# 历史导航跨标签生命周期回归

## 发现与复现

基于干净的 `1767a47b985186815485f46ad2feb076c75c8223` 继续审查。检查了点位草稿关闭、设置/日志清理、配置备份结果、历史选点/导航/暂存与导出的调用关系，选择已证明的导航生命周期问题；不是逐条审计全部本地历史提交。保留现有提交，不启动主应用或访问真实数据。

此前 HistoryNavigation 对同一实例保证导航只消费一次，普通重渲染的回归也通过。但实例放在 HistoryView 的useRef内，而DeviceView仅在tab===2时挂载HistoryView。App仍保留原目标与token，所以切到实时再回历史会创建新导航实例，将已消费目标当成新事件。用户在第一次定位后手动选了另一点位或切到物理值，返回历史时又会被旧目标改成原点位、原始值及旧范围。

修改前新增离线组合测试，读取实际App源码，只执行经过审查的导航分配、参数表达式、consume/cancel和TabBar回调。复现得到第二次range、raw和点位11的完整动作，而预期为null；断言失败。没有复制生产导航状态机，也未挂载整个App、发请求或操作设备。此前仅复用同一HistoryNavigation实例的单元测试没有覆盖真实子组件卸载关系。

## 修复与边界

将既有HistoryNavigation实例移到DeviceView，与现有本页暂存查询的所有者处于相同生命周期，通过prop传入HistoryView，不改状态机协议或建立全局缓存。当前设备页内切标签不会遗忘已消费状态；明确再次点击生成新token仍可重新定位，切换到其他设备后是独立实例。

手动切到其他标签时取消尚未完成的点位聚焦。这样离开历史等待定义加载后，返回时不会把旧点位应用到另一个默认区间；不依赖卸载effect取消，避免将React临时效果清理当成用户离开。原手动选点、查询、取消和恢复暂存条件的cancelPending仍调用同一所有者。

这不是自动保存分析状态：HistoryView原有区间、预设、表格/图表及分页重开默认值保持不变；持久化的选点/数值模式不再被旧目标再次覆盖。需要保留精确查询条件时继续用现有“本页暂存查询”。整个DeviceView卸载、刷新页面或更换设备不保留本轮导航日志，未扩大到跨页面/浏览器的持久化。未修改采集、告警阈值、历史解码、身份验证或导出协议。
