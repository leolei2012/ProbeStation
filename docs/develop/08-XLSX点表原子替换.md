# XLSX点表原子替换

2026-11-06，基线3291610。只用内存配置库和内存工作簿验收，不启动应用、不导入真实文件或访问真实数据库，不部署或操作设备。

## 已确认的问题

全量点表导入入口是Sink.importPointBook，由Web/REST的points/book和MCP import_points_xlsx共用。旧实现只在删除前校验告警页，随后删除现有组，再创建新组并逐行解析点位。后续行地址或显示精度非法时，仍返回部分计数，原分组、点位和告警已经丢失；数据库写入异常也没有整次回滚。逐行通知还会让监听者看到中间配置。

新回归先在旧代码失败：合成工作簿的第二点位J6=9（显示小数位数只允许0–8），第一行合法、告警页合法，导入后原配置快照却改变。全程:memory:，没有读取用户点表。

## 本轮范围

本轮先保证整次替换/追加的原子性，保留原有成功导入的解析规则；不是完整的XLSX字段保真改造，也不是备份格式迁移。

- 工作簿载入及既有告警预检仍在写入前执行。ConfigStore.applyPointBookImport承接同步的XLSX创建回调，在BEGIN IMMEDIATE内完成旧组删除、新组/点位/告警创建及范围更新。解析器不得在此同步回调中await、调用硬件或自行提交。
- 既有解析器发现任何行错误，整次ROLLBACK；groups/registers均返回0，errors保留行号原因。不会再保留有效行的部分结果。replace=false追加也采用同一事务，原来的配置ID保留。
- 没有分组页的工作簿不能用来清空设备，返回错误且保留原配置。空页、无可解析点行及原告警错误同样不会留下半次导入。
- 删除、建组、建点、建告警、范围更新或提交失败均回滚并抛出异常，不伪装成成功报告。BEGIN失败没有写入；回滚本身失败明确抛出“结果不确定，勿自动重试”。
- 事务内抑制逐行config/changed，成功后只有一次scope=point-book-import/id=目标设备的通知，监听者看到完整配置。错误返回不通知；现有消费者监听所有scope，保持兼容。
- 已提交后的同步通知或日志写入失败通过warnings报告，不把完成的替换变成可无条件重试的异常。MCP外层日志失败也保留原报告。此类警告不代表数据库已经回滚。

返回保留groups/registers/errors，增量增加warnings。REST原有行错误200+errors结构保持不变，调用方必须检查errors；异常走原错误通道。MCP需检查errors和warnings。现有Web上传处理会检查errors并刷新数据，本轮没有新增warnings展示或候选UI，未做页面视觉验收。

设备连接参数、其他设备配置、历史记录不参与事务替换；成功全量导入仍会重建目标组、点位和告警ID。真实配置需按既有用户授权流程处理，本轮没有实际导入。

## 明确未完成

只读代码检查发现，当前全量XLSX解析器仍有独立字段问题：忽略分组从站头、忽略点位quantity列、系数0经旧默认表达式变成1、组跨度按点位起址而非完整dtype宽度重算；相同/清洗后冲突的sheet名称导出也需另查。没有在本轮顺手改变这些行为，以免在缺少回归和格式决策时扩大范围；下一阶段应逐项离线复现、修复保真和完整校验，再宣称全量XLSX可以无损往返。当前JSON配置备份的quantity独立元数据契约不受影响。

因此，本轮只宣称“已有校验报告失败或写入失败时不留下部分替换”，不能把errors为空当作所有字段/硬件来源已验证。本轮没有新增依赖、UI改动、实机/真实文件验证、生产迁移、服务启动/重启或推送。
