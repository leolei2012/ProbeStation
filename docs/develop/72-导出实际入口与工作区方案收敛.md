# 导出实际入口与工作区方案收敛

## 结论

基于干净的`b8d3aed9e359d13f2f5cd331447589cf0a32a56e`重新审查，**不能把现有Workspace配对直接接入实际导出并称为安全完成**。该服务没有加载，配对启动时刻意不可用，必须成功管理一次两库切换后才可获取。将它设为现有GET/Sink的必需条件会拒绝当前正常导出；为此恢复已移除的工作区或首次请求盲目配对，都不是最小兼容改动。

本轮停止新增运行时能力：未改apps、packages或真实数据库，没有恢复Workspace或把它注册进主程序。仅增加可重复的实际入口审计与修正过时文档。既有提交保留，但其局限明确如下。

## 可控实际链路审计

运行`npm run audit:export-entry`。仅接受固定`--memory`，拒绝地址和文件库路径。静态AST检查主入口无workspace导入/注册及config→store→sink顺序；随后只执行这三个实际Cordis插件入口，数据库路径均`:memory:`、定时器为0。使用真实Sink、真实SQLite/DuckDB及共享Fastify路由inject，无listen、主程序、poller、驱动、slave、MCP或模型。

实际预期结果：

1. 无workspace provider，旧CSV和XLSX均HTTP200、带附件，值为10，证明当前导出不依赖它。

4. 独立直接调用配置快照、store句柄查询与后置元数据核对，可以读取当前源2的200，说明组件可复用；**未据此声明两库启动已配对，也未证明预检绑定实际消费**。

## 前几步代码价值与限制

- 69号配置只读事务快照：可直接复用于单目录导出的同次collect，避免设备/分组/点位逐次读取成不同快照；scope只表明打开周期，不是内容版本。
- 70号store读取句柄：可固定异步查询的连接代际，拒绝迟到或跨重开的结果；不能决定它与哪个配置库配对，也不能检测配置单独重开。
- 71号Workspace配对：只在显式注册该保留服务且成功管理切换时有效。当前主入口不使用，属于有测试的保留代码，不计为用户已获得的导出保护。本轮不再扩大它，也不删除/回滚既有提交。
- 67号前端保护：仍有实际用途，可以拒绝已经同步到页面的变化；后台尚未同步的变化仍能绕过它。其他批次/来源、限额及列名保护保留，不与版本保护混为一谈。

## 最小可行后续方案与实施门槛

方向应回到**单数据目录实际装配点和Sink**，无需恢复Workspace：

1. 先在可控真实插件链路中验证一次单目录启动拥有关系：由明确拥有config/store打开动作的装配流程，在两者成功就绪后确认原实例和打开周期。不能在第一个导出请求里仅凭“都ready”或相同配置值推断配对；任一独立reopen/provider替换后需拒绝，不自动重配。现有句柄尚无公开等待初始化契约，此处须先设计，不访问私有ready来实现生产接入。
2. 为实际Sink增加可选条件导出路径，保持旧签名/GET兼容：在同一次collect读取69号快照、核对expected定义及启动配对，然后仅消费这份定义和70号句柄读取数据。附件生成后再次核对周期，过期不回附件。不能“预检→调用会重读配置的旧export方法”。普通编辑不变scope，必须另有规范化内容条件；不能将scope当revision。
3. 用实际共享路由+真实内存库先证明CSV/XLSX：后台改来源/删点/改类型、比较后I/O等待、配置单独重开、store单独重开、初始化/部分失败、XLSX生成期间失效均无错误附件；正常值/毫秒/批次状态/20万原始行边界不变；旧客户端仍可按旧契约工作。版本化preview/checked请求需能力及成功回执，旧后端忽略条件时不可冒充已校验。
4. 上述证明后再最小注册新只读入口，并接前端/MCP。隔离测试版当前禁用非GET/HEAD，若新契约需只读POST，只精确放行新增路由；不打开全部写方法。未完成这些步骤前，不宣称完整服务端版本保护或自动PASS/FAIL。

这是一份实施方案，不是已接入能力。本轮停在安全边界，没有权限审批阻塞；未实施是缺少实际单目录拥有/版本消费契约和其端到端证明，不能用新增未使用服务替代。
