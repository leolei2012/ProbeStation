# 设备状态提醒读取与恢复

## 问题与范围

基于干净的 `9b8be5da62eece87cf42761b504543c4c4f9ecb4` 继续，保留其全局保留策略修复。原 DeviceIssues effect 在请求 finally 才安排10秒后的下一次读取，没有读取超时；永不结束的GET会让整条轮询链永久停止。原 effect 直接接收 result.issues，合法JSON中的 null 会进入状态，下一次访问 length 抛错。已在修改前提取实际旧 effect，用假API/计时器离线复现：挂起没有任何后续定时器，null导致 TypeError。未访问真实服务。

本轮只改顶部提醒的只读客户端与展示。审查 `GET /api/ai/issues`：从当前配置、热缓存与现有诊断getter汇总暂停、断线、缺数据/质量及过旧提醒，返回 issues 和 checkedAt；此路由不发Modbus请求、不连接/重连、不写配置、不调用模型。使用 Fastify inject 实际路由和内存依赖回归，不监听HTTP端口；只在新建空临时目录解析缺省助手设置。没有启动主应用，也未调用可能有同步副作用的其他设备状态路由。

## 行为

独立 DeviceIssuesRead 复用只读取消与超时工具，固定读取同源 `/api/ai/issues`，保留既有 `X-ProbeStation-AI: 1` 访问头，禁缓存。同步合并在途自动/手动读取，默认10秒超时并结束等待；不依赖服务器一定响应取消。每次自动读取完成后等10秒安排下一轮，沿用旧刷新间隔；挂起超时情况下从本轮开始到下一轮约20秒。手动核对可提前恢复。卸载撤销只读等待并停止后续调度，迟到成功/失败/finally不得覆盖新状态或解锁新的在途读取。页面后台计时器可能被浏览器节流，不保证实时告警时延。

先完整验证响应再接受：issues必须是数组，每项的设备ID、视图、文本及可选点位/时间区间/模式需合法；拒绝整个异常响应，不悄悄丢坏项。保留原顺序、同一设备的多条提醒和毫秒关联区间，冻结投影副本；不复制额外字段或后端导航token。App仍生成自己的导航序号，原 DataTarget 类型通过原模块重导出。旧响应缺 checkedAt 允许查看，明确显示未提供；不拿本页接收时间冒充后端核对时间。

初次等待、成功空汇总、异常/失败与上次快照分开展示。失败或重读中保留已有提醒，明确当前状态未核实；旧按钮标为上次关联位置，只有用户点击才导航，不自动执行恢复。保留原提醒列表可收起的展示方式，汇总数量与读取状态在外部可见，展开后查看提醒、时间与范围。空汇总不意味着所有设备健康或测试PASS。中英提示、长标签换行、刷新禁用及读数期间的紧凑状态区一并处理；原后台规则、阈值、采集行为不改。
