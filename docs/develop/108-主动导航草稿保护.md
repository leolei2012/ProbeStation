# 主动导航草稿保护

后续109号实现接受清单移除后的只读本页留存，并停用被留存旧编辑器的新保存；下述“后台仍丢稿”和“不复制字段”描述本阶段审计时状态，不代表最新代码。未增加持久保存或自动恢复。

## 范围

基线788dd23f36fa5d4bb2b195be619a3e6ed1e22191，开始时工作区干净，无AGENTS.md和.agents/skills。107号审计证明整体DeviceView卸载绕过局部关闭确认；本轮只实施第一阶段主动导航保护，不把后台移除或浏览器刷新伪称已解决。

覆盖DeviceView内部DeviceModal和LiveTable内部PointSettingsEditor。新增DraftNavigation为App当前生命周期持有的轻量登记器，记录owner设备ID、编辑器范围和最新dirty/busy读取回调，不复制草稿字段、不读写localStorage/配置库/设备。组件通过可选draftScope报告现有原始输入dirty判断及同步保存锁；关闭/保存/卸载后注销，独立编辑器/预览不传新props时保留原用法。

Root新建设备弹窗不随这些设备/页面导航卸载，因此不登记为设备视图草稿，不为无关导航增加确认。GroupModal、告警、写值、助手输入和其他表单不在此次两类编辑器保护承诺中；业务写入/条件保存API及原草稿关闭状态机不改。

## 导航与确认

App在设备按钮、统一navigateData（助手/提醒/告警引用）、全局数据库/监控切换的第一条状态变化之前判断范围。跨设备或离开监控会卸载整个DeviceView，核对该owner所有登记；相同设备的历史/主站通信诊断只卸载实时表格，核对live范围；本机从站的diagnostics引用原逻辑映射到实时tab0，不误拦截。相同设备/相同全局页面和live引用不卸载编辑器，直接通过。当前已不是监控视图或当前设备已不在列表时，根本没有该DeviceView可供卸载，直接放行，避免迟到清理的登记误拦截后续导航；这不会保存或恢复后台移除时丢失的草稿。

DeviceView的标签切换只在当前tab0转到其他标签时核对live范围，先拒绝再处理setTab和historyNavigation.cancelPending。设备编辑器仍在相同DeviceView中，不会因此多问。Root引用已经在意图入口确认，应用target的effect不再确认，避免同一操作问两遍。

| 状态 | 行为 |
| --- | --- |
| 无登记、干净、完全撤回输入 | 直接按原流程导航，无确认 |
| 不属于此次卸载范围或其他owner | 不读取/不阻断，无确认 |
| 一或多个受影响编辑器有修改 | 合并一次原生确认；取消保留输入和当前页面 |
| 取消 | selectedId/view/dataTarget/token、移动侧栏、tab和待处理历史意图均不改变 |
| 明确继续 | 原导航执行，不自动保存、撤销或重试 |
| 受影响编辑器保存中 | 不导航、不确认丢弃，提示等待/核对；不取消原请求 |
| 读取状态或确认界面异常 | 保守拒绝并提示状态待核实，无导航副作用 |

不缓存放弃许可。取消后新的显式请求会重新核对，避免前次许可被未发生的导航或后续编辑错误复用；“一次确认”是单个意图合并所有受影响编辑器，且不在Root/目标effect重复询问，并不抹掉用户再次点击的含义。

dirty沿用各编辑器的原始文本/枚举比较，登记读取busy来自同步ref锁，因此保存开始但React尚未重渲染时也不能被主动导航卸载。局部确认/继续编辑仍按原PointDraftCloseGuard运行；明确放弃或点位保存成功后closed状态不会再次报dirty。设备保存成功仍由原父回调关闭，清理登记后后续导航无陈旧拦截。未知保存结果仍用原错误/待核实语义，导航不推断后台是否已保存，也不重试请求。
