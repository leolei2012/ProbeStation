# 历史空选择与查询取消

状态：已实现，最终完整离线检查通过；浏览器交互验收未完成。日期：2026-11-06。

## 已验证的问题

历史页原查询effect只检查时间有效性，清空选择后仍生成 `register_ids=` 请求。表格分页接口不按该参数筛选，会继续读取设备时间戳/原始数据；原空状态还可能先显示查询中，完成后误显示无历史数据而不是未选点位。

在保留原请求条件/参数的查询计划中，空选择回归先得到完整page URL而失败，再增加空选择短路后通过。原250ms防抖/HTTP请求的生命周期统一为可取消任务，便于测试取消和竞态。

## 本轮行为

- 空选择或无效输入不创建定时查询、不发历史请求；清空选择时释放旧任务并清除旧数据/错误/质量摘要。表格和曲线直接显示已有的“未选择任何寄存器”，查询/导出按钮禁用；重新选点自动查询。
- 任务同时管理防抖和HTTP等待。防抖期取消不再进入fetch；活动请求取消会传递AbortSignal。卸载/切换时静默清理，忽略迟到响应，包括同一URL刷新或清空后重新选择。
- 结果身份包含设备、精确时间、模式、页码及规范化点位集合；响应归属于发起它的请求，避免切换点位/页码后短暂用旧结果当成当前结果。
- 保留250ms防抖、30秒超时、原接口参数、分页大小及降采样上限；不改变采样/告警/存储或已选非空时的后端读取语义。曲线组件在空选择时保留挂载及缩放状态。
- 请求已进入后端后，客户端取消等待不等于强制中断数据库SQL；本轮未新增表格服务端中断接口，也未将非空表格查询改为按已选点位分页。
