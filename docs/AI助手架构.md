# 内置 AI 助手

## 设置和聊天

接口配置统一放在左下角「设置 → AI 助手」。聊天内保留模型与推理等级选择，提供商管理入口统一在设置中。保存后刷新聊天的模型信息；正在运行的请求继续使用启动时的配置，新消息使用新配置。

- `apps/web/src/assistant-client.ts`：统一 API 请求和配置类型。
- `apps/web/src/AssistantSettings.tsx`：配置加载、保存、错误状态；密钥不回显、不进入浏览器存储。
- `apps/web/src/AssistantPanel.tsx`：会话生命周期、轮询、发送/停止、提案确认、窗口展开和滚动跟随。
- `apps/web/src/AssistantMessage.tsx`：消息展示和工具记录。回答使用 react-markdown + remark-gfm；不执行 HTML，不自动加载模型输出中的远程图片。
- `packages/api/src/assistant.ts`：服务端会话、模型调用、白名单工具与提案执行。模型不能自行确认修改。

聊天支持展开/还原、Enter 发送、Shift+Enter 换行、中文输入法组合输入保护。向上阅读时不强制滚到末尾，可点「回到最新消息」。工具原始结果默认折叠。

## DSH 参考边界

本次查阅 [DeepSeek Harness 官方仓库](https://github.com/deepseek-ai/deepseek-harness)，参考版本 `5badb15009ae1756c3afe0ae0cef1faafc290ccc`，重点是 `packages/client/ui-chat` 中的 ChatView、AssistantMarkdown、use-chat-scroll 和 ui-chat/package.json。

DSH 的聊天视图通过会话控制器、conversation 节点、renderer、settings、workspace 等插件协作，并非一个可独立复制的 React 组件。本项目参照其设置/会话/消息展示分层、Markdown 展示、工具折叠和阅读位置保护思路，使用现有 API 实现适配；没有复制 DSH 源码，也没有引入完整 DSH 运行时。下载到 reference/ 的源码仅供本地参考，不参与构建。

模型回答采用流式接收，会话在本地服务端持久化，按设备恢复；不包含 DSH 多会话管理和 agent 插件系统。后续如迁移完整 DSH，需另做会话协议及设备工具审批的适配，不能直接开放其通用执行工具来替代当前白名单。

## 多提供商与模型选择

`assistant-providers.ts` 直接复用 DSH llm-pi-ai 同一底层依赖 `@earendil-works/pi-ai` 0.87.x 的 builtinModels、streamSimple 和 getSupportedThinkingLevels。未复制其 Cordis 适配器或 UI 源码，仍保留 ProbeStation 白名单工具、只读执行保护和人工确认。

已接入 17 个 API Key 提供商，包括 DeepSeek、MiniMax/中国区、Anthropic、Google、OpenAI、Moonshot/中国区等。未接入 OAuth、Bedrock、Azure、Vertex 等特殊认证流程。没有读取宿主机环境中的模型密钥。内置目录可能落后于服务商实时发布；目录外可暂用自定义 Chat Completions。

配置文件兼容旧单提供商格式，新增 provider 与 profiles 字典，各提供商密钥分开保存。模型请求捕获配置快照，运行中修改设置不会改变该轮请求。修改端点不会沿用该提供商旧端点密钥。模型接口的原生 assistant 元数据保存在服务端会话中，用于工具关联、推理签名等回放；不返回浏览器。跨提供商适配由 pi-ai 处理，切换模型重置推理等级。

设置采用已配置提供商卡片与第三方/自定义分区；聊天输入框左侧添加附件、右侧模型与推理选择浮层，目录支持搜索。只读问答在工具定义与执行层都禁止创建修改提案。推理等级由内置目录过滤；自定义接口仅在手工启用 reasoning_effort 时显示协议候选值，不保证每种模型都支持。

模型增量文本在服务端内存中累积，浏览器通过现有 700 ms 轮询渐进显示，同时显示当前查询工具；最终答案与原生工具回放元数据一并保存。自定义 Chat Completions 支持 SSE 分片和工具参数拼接，也兼容返回完整 JSON 的接口。中断流不能作为完成答案写入上下文。

验证：`scripts/test-assistant-providers.ts` 使用模拟 SSE 验证 DeepSeek、Anthropic、MiniMax 中国区原生协议的工具调用和回放；`scripts/test-assistant.ts` 验证提供商配置隔离及原有工具权限。测试不使用真实密钥、不接触硬件。

运行环境现要求 Node.js >= 22.19.0，部署前运行 npm install。

## 附件和统一助手

界面不再区分只读问答与配置助手，统一查询/分析和提出修改；修改仍须人工确认。后端保留 read 参数供已有客户端兼容。加号用于添加附件，不提供新会话按钮。

每条消息最多 4 个附件，总计 6 MB；PNG/JPEG/WebP 图片每个 2 MB，UTF-8 文本/CSV/JSON/日志/代码每个 20 KB。暂不支持 PDF、Office、压缩包。服务端校验编码、类型与大小，图片检查内置模型视觉能力；自定义接口需要所选模型支持图像。文本作为带文件名的数据上下文传入，图片使用原生图像内容块。已发送附件随上下文保存在本机服务端 ai-sessions 文件中，不作为指令执行；历史界面只回传文件名和大小。自动/手动压缩会移除较早图片原文，只保留文字结论。整个会话对图像编码累计设 8 MB 上限，对文本继续执行上下文限制。

附件只在发送时随消息上传到本地后端并交给所选模型服务；选择文件本身不发送。发送请求被拒绝时保留待发附件；后端接收消息后清除待发列表，后续模型执行失败仍可在同一会话继续询问。

## /compact 命令

输入框输入 `/` 显示命令菜单，选择 `/compact` 后发送。参考 DSH command-compact 与 compaction-basic 的按需摘要语义，适配当前会话 API；并非直接加载 DSH 插件。使用当前提供商与模型，无工具调用，最多等待 120 秒；停止/失败不改上下文。保留系统约束和最近完整用户轮次，较早消息变成摘要，界面记录保留。摘要作为用户级参考数据，不能提高指令权限。较早图片不发给摘要器，只保留历史文字结论。减少比例按请求数据字符数估算，不是假称精确 token 数。

上下文管理以模型窗口为依据：目录模型使用 contextWindow，自定义 API 可以在设置中填写可选 contextWindow（tokens），留空时不设置固定文本触发线，由 API 决定可接收的容量，仍支持手动压缩。已移除 80,000 字符、80 条消息、150,000/180,000 字符阻断及输入框 8,000 字符限制；工具结果不再按固定字符长度截断，查询本身的点数/分页边界仍保留。

回复预留 min(8192, contextWindow / 4) tokens，在剩余输入空间的约 90% 触发摘要。例如 204,800 窗口预留 8,192，约 176,947 个估算输入 tokens 时开始压缩。估算按 ASCII 文本约四字符一 token、非 ASCII 约 1.5 token/字符，加消息结构、工具定义和图片开销；剔除重复的 _native 元数据，不把图片 base64 当作文本 tokens。不是精确分词，实际容量由 API 判断。

工具调用之间再次检查已知容量；需要压缩时保留当前完整工具链及最新用户轮次，避免孤立的调用/结果。图片累计编码约 6 MB 时也会尝试压缩较早图片，这是请求体大小保护。首次大附件没有旧历史时不触发摘要。压缩失败保留上下文并显示错误。附件上传大小、查询分页、最多工具轮次、请求超时和单次输出限制仍独立存在。


## 聊天恢复、数据来源和配置撤销

- 会话原子写入 `data/ai-sessions/<UUID>.json`（跟随实际 dataDir）。浏览器仅保存按设备划分的会话 ID，不保存密钥；切换设备、刷新和服务重启后可恢复。关闭面板或切换设备不终止后端任务；需要停止时点击停止按钮。服务重启中断的任务不会自动重跑，未确认提案会取消。
- 聊天文件包含历史对话、附件和工具查询结果，请随本地数据目录一起管理和备份。浏览器清除站点数据或换浏览器后不会自动发现旧会话；跨电脑使用需继续访问同一服务端并保留会话标识，不提供云同步。
- `POST /api/ai/test` 使用编辑中的 API 配置发送简短测试消息，不保存配置、不调用设备工具；区分鉴权、模型/地址、额度、服务故障与超时。
- `GET /api/ai/issues` 每 10 秒由界面刷新，汇总暂停、离线、未采集、多字数据不完整、过期与质量异常；只读取缓存，不额外采集设备。过期容差与观测表采用同一组轮询周期估算。
- 查询来源由服务端根据实际成功执行的工具生成，绑定当前用户轮次；点击历史来源会选择设备、点位及原查询时间范围。实时来源打开当前观测页，历史曲线可在原范围内继续缩放。来源表示工具查询出处，不保证模型的每一句结论正确。
- 配置卡片显示设备/分组/点位、字段、前后值和读回状态。`POST /api/ai/sessions/:id/proposals/:proposal/undo` 仅允许撤销已成功应用的修改；当前字段必须仍等于修改后的值，才恢复旧值并再次读回。避免覆盖他人后来修改的数据，重复撤销返回冲突。

新增验证：`scripts/test-assistant-workflow.ts` 覆盖分片输出、工具参数拼接、流中断、跨实例恢复、自动摘要、来源、状态提醒、连接错误分类及撤销冲突。测试使用临时数据目录和模拟模型，不调用真实硬件或付费模型。
