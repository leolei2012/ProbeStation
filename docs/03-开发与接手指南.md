---

## 1. 这是什么

ProbeStation（砺台）：面向嵌入式设备的**观测与测试平台**。用 DeepSeek Harness（DSH）「一切皆插件」的理念，
用 TypeScript + Cordis 全量重写了旧的 Python FastAPI Monitor。

一句话：**监控是数据底座（Modbus 采集 + 时序存储 + 仪表盘），AI 测试是大脑（通过 MCP 让 agent 读写设备）。**

## 4. 架构总览

**插件化范式（Cordis 五理念）**，每个插件就是一个「服务」：

1. 插件 = 实现 Service 的对象（`apply(ctx, config)`）。
2. context 是服务仓库：服务挂 `ctx.<key>`（`ctx.modbus`、`ctx.store`…），按 key 找，不 import 实现。
3. `inject` 声明依赖：加载顺序由依赖决定。
4. 类型化事件：`emit / waterfall / parallel / serial`。
5. 注册都是可逆 effect（`ctx.effect()` / `ctx.on()`）。

**数据流：**

```
真机/从站 ──Modbus──▶ modbus ──▶ poller ──emit(poller/result)──▶ api(WS) ──▶ 前端
                              │
                              ├─▶ store(热缓冲+DuckDB) ──▶ api(REST latest/query)
                              │                                └─▶ sink(导出)
                              └─▶ rule(评估) ──emit(rule/trigger)──▶ api(WS) + config.log

MCP 客户端(DSH/agent) ──HTTP──▶ mcp(8081) ──▶ config/store/poller（读快照/查历史/写寄存器）
```

## 5. 插件与服务一览（12 个）

| 插件 | 提供的 `ctx.*` | 端口/能力 | 注入 |
|---|---|---|---|
| core | — | 全局配置 schema（占位） | — |
| config | `ctx.config` | 元数据 CRUD + 规则 + 日志（node:sqlite） | — |
| modbus | `ctx.modbus` | `createDriver(transport)` → ModbusDriver（TCP 的 `JsmodbusDriver` / RTU 的 `SerialDriver`，读/写） | — |
| poller | `ctx.poller` | `startAll/stopAll/pollOnce/write`（TCP 并行；RTU 同串口串行排队，半双工） | config, modbus, store |
| store | `ctx.store` | `write/flush/getLatest/query/queryObject` | — |
| sink | `ctx.sink` | `exportCsv/exportXlsx` | config, store |
| rule | `ctx.rule` | 订阅 poller/result → rule/trigger | config |
| api | `ctx.api` | Fastify：REST+WS+静态（8080） | config, store, poller, sink, importer, workspace |
| slave | `ctx.slave` | Modbus 从站（8502） | — |
| importer | `ctx.importer` | `import()`（MBS/MBP 解析） | config |
| mcp | `ctx.mcp` | MCP 服务器（8081）34 个工具（设备创建/读写/查/快照/健康/告警 + CRUD + 采样/保留 + 录制 + 点表xlsx导入导出 + OTA），每会话独立 McpServer+transport | config, store, poller, ota, sink |
| ota | `ctx.ota` | 固件升级（0x41 状态机 + 固件上传/落盘 + 断点续传 + 暂停恢复轮询） | config, poller, workspace |
| workspace | `ctx.workspace` | 工作区管理（一个文件夹=一个工作区） | config, store, poller |

`core/src/protocol.ts` 是主站/从站共用的协议契约：统一四类数据区、FC01/02/03/04/05/06/15/16、请求数量与地址边界、广播规则、执行结果和结构化错误。`ModbusDriver.execute()` 已作为兼容入口接入现有驱动；当前通过该入口实际执行 FC03/04/06/16，FC01/02/05/15 将按 `docs/product/09-Modbus主从站完整化计划.md` 逐项落地，未实现时明确返回 `unsupported_function`。

**关键事件**：`poller/result`（轮询结果）、`rule/trigger`（告警命中）、`poller/group-error`/`poller/group-ok`（按组轮询故障/恢复）、`workspace/changed`（切换工作区）。事件是**全局分发**的（兄弟插件 emit/on 互达）。

## 6. 插件开发范式（怎么加一个插件）

以最小插件为例，照着抄：

```ts
// packages/xxx/src/index.ts
import type { Context } from 'cordis'
import z from 'schemastery'

export const name = 'xxx'                      // 插件名
export const inject = ['config', 'store']       // 依赖的服务名（数组）

export interface Config { a: string; b?: number }  // 配置类型
export const Config: z<Config> = z.object({
  a: z.string(),               // schemastery：字段默认可选！必填加 .required()
  b: z.number().default(1),    // 有默认值用 .default()
})

export function apply(ctx: Context, config: Config): void {
  const cfg = (ctx as any).config   // 注入的服务（暂用 any，未做类型增广）
  const store = (ctx as any).store

  ctx.on('poller/result', ({ points }: any) => { /* 订阅事件 */ })
  ctx.emit('xxx/event', { ... })    // 发事件

  ctx.provide('xxx', { /* 对外提供的服务 */ })  // 提供 ctx.xxx
}
```

**步骤**：

1. `packages/xxx/package.json`（`@probebench/xxx` + 依赖）+ `src/index.ts` + `README.md`。
2. 在 `apps/cli/src/main.ts` 里 `import` + `ctx.plugin(xxxPlugin, config)` 装配。
3. 在 `apps/cli/package.json` 加 `@probebench/xxx: "*"`。
4. `scripts/test-xxx.ts` 写冒烟测试。
5. 写 README（Config / Service / 用法 / 当前限制）。

**硬规则（踩过坑）**：

- `ctx.plugin()` 是**异步激活**的，必须 `await`，否则服务还没对外可见。
- 消费者用 `inject: [name]` + `ctx.<name>` 访问；`ctx.get(name)` 默认 strict 只返回活跃 fiber 的服务。
- Service 的异步初始化用 `ready: Promise` 模式（构造器启动、方法内 await），**不要**写 async apply。

## 7. 数据模型

### 7.1 元数据（config，SQLite，5 张表）

`monitor_objects`（设备）/ `register_groups`（寄存器组）/ `registers`（寄存器）/ `alarm_rules`（告警规则）/ `logs`（日志）。

- 每台设备**独立配置**寄存器（无类型模板）。
- **设备连接方式**：`transport`（`tcp`/`rtu`）+ 串口参数 `serial_path/baud_rate/parity/stop_bits/data_bits/flow_control` + `slave_id`（设备从站地址，OTA 寻址用；存 config，不进 YAML；RTU 时 `ip` 可为空、以 `serialPath` 寻址）。
- **固件**：`firmwares` 表（id/name/version/size/crc32/file_path/created_at），二进制存工作区 `firmware/firmware_<id>.bin`（不存 SQLite）。
- **寄存器类型**：位宽(16/32/64) × 端序(大端默认/小端 `-LE`) × 格式(int/uint/float/hex/bin)，共 30 种；编解码在 `packages/core/src/codec.ts`（16 位大小端=字节交换、32/64 位=字序反转、64 位整数用 BigInt；hex/bin 为原始显示不可写）。32/64 位寄存器合并相邻地址，被覆盖地址显示 `—` 且类型下拉禁用。
- **新建分组自动生成寄存器**：API/MCP 的 create_group 按 `quantity` 每地址生成一个寄存器（默认 int16、无别名）。
- **无语义层字段**（scale/unit/enum 都没有——决策 #10，AI 语义后续用 Excel 外部整理）。

### 7.2 时序（store，DuckDB，1 张表）

`poll_data(object_id, address, ts TIMESTAMP, raw_value DOUBLE, quality VARCHAR)`。

- **按「地址」存原始 16 位字**（类型只是显示方式，解码在消费端做）：poller 按 `g.startAddress + i` 发 `address`，冷层 `poll_data` 用 `object_id` 列区分设备、热层用 `objectId:address` 复合键（地址是**每设备独立**的，不能只按地址键控，否则多设备同地址会互相覆盖导致实时值「闪」）。单设备快照用 `store.getLatestByObject(objectId)`；前端 `latest` 也是复合键、`buildRegViews(..., objectId)` 按当前设备过滤。32/64 位寄存器在时序里是「多个相邻地址的原始字」，消费端用 `packages/core/src/codec.ts` 里共享的解码器：`decodeRawByAddr()`（数值，供曲线/告警规则/MCP）和 `formatRawByAddr()`+`formatRegisterValue()`（显示字符串，hex/bin 逐字、数值格式化，供实时表/历史/CSV/XLSX），两者共用同一个「按寄存器收字 + 覆盖/数据不足判定」逻辑。
- 热层：内存 `Map<address, latest>`，`getLatest()` 零磁盘 IO。
- 冷层：DuckDB 列存，批量写（满 `flushBatchSize` 或定时 `flushIntervalMs` 才落库）。
- `decoded_value` 不落库（无缩放，raw 就是值）。
- 数据保留：**已实现**（全局默认 + 设备覆盖，`0` 为永久）；时序降采样仍未实现（Phase 5）。

## 8. 关键技术点 / 踩坑记录（重要！接手必读）

1. **Cordis 4 服务范式**：`ctx.provide(name, val)` 提供、`inject + ctx.name` 消费；`ctx.plugin()` 要 `await`；`ctx.get(name)` 默认 strict（只读活跃 fiber 的服务），顶层测试用 `ctx.get(name, false)`。
2. **schemastery**：字段**默认可选**（`required` 默认 false），**没有 `.optional()`**；必填用 `.required()`，默认值用 `.default()`。用 `import z from 'schemastery'`。
3. **jsmodbus（从站）**：从站的 `holding` 缓冲要**预填**；`readHoldingRegisters` 事件**只在 holding 为 falsy 时触发**。响应用 `body.valuesAsArray`。
4. **MCP**：`McpServer`/底层 `Protocol` **只能连一个 transport**（第二次 `connect()` 抛「Already connected to a transport」）→ streamable-http 的**多会话/多连接**必须**每个会话新建一个 McpServer + 一个 `StreamableHTTPServerTransport`**（有状态模式 `sessionIdGenerator`，以 sessionId 缓存、`onclose` 清理）。**不能全局单例复用**：否则断开后第二次连接报「Server already initialized」卡死（规格符合性报告 P0，已修）。stateless 模式则每个请求都要新建 transport。挂 Fastify 用 `reply.hijack()` 会 double-close 崩溃 → MCP 用**独立 node:http 服务器**（8081）。
5. **@fastify/static**：`root` 必须**绝对路径**（`resolve()`）。
6. **@fastify/websocket**：要 `await register()` 后再注册 `/ws`，否则升级失败 → 用 Fastify async 插件封装（apply 是同步的）。
7. **npm 缓存**（沙箱环境）：`AppData\Local\npm-cache` 写不进去时，重定向 `$env:npm_config_cache = "<workspace>\.npm-cache"`。
8. **node:sqlite**（Node 24 内置）做元数据；**@duckdb/node-api** 做时序（原生模块，需 prebuilt 二进制）。
9. **前端**：纯 CSS（`styles.css`，CSS 变量 + 深色主题），设计令牌复刻 DSH；i18n 用轻量字典 + `t()`；状态用 useState + localStorage 持久化（无路由库/状态库）。SVG 曲线不要用固定 aspect-ratio/viewBox（文字会被拉伸）→ 用 `ResizeObserver` 实测容器像素当 `viewBox`（1:1），X/Y 刻度密度按画布宽高自适应；拖拽框选时 SVG 加 `user-select:none` + 文字 `pointerEvents:none` 防选中。
10. **Modbus 故障显示**：轮询**按组**捕获错误——连接失败对该设备所有到期组标错、单组读取异常只标该组。jsmodbus 出错时 reject 的是 `UserRequestError`（**不是 Error 实例**，形如 `{ err, message, response? }`，err ∈ `Timeout`/`Offline`/`OutOfSync`/`ModbusException`/`ManuallyCleared`），驱动 `normalize()` 必须显式处理否则会 `String(e)` 变成 `[object Object]`：`Timeout`→`Timeout`、`ModbusException`→按 `e.response.body.code` 映射 `Illegal Data Address` 等、其余→`e.message`；socket 连接错误是真正的 Error，保留原样（`connect ECONNREFUSED ...`）。poller 发 `poller/group-error`（值变化才发）与 `poller/group-ok`（读成功且之前有错才发）→ api 转 WS → 前端分组头部红色徽标，恢复后自动清除。
11. **寄存器类型与端序**：类型名编码位宽+端序+格式（`int32-LE`/`hex16`/`bin64`… 共 30 种）；16 位大小端=字节交换 `swap16`、32/64 位=字序反转；hex/bin 是原始显示（不可写）；32/64 位合并相邻地址，被覆盖地址显示 `—` 且类型下拉禁用。
12. **轮询用单一全局循环 + 每轮动态读设备列表**：`startAll()` 只建一个 `setInterval`，每轮 `listObjects().filter(mode!=='slave')` 后逐个 `pollObject`——因此「新建设备 / 启动时已断开再点连接」都会自动纳入轮询，断开/删除的自动排除（旧实现是启动时给每台设备各建一个 setInterval，启动后再启用/新建的设备永远不被轮询）。`pollObject` 每轮开头仍 `getObject().isActive`：断开/停用时 `markDisconnected()` 给所有启用分组发 `group-error`（消息 `Disconnected`，前端映射为「已断开」）并释放连接，分组头部显示 ⚠ 徽标；重连读成功后发 `group-ok` 自动清除（测试 test-disconnect / test-device-toggle）。
13. **同一轮询周期内所有分组必须共享一个时间戳**：`pollObject`/`pollOnce` 里每个分组是独立 `await` 读的，若每个点都 `new Date().toISOString()`，多分组之间时间戳会差几十毫秒、**永不重合**，历史页按精确 `ts` 分组就会让每组各成一行、另一组显示 `—`（数据不足）。正确做法是进循环前生成一次 `cycleTs`，本轮所有点都用它（已修；见测试报告 P0）。
14. **Fastify 插件要在路由前注册、但不能用 async apply**：`@fastify/compress` 这类用 `onRoute` 钩子的插件必须「注册完成后」再定义路由，否则路由拿不到钩子；但把 api 的 `apply` 写成 `async` 会让 Cordis 激活时序错乱（`ctx.get('api')` 拿到 undefined、`app.listen` 崩）。正确做法：`apply` 保持同步，把 `await compress 注册 + 全部路由 + websocket + 静态托管` 塞进**一个 `void app.register(async (fastify) => {...})`**，事件中继 `ctx.on(...)` 仍留在外层同步注册。
15. **RTU 串口**：串口是**半双工**，同一时刻只能一个请求在总线上——poller 把 RTU 设备按 `serialPath` 分组、用 `enqueueRtu()`（Promise 链）串行轮询，`write` 也走同一队列；驱动缓存键 TCP 按设备 `tcp:id`、RTU 按串口 `rtu:serialPath`（**同一条串口多台 slaveId 设备共享一个 SerialDriver + 一个 SerialPort**，内部按 slaveId 各建一个 `ModbusRTUClient`，靠 jsmodbus 的 `unitId` 过滤路由响应）。`serialport` 是原生模块（prebuilt 随 npm 包带，无需编译）；**测试用 `SerialPortMock` 时注意 `@serialport/binding-mock` 有 CJS/ESM 双入口**（`exports.require` vs `default`），`SerialPortMock` 内部走 `require`，测试里要用 `createRequire` 拿同一个实例，否则 `createPort` 的端口状态不互通（报「Port does not exist」）。
16. **OTA 0x41（自定义功能码）**：jsmodbus 公开 API 不暴露「发任意功能码」，所以 OTA **绕过 jsmodbus、拼原始帧**——`packages/ota/src/frame.ts` 出 PDU（`0x41+cmd+data`，均大端），RTU 加 `addr+crc16(低字节前)`、TCP 加 MBAP 头（tx 递增）；经 `modbus.getRawSocket()` 拿底层 socket 直连。CRC32 用 `crc.crc32()>>>0`（CRC-32/ISO-HDLC，poly `0xEDB88320`）。升级期间 `poller.pauseObject` 暂停轮询、结束 `reconnectDevice` 清 jsmodbus 残留 0x41 缓冲（尤其 RTU 共享串口，jsmodbus 的 RTU 客户端解析不了 0x41 会积在 `_buffer`）。块大小默认 128（对齐设备侧 `MB_IAP_MAX_DATA`）。
17. **WebSocket 长期运行恢复**：前端 `/ws` 使用连接状态机（connecting/connected/stale/reconnecting/disconnected），10s 应用层 ping/pong、30s 无消息标记 stale、45s 强制重连；重连按 1/2/4/8/15s 指数退避（±20% 抖动）且不限次数。断线期间每 5s 通过当前设备 `latest` REST 接口补偿，恢复后自动停止；重连收到服务端全量 `latest` 后覆盖旧快照。浏览器网络恢复或重新可见时立即重连，HTTPS 自动使用 `wss://`。服务端广播检查 socket 状态并隔离发送异常，每 15s 清理超过 60s 未见客户端心跳的僵尸连接。UI 将「设备启用」与「实时通道状态」分开显示。
18. **Modbus 通信诊断**：TCP 按设备、RTU 按共享串口通道维护有界诊断器。底层 stream 旁路记录 TX/RX 的 HEX、Slave ID、功能码和异常码；请求路径统计成功、失败、超时、连续错误、最近 100 次错误率以及最后/平均/最大响应耗时。默认仅保存每通道最近 2000 条，避免长期运行内存增长；RTU 设备查询报文时按其分组 Slave ID 过滤。
19. **四数据区与位读取**：TCP/RTU 主站支持 FC01/02/03/04。采样点强制携带 `area`，热层只使用 `objectId:area:address`，DuckDB `poll_data` 使用独立 `area` 列，因此四数据区的地址 0 可以同时存在。不输出旧地址键，REST/MCP 单地址读取必须显式给出 area。FC01/02 返回值截断到请求 quantity，避免最后一个字节的填充位越界入库。
