---

## 1. 这是什么

ProbeStation（砺台）：面向嵌入式设备的**观测与测试平台**。用 DeepSeek Harness（DSH）「一切皆插件」的理念，
用 TypeScript + Cordis 全量重写了旧的 Python FastAPI Monitor。

一句话：**监控是数据底座（Modbus 采集 + 时序存储 + 仪表盘），AI 测试是大脑（通过 MCP 让 agent 读写设备）。**

## 2. 快速开始

```bash
npm install          # 安装依赖（沙箱环境需把 npm 缓存重定向：见 §8）
npm run start        # 构建前端 + 一键启动完整应用
```

启动后：

| 端口 | 用途 |
|---|---|
| **8080** | Web UI（React 仪表盘）+ REST API + WebSocket |
| **8081** | MCP 服务器（给 AI agent 用） |

- 浏览器打开 `http://localhost:8080`。
- 首次启动会自动播种两台设备：`测试从站`（192.168.90.176:8899，真实 Modbus slave，两个分组：0x0000 起 10 个斜坡上升 + 0x1000 起 10 个斜坡下降）+ `本地模拟器`（127.0.0.1:8502，两个分组：运行状态@0x0000 + 电气参数@0x1000）。
- 数据文件在 `data/`（gitignore）：`config.db`（元数据）+ `poll.duckdb`（时序）。删掉即重置。
- **工作区**：一个文件夹 = 一个自包含工作区（内含 `config.db` + `poll.duckdb`）。左侧栏顶部可点开「切换工作区」选文件夹（路径输入 + 子目录浏览 + 最近使用），切换后设备列表随之切换（对齐 DSH）；数据库文件就存在所选文件夹里，**重启后自动回到上次使用的工作区**。

## 4. 架构总览

**插件化范式（Cordis 五理念）**，每个插件就是一个「服务」：

1. 插件 = 实现 Service 的对象（`apply(ctx, config)`）。
2. context 是服务仓库：服务挂 `ctx.<key>`（`ctx.modbus`、`ctx.store`…），按 key 找，不 import 实现。
3. `inject` 声明依赖：加载顺序由依赖决定。
4. 类型化事件：`emit / waterfall / parallel / serial`。
5. 注册都是可逆 effect（`ctx.effect()` / `ctx.on()`）。

**数据流：**

```
真机/从站 ──Modbus──▶ modbus ──▶ poller ──emit(poller/result)──▶ api(WS) ──▶ 前端
                              │
                              ├─▶ store(热缓冲+DuckDB) ──▶ api(REST latest/query)
                              │                                └─▶ sink(导出)
                              └─▶ rule(评估) ──emit(rule/trigger)──▶ api(WS) + config.log

MCP 客户端(DSH/agent) ──HTTP──▶ mcp(8081) ──▶ config/store/poller（读快照/查历史/写寄存器）
```

## 5. 插件与服务一览（12 个）

| 插件 | 提供的 `ctx.*` | 端口/能力 | 注入 |
|---|---|---|---|
| core | — | 全局配置 schema（占位） | — |
| config | `ctx.config` | 元数据 CRUD + 规则 + 日志（node:sqlite） | — |
| modbus | `ctx.modbus` | `createDriver()` → ModbusDriver（读/写） | — |
| poller | `ctx.poller` | `startAll/stopAll/pollOnce/write`（按组 scan rate + slave id 轮询） | config, modbus, store |
| store | `ctx.store` | `write/flush/getLatest/query/queryObject` | — |
| sink | `ctx.sink` | `exportCsv/exportXlsx` | config, store |
| rule | `ctx.rule` | 订阅 poller/result → rule/trigger | config |
| api | `ctx.api` | Fastify：REST+WS+静态（8080） | config, store, poller, sink, importer, workspace |
| slave | `ctx.slave` | Modbus 从站（8502） | — |
| importer | `ctx.importer` | `import()`（MBS/MBP 解析） | config |
| mcp | `ctx.mcp` | MCP 服务器（8081）6 个工具 | config, store, poller |
| workspace | `ctx.workspace` | 工作区管理（一个文件夹=一个工作区） | config, store, poller |

**关键事件**：`poller/result`（轮询结果）、`rule/trigger`（告警命中）、`poller/group-error`/`poller/group-ok`（按组轮询故障/恢复）、`workspace/changed`（切换工作区）。事件是**全局分发**的（兄弟插件 emit/on 互达）。

## 6. 插件开发范式（怎么加一个插件）

以最小插件为例，照着抄：

```ts
// packages/xxx/src/index.ts
import type { Context } from 'cordis'
import z from 'schemastery'

export const name = 'xxx'                      // 插件名
export const inject = ['config', 'store']       // 依赖的服务名（数组）

export interface Config { a: string; b?: number }  // 配置类型
export const Config: z<Config> = z.object({
  a: z.string(),               // schemastery：字段默认可选！必填加 .required()
  b: z.number().default(1),    // 有默认值用 .default()
})

export function apply(ctx: Context, config: Config): void {
  const cfg = (ctx as any).config   // 注入的服务（暂用 any，未做类型增广）
  const store = (ctx as any).store

  ctx.on('poller/result', ({ points }: any) => { /* 订阅事件 */ })
  ctx.emit('xxx/event', { ... })    // 发事件

  ctx.provide('xxx', { /* 对外提供的服务 */ })  // 提供 ctx.xxx
}
```

**步骤**：

1. `packages/xxx/package.json`（`@probebench/xxx` + 依赖）+ `src/index.ts` + `README.md`。
2. 在 `apps/cli/src/main.ts` 里 `import` + `ctx.plugin(xxxPlugin, config)` 装配。
3. 在 `apps/cli/package.json` 加 `@probebench/xxx: "*"`。
4. `scripts/test-xxx.ts` 写冒烟测试。
5. 写 README（Config / Service / 用法 / 当前限制）。

**硬规则（踩过坑）**：

- `ctx.plugin()` 是**异步激活**的，必须 `await`，否则服务还没对外可见。
- 消费者用 `inject: [name]` + `ctx.<name>` 访问；`ctx.get(name)` 默认 strict 只返回活跃 fiber 的服务。
- Service 的异步初始化用 `ready: Promise` 模式（构造器启动、方法内 await），**不要**写 async apply。

## 7. 数据模型

### 7.1 元数据（config，SQLite，5 张表）

`monitor_objects`（设备）/ `register_groups`（寄存器组）/ `registers`（寄存器）/ `alarm_rules`（告警规则）/ `logs`（日志）。

- 每台设备**独立配置**寄存器（无类型模板）。
- **无语义层字段**（scale/unit/enum 都没有——决策 #10，AI 语义后续用 Excel 外部整理）。

### 7.2 时序（store，DuckDB，1 张表）

`poll_data(object_id, register_id, ts TIMESTAMP, raw_value DOUBLE, quality VARCHAR)`。

- 热层：内存 `Map<registerId, latest>`，`getLatest()` 零磁盘 IO。
- 冷层：DuckDB 列存，批量写（满 `flushBatchSize` 或定时 `flushIntervalMs` 才落库）。
- `decoded_value` 不落库（无缩放，raw 就是值）。
- 降采样/保留：**未实现**（Phase 5）。

## 8. 关键技术点 / 踩坑记录（重要！接手必读）

1. **Cordis 4 服务范式**：`ctx.provide(name, val)` 提供、`inject + ctx.name` 消费；`ctx.plugin()` 要 `await`；`ctx.get(name)` 默认 strict（只读活跃 fiber 的服务），顶层测试用 `ctx.get(name, false)`。
2. **schemastery**：字段**默认可选**（`required` 默认 false），**没有 `.optional()`**；必填用 `.required()`，默认值用 `.default()`。用 `import z from 'schemastery'`。
3. **jsmodbus（从站）**：从站的 `holding` 缓冲要**预填**；`readHoldingRegisters` 事件**只在 holding 为 falsy 时触发**。响应用 `body.valuesAsArray`。
4. **MCP**：stateless 模式每个请求要新建 transport（SDK 会抛「cannot be reused」）→ 用**有状态模式**（`sessionIdGenerator: () => randomUUID()`）。挂 Fastify 用 `reply.hijack()` 会 double-close 崩溃 → MCP 用**独立 node:http 服务器**（8081）。
5. **@fastify/static**：`root` 必须**绝对路径**（`resolve()`）。
6. **@fastify/websocket**：要 `await register()` 后再注册 `/ws`，否则升级失败 → 用 Fastify async 插件封装（apply 是同步的）。
7. **npm 缓存**（沙箱环境）：`AppData\Local\npm-cache` 写不进去时，重定向 `$env:npm_config_cache = "<workspace>\.npm-cache"`。
8. **node:sqlite**（Node 24 内置）做元数据；**@duckdb/node-api** 做时序（原生模块，需 prebuilt 二进制）。
9. **前端**：纯 CSS（`styles.css`，CSS 变量 + 深色主题），设计令牌复刻 DSH；i18n 用轻量字典 + `t()`；状态用 useState + localStorage 持久化（无路由库/状态库）。
10. **Modbus 故障显示**：轮询**按组**捕获错误——连接失败对该设备所有到期组标错、单组读取异常只标该组；驱动把 jsmodbus 的异常码（`body.code`）和 `err:'Timeout'` 归一成可读消息（`Illegal Data Address`/`Timeout`），连接错误保留原样（`connect ECONNREFUSED ...`）；poller 发 `poller/group-error`（值变化才发）与 `poller/group-ok`（读成功且之前有错才发）→ api 转 WS → 前端分组头部红色徽标，恢复后自动清除。
