## 1. 一句话定位

给 AI agent 提供**调试嵌入式设备的手脚**：让 AI 能**观测**（读寄存器）和**控制**（写寄存器）单片机，像工程师一样交互式调试。

- **监控（采集/存储/可视化）是数据底座（眼睛）**，**MCP 读写是手脚**，**YAML 说明书让 AI 看得懂（大脑）**。
- 核心卖点不是「测试」，是「**调试**」：读状态 → 判读 → 控制 → 验证 的交互式闭环。
- 护城河：**语义清单 YAML（给调试 agent 的说明书，让 AI 看懂设备）**。工具忠实执行、不兜底。

- 中文产品名：砺台（「砺」= 磨砺/反复试验，「台」= bench/试验台）。
- 英文/代码名：ProbeStation（半导体「探针台」隐喻：用探针戳芯片测好坏 ≈ 用 Modbus 戳设备测好坏）。
- 前身：旧 Monitor 平台（Python FastAPI + Quasar/Vue），本工程为其**全量重写**。

> 定位澄清：立项时曾表述为「AI 测试」，现已澄清为「**AI 调试**」——给 agent 一个能动手调设备的手脚，而非跑固定用例的测试执行器。详见 `docs/product/03/04/05`。

## 3. 当前已实现能力（Phase 0–4 ✅）

核心闭环已打通，功能不弱于旧 Monitor：

- **采集**：Modbus TCP + RTU 串口主站轮询（jsmodbus）；轮询周期按设备配置，组保留独立 slave id，同设备到期组在同一轮共享时间戳。
- **存储**：热内存快照 + DuckDB 列存（时序）；node:sqlite（元数据）。
- **可视化**：React 18 仪表盘（`:8080`，DSH 风格深色主题）+ REST API + WebSocket 实时推送。
- **控制**：写寄存器（FC06/FC16，支持 16/32/64 位 + 大小端）。
- **CRUD**：设备 / 寄存器组 / 寄存器 / 告警规则 / 日志。
- **从站模拟**：本地 Modbus slave 模拟器（`:8502`），首次启动播种「测试从站 + 本地模拟器」。
- **告警**：规则引擎（订阅轮询结果 → 触发告警）。
- **导入导出**：MBS/MBP 寄存器文件导入；CSV / XLSX 导出。
- **工作区**：一个文件夹 = 一个自包含工作区（config.db + poll.duckdb），可运行时切换。
- **采样与保留**：按设备设置轮询周期（下限 1ms，实际受 Modbus 往返限制）；全局默认 + 设备覆盖的数据保留清理。
- **录制**：连续录制与条件触发录制，支持前后窗口、查询、停止和删除会话。
- **MCP 服务器**（`:8081`，34 个工具）：把「读快照 / 查历史 / 写寄存器 / 分组寄存器 CRUD / 新增·启停设备 / 分组启停 / 采样与保留 / 录制 / 点位表 xlsx 导入导出 / OTA 固件升级」暴露给 AI agent——**AI 调试的手脚**。

## 4. 技术架构（PM 速览版）

> 详细实现见 `docs/02`（方案）、`docs/03`（现状）。

```
真机/从站 ──Modbus──▶ modbus ──▶ poller ──emit──▶ api(WS) ──▶ 前端
                             │
                             ├─▶ store(热缓冲+DuckDB) ──▶ REST 查询/导出
                             └─▶ rule(告警) ──▶ WS + 日志

MCP 客户端(DSH/agent) ──HTTP──▶ mcp(8081) ──▶ config/store/poller
```

- 技术栈：TypeScript + Cordis 4（插件运行时），13 个插件各司其职，依赖注入 + 类型化事件。
- 插件清单：`core / config / modbus / poller / store / sink / rule / api / slave / importer / mcp / ota / workspace` + 前端 `apps/web` + 入口 `apps/cli`。

## 5. 与理想形态的差距（Roadmap 缺口 / Phase 5 ⬜）

1. **AI 调试能力**：目前 MCP 只提供原始数据读写，缺「YAML 说明书的流转 + 原始数据读写完善」——这是核心卖点，尚未兑现。
2. **时序降采样**：数据保留清理已经实现，但尚未把长期数据聚合为分钟/小时粒度；高频长期留存仍可能带来较大的 DuckDB 体量和查询成本。
3. **写寄存器**：已具备忠实执行能力（写什么就写什么），无需额外护栏——这是定位，不是缺口。

---

## 6. 产品经理初步观察（待与团队确认）

1. **闭环已成立**：采集→存储→可视化→告警→导出→AI 接口链路是通的，非 demo 半成品。
2. **核心卖点未兑现**：AI 调试仍是「接口就绪、能力未落地」；当前更像**增强版监控平台**，而非「能让 AI 看懂并控制设备」的调试工具。
3. **定位已澄清**：工具忠实执行、不兜底，写错是 agent 的责任——无需再补安全护栏。
4. **性能债有所收敛**：保留清理已落地；降采样缺失仍会影响需要长期保存高频数据的场景。
