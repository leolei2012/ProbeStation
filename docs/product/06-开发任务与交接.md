## 0. 产品定位（30 秒看懂）

> **ProbeStation = 给 AI agent 的 Modbus 原始数据通道。** 平台只读/写原始寄存器值，忠实执行；语义（scale/unit/enum）由固件 agent 产出 YAML 说明书、调试 agent 自己理解，**平台不消费 YAML、不做翻译、不按名寻址、不做任何安全拦截**。

三方分工：

| 角色 | 做什么 |
|---|---|
| 固件开发 agent | 写固件 + 产出 YAML 说明书 |
| 平台（你要改的） | 读原始值 / 写原始值 / 查历史，忠实执行 |
| 调试 agent | 拿 YAML + 读原始值，自己理解、自己调试 |

## 1. 现状：平台已有什么（不用重做）

12 个 MCP 工具（`packages/mcp`，端口 8081）已实现，核心链路已通：

| 类别 | 工具 |
|---|---|
| 读 | `list_devices` / `list_registers` / `read_register` / `read_all` / `query_history` |
| 写 | `write_register`（FC16，忠实执行） |
| 配置 | `create/update/delete_group` + `create/update/delete_register` |

底层已具备：Modbus TCP 轮询（FC03/FC04 + FC06/FC16）、DuckDB 时序存储、本地从站模拟器（8502）、告警规则引擎。

**注意：目前仅支持 TCP（网口），不支持串口 RTU——这是 §2 要补的核心缺口。**

## 2. 开发任务（按优先级）

### P0：RTU 串口支持（连上串口单片机的前提）

**背景**：当前只支持 Modbus TCP（网口），不支持串口。很多单片机调试是 USB-TTL 串口直连，这是「连上设备」的核心能力。

**好消息**：jsmodbus 已内置 `ModbusRTUClient`（协议层现成，CRC/帧解析都有），只差串口访问库 + 封装。

**要做**：

1. 安装 `serialport` 库（原生模块，和 DuckDB 一样依赖 prebuilt 二进制）。
2. 新增 `SerialDriver` 实现现有 `ModbusDriver` 接口：用 serialport 打开串口 → 传给 `ModbusRTUClient`。上层 poller/api/mcp 不动。
3. 设备模型加串口参数（存 **config**，**不进 YAML**，保持「平台不消费 YAML」原则）：

| 字段 | 取值 | 说明 |
|---|---|---|
| `transport` | `tcp` / `rtu` | 连接方式（新增，默认 tcp） |
| `serialPath` | `COM3` / `/dev/ttyUSB0` | 串口路径 |
| `baudRate` | 9600 / 19200 / 38400 / 57600 / 115200 | 波特率 |
| `parity` | `none` / `even` / `odd` | 校验位（默认 even） |
| `stopBits` | `1` / `2` | 停止位 |
| `dataBits` | `8` | 数据位（RTU 固定 8） |
| `flowControl` | `none` / `rtscts` / `xonxoff` | 流控（默认 none） |
| `slaveId` | 1–247 | 从站地址（已有） |

4. **轮询串行化**：RTU 是半双工，一条串口同一时刻只能「发一个请求、等一个响应」，不能像 TCP 那样并行；同一条串口上的多台设备必须依次轮询。
5. （可选）RTU 从站模拟器：jsmodbus 有 `ModbusRTUServer`，可做本地串口仿真。

**验收标准**：

- [ ] USB-TTL 连上串口单片机，能读/写寄存器
- [ ] 同一条串口上多台 slaveId 设备依次轮询（不并发）
- [ ] 串口参数错误时给出明确提示（超时/无响应，提示检查波特率/校验位/接线）

### P1：数据新鲜度透出（最便宜最有价值）

**问题**：agent 读回一个值，分不清是「刚采的」还是「3 小时前的旧缓存」，调试时可能对着过期数据做判断。

**现状（源码）**：

| 工具 | 现在返回 | 缺什么 |
|---|---|---|
| `read_register` | `{ register_id, value, timestamp }` | 缺 `quality` |
| `read_all` | `{ register_id: value }` | 缺 `timestamp`、`quality` |
| `query_history` | `[{ ts, value }]` | 缺 `quality` |

而底层 `store.getLatestByObject()` **已经存了** `quality` 和 `timestamp`，只是 MCP 没透出来。

**要改两处**：

1. `packages/store/src/index.ts`：`queryObject` / `query` 的 SQL 补 `quality` 列（`SELECT ts, address, raw_value, quality ...`），返回结构加 `quality`。
2. `packages/mcp/src/index.ts`：`read_register` / `read_all` / `query_history` 把 `quality`（和 `timestamp`）透出到返回。

**验收标准**：

- [ ] `read_register` 返回 `{ register_id, address, value, timestamp, quality }`
- [ ] `read_all` 每个寄存器返回 `{ value, timestamp, quality }`
- [ ] `query_history` 返回 `[{ ts, value, quality }]`

### P2：工具补强（可选，往后放）

| 工具 | 做什么 | 现状 |
|---|---|---|
| `get_device_snapshot` | 一次返回整机原始值快照（带 alias + 时间戳） | `read_all` 已有，补 alias/timestamp 即可 |
| `get_device_health` | 连接状态 / 轮询是否在跑 / 最近采样时间 | 新增 |
| `list_alarm_rules` | 查看已配告警规则 | 新增 |

### 明确不做（已砍掉，别再实现）

- ❌ 语义翻译（scale/unit/enum 换算）
- ❌ 按名寻址（`read("motor_temp")`）
- ❌ 加载/解析 YAML（`load_semantics`）
- ❌ 安全护栏（白名单 / 值域校验 / 审批 / 危险分级）

## 3. 配合验证：最小闭环 spike

开发 P0 的同时，建议跑一次**最小闭环验证**，确认产品成立（成本几天）：

1. 用本地从站模拟器（8502），不碰真机。
2. 手写一份 YAML 说明书（几行，见 `03`）。
3. 让调试 agent 完成一次：读原始值 → 对照 YAML 理解 → 写原始值 → 读回验证。

**跑通了，产品就成立；跑不通，问题暴露得早。**

---

## 4. 责任边界（开发时必须遵守）

- **忠实执行**：写操作不做任何拦截、校验、审批。agent 写什么就写什么，写错是 agent 的责任。
- **平台不碰语义**：不解析 YAML、不按 `name` 寻址、不做 scale/unit/enum 换算。
- 寻址用 `register_id` 或 `address`（平台已有的），不用 YAML 里的 `name`。

---

## 5. 一句话总结

> 优先做 **P0（RTU 串口支持，若目标硬件是串口）** 和 **P1（数据新鲜度透出）**，再跑最小闭环验证。语义和安全都不是平台的活，是 agent 的活。
