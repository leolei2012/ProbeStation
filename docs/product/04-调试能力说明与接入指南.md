# 调试能力说明与接入指南（给固件开发 agent）

> 状态：v1.2 · 日期：2026-08-14
> 读者：**固件开发 agent**（写单片机程序的一方）
> 前置：请先读 [`03-语义清单契约-YAML规范.md`](03-语义清单契约-YAML规范.md)（你产出的寄存器说明书格式）。
> 本文回答：**我们给你提供了什么调试能力，你该怎么接入、怎么用。**

---

## 1. 一句话

我们提供的是**原始数据通道**：通过 MCP 接口，调试 agent 可以直接读、写、查 Modbus 寄存器的**原始值**。至于这些原始值「是什么量、单位是什么、要不要 ×0.1」，由调试 agent 拿你产出的 **YAML 说明书**（03 号）自己理解——**平台不做翻译，也不碰你的 YAML**。

---

## 2. 完整工作流

```
① 写固件 + 在 Modbus 上挂寄存器
        │
        ▼
② 产出语义清单 YAML（03 号规范，给调试 agent 当说明书）
        │
        ▼
③ 调试 agent：用 MCP 读原始值 / 写原始值，对照 YAML 理解数据
```

**关键点**：YAML（②）是给调试 agent 看的「寄存器说明书」，平台不解析它。平台只负责把原始数据读出来、写进去。

---

## 3. 你能得到的调试能力

> 状态标记：✅ 已实现 ｜ 🚧 建设中（目标形态，接入时以平台实际提供的工具为准）。

| 能力 | 工具 | 说明 | 状态 |
|---|---|---|---|
| 设备列表 | `list_devices` | 列出设备（含连接状态） | ✅ |
| 寄存器列表 | `list_registers` | 某设备的寄存器（`alias` / `address` / `data_type`） | ✅ |
| 读单寄存器 | `read_register` | 读原始值（按 `data_type` 解码后的数值）+ 时间戳 + quality | ✅ |
| 写单寄存器 | `write_register` | 写原始值 | ✅ |
| 查历史 | `query_history` | 查时间范围的历史原始值 | ✅ |
| **一键读整机** | `get_device_snapshot` | 一次返回整台设备所有寄存器的原始值 | 🚧 |
| 设备健康 | `get_device_health` | 连接是否正常、轮询是否在跑、最近采样时间 | 🚧 |
| 告警查看 | `list_alarm_rules` | 查看已配告警规则 | 🚧 |

> **平台只做「读原始值 / 写原始值」，不做翻译**：scale、unit、enum、bitfield 这些语义，由调试 agent 拿 YAML 自己换算。

---

## 4. 寻址方式

- 用平台的 `register_id` 或 `address` 定位寄存器（这是平台本来就有的）。
- 平台**不认** YAML 里的 `name`（`motor_temp` 这类）——`name` 是给调试 agent 自己映射用的，它在 YAML 里自己查 `motor_temp → 0x0064`。

> 即：`name ↔ address` 的对应关系写在 YAML 里，由 agent 自己查表，平台不管。

---

## 5. 端到端示例

假设你写完一个「冰沙机控制器」固件：

**① 挂寄存器**（在固件里，Modbus 上）：
- `0x0064` 电机温度（int16，×0.1）
- `0x0100` 加热设定温度（int16，×0.1，可写）

**② 产出 YAML 说明书**（按 03 号，节选）：
```yaml
registers:
  - { name: motor_temp, address: 0x0064, data_type: int16, scale: 0.1, unit: "℃" }
  - { name: heater_setpoint, address: 0x0100, data_type: int16, scale: 0.1, unit: "℃", access: write }
```

**③ 调试 agent 用 MCP 读原始值 + 对照 YAML**：
```
read_register(device_id, register_id_of_0x0064)   → 254（原始值）+ timestamp + quality
  → 调试 agent 查 YAML：motor_temp, scale 0.1 → 理解成 25.4 ℃

write_register(device_id, register_id_of_0x0100, 700)   → 写原始值 700
  → 调试 agent 查 YAML：700 × 0.1 = 70.0 ℃
```

## 6. 你需要做什么（检查清单）

- [ ] 按 [`03-语义清单契约`](03-语义清单契约-YAML规范.md) 产出 YAML，随固件一起提交。
- [ ] `firmware.version` 填准确（防过期说明书）。
- [ ] 每个寄存器的 `name` 语义化、`address`/`data_type` 对齐固件。
- [ ] 需要缩放的填 `scale` + `unit`，状态寄存器用 `enum` / `bitfield`，命令寄存器用 `volatile` 标注。

---

## 7. 边界与说明

- 平台**只提供原始数据**，不做翻译、不解析 YAML、不按名寻址。
- YAML 是**唯一真源**（agent 之间的说明书）；Excel 是给人审阅的视图。
- 写操作**忠实执行**：写错是 agent 的责任。
