> 原则：逐阶段交付、每阶段独立测试；统一采用新数据区模型，不保留旧地址键或省略数据区的 API。

## 3. 阶段 1 已交付契约

- 数据区：`coil / discrete-input / holding-register / input-register`。
- 功能码：FC01/02/03/04/05/06/15/16。
- 统一 `ModbusRequest`、`ModbusResult`、`ModbusFailure`。
- 错误类型覆盖请求非法、功能未支持、连接/串口打开、超时、无响应、半帧、CRC、事务号、Slave ID、功能码、Modbus 异常和取消。
- 驱动兼容入口 `execute()` 已覆盖现有 FC03/04/06/16；其余功能码按阶段实现。

## 4. 阶段 2 已交付诊断

- TCP 按设备、RTU 按物理串口通道采集 TX/RX；记录 HEX、长度、Slave ID、功能码和异常码。
- 有界内存缓冲默认 2000 条，查询 limit 上限 2000；不会因长期运行无限堆积。
- 指标覆盖成功、失败、超时、连续错误、最近 100 次错误率及最后/平均/最大响应耗时。
- REST：`GET /api/monitor_objects/:id/diagnostics`、`GET /api/monitor_objects/:id/frames`、`POST /api/monitor_objects/:id/frames/clear`。
- RTU 多设备共享串口时指标明确标记 `scope=channel`，设备报文按其配置的 Slave ID 过滤。

## 5. 阶段 3 已交付 FC01/FC02 与数据区隔离

- TCP、RTU 主站新增 FC01 线圈读取和 FC02 离散输入读取，统一 `execute()` 同步支持。
- 位响应按 Modbus LSB-first 解析，并截断至请求 quantity，不把最后一个字节的填充位写入点表。
- 热层键升级为 `objectId:area:address`，历史表增加 `area` 列；四数据区相同地址互不覆盖。
- 实时键只使用 `objectId:area:address`，单设备快照只使用 `area:address`，不提供旧地址键别名。
- Web 分组支持选择 FC01/02，实时表、历史表和曲线按数据区解码；导出链路同步隔离数据区。
- `/api/data/query` 强制要求 `area` 参数；MCP `read_register` 同样要求显式数据区。

## 6. 总体验收

- TCP/RTU 主从站八功能码正常、边界、异常码、超时、半帧、CRC、错站号全部有自动测试。
- 同串口多 Slave ID 严格串行，队列和日志有界，拔插后自动恢复并可靠释放串口。
- 旧工作区无需手工迁移即可打开；历史数据与新数据区不会串地址。
- 完成 TCP 与 RTU 各 24 小时挂机，Web、REST、MCP 数据一致，无持续内存增长。
