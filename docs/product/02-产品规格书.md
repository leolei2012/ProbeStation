## 1. 产品概述

### 1.1 一句话定位

**监控是数据底座（Modbus 采集 + 时序存储 + 仪表盘），AI 调试是手脚（通过 MCP 让 agent 观测与控制设备）。**

### 1.2 命名

- 中文：砺台（「砺」= 磨砺/反复试验，「台」= bench/试验台）
- 英文：ProbeStation（半导体「探针台」隐喻：探针戳芯片测好坏 ≈ Modbus 戳设备测好坏）

### 1.3 前身与动机

由旧 Monitor 平台（Python FastAPI + Quasar/Vue）全量重写而来，解决四类扩展痛点：加新协议、加新 UI、加新告警/数据出口、代码难维护，并为 AI 调试打地基。

## 4. 系统架构（产品视角）

```
真机/从站 ──Modbus──▶ modbus ──▶ poller ──emit──▶ api(WS) ──▶ 前端
                             │
                             ├─▶ store(热内存+DuckDB) ──▶ REST 查询/导出
                             └─▶ rule(告警) ──▶ WS + 日志

MCP 客户端(DSH/agent) ──HTTP──▶ mcp(8081) ──▶ config/store/poller
```

**端口**：

| 端口 | 用途 |
|---|---|
| 8080 | Web UI + REST API + WebSocket |
| 8081 | MCP 服务器（streamable-http，端点 `/mcp`） |
| 8502 | 本地 Modbus 从站模拟器 |

## 5. 功能规格

### 5.1 设备管理（monitor_objects）

- 每台设备独立配置：`name / ip / port / mode(master|slave) / is_active / 其他`。
- **连接方式**：`transport`（tcp / rtu）；RTU 设备加串口参数 `serialPath / baudRate / parity / stopBits / dataBits / flowControl`（存 config，不进 YAML）；从站地址 `slaveId` 在组级。
- 支持：新建、更新、删除（级联删组与寄存器）、启停（toggle 暂停/恢复轮询）。
- master 设备被轮询；slave 设备被轮询引擎跳过（平台对外模拟语义）。

### 5.2 寄存器组管理（register_groups）

- 组 = 一段地址区间：`name / function_code / start_address / quantity / slave_id / poll_interval_ms / mode(read|write|read_write|disable) / is_active`。
- 支持新建（**自动按 quantity 每地址生成一个寄存器**，默认 int16、无别名）、更新、删除、暂停。
- 轮询按组 scan rate + slave id 执行。

### 5.3 寄存器管理（registers）

- 字段：`alias / function_code / start_address / quantity / data_type / sort_order` 等。
- **寄存器类型（30 种）**：位宽（16/32/64）× 端序（大端默认 / 小端 `-LE`）× 格式（int / uint / float / hex / bin）。
  - 16 位大小端 = 字节交换；32/64 位 = 字序反转；64 位整数用 BigInt。
  - `hex` / `bin` 为原始显示，**不可写**。
  - 32/64 位寄存器合并相邻地址，被覆盖地址显示 `—` 且类型下拉禁用。
- 支持新增、更新（别名/类型）、删除。

### 5.4 数据采集（poller）

- Modbus 主站轮询：FC03（保持寄存器）+ FC04（输入寄存器）；FC01/FC02（位读取）未实现。
- **传输**：支持 TCP + RTU 串口；RTU 半双工，同串口多设备串行排队轮询（一个请求回来再发下一个）。
- 单一全局轮询循环，每轮动态读设备列表（新增/断连重连的设备自动纳入，删除/停用自动排除）。
- 连接持久复用，失败自动重连。
- **按组故障捕获**：连接失败 → 该设备所有到期组标错；单组读取异常 → 只标该组。错误归一化（Timeout / Illegal Data Address / 连接失败等），前端红色徽标显示，恢复自动清除。

### 5.5 时序存储（store）

- 热层：内存最新快照（零磁盘 IO），支撑实时表与 WS 推送。
- 冷层：DuckDB 列存，单表 `poll_data(object_id, address, ts, raw_value, quality)`。
- 批量写：满 `flushBatchSize`（500）或定时 `flushIntervalMs`（2000ms）落库。
- 按「地址」存原始 16 位字，解码在消费端做。
- **未实现**：降采样 / 数据保留（Phase 5）。

### 5.6 实时监控与可视化（Web）

- React 18 + Vite，DSH 风格深色主题；纯 CSS，无路由库/状态库。
- 左侧栏：设备/工作区选择（DSH 风格文件夹树）、新建设备、设置。
- 右侧工作页：设备状态徽章 + 工具栏（暂停 / 导出 CSV/XLSX / 删除）+ 寄存器实时值表 + 行内写值。
- 设置页：浅色/深色主题、中文/English、应用信息、清空日志；主题与语言持久化 localStorage。
- 已有历史曲线 Tab：框选缩放、X/Y 轴自适应、无单位数值曲线。

### 5.7 历史数据查询

- REST：单地址历史（`/api/data/query`）、全设备历史（`/api/data/object`）、最新快照（`/api/monitor_objects/:id/latest`）。

### 5.8 数据导出（sink）

- 格式：CSV / XLSX（宽表：行 = 时间戳，列 = 寄存器，列名用 alias）。
- 支持可选 `register_ids` 子集导出。
- **限制**：一次性读全量，无分页/流式。

### 5.9 写寄存器（控制真机）

- 方法：FC06 单写 / FC16 多写（默认 multiple，适配固件只开 FC03 + FC16）。
- 按 dataType（16/32/64 位 + 大小端）编码；32/64 位多字写入；数据不足拒绝。
- **说明**：写值忠实执行（无校验/审批），这是「不兜底」的定位，非缺陷。

### 5.10 告警规则（rule）

- 规则模型：`registerId / operator(> < >= <= == !=) / threshold / message`。
- 实时评估：订阅轮询结果，命中发 `rule/trigger` → WS 推送前端。
- **限制**：仅单阈值；无多条件、无去抖/恢复通知；告警历史未落库（仅实时事件）。

### 5.11 从站模拟（slave）

- Modbus TCP 从站（jsmodbus），holding 缓冲区 = 寄存器内存，支持 FC03 读 / FC06 / FC16 写。RTU 从站为可选扩展（jsmodbus 有 `ModbusRTUServer`）。
- 用于本地测试与设备仿真；启动播种「测试从站（真实 slave）+ 本地模拟器（127.0.0.1:8502）」。

### 5.12 寄存器文件导入（importer）

- 支持：`.mbp` XML（Modbus Poll v12+）、`.mbp` INI（< v12）、`.mbs` 二进制（Witte Modbus Slave）。
- 按后缀自动选解析器，解析为设备/寄存器配置。
- **限制**：多 Data/多 Window 的组映射未完全对齐（导入到第一个 group）；base64 JSON 传输，非 multipart。

### 5.13 工作区（workspace）

- 一个文件夹 = 一个自包含工作区（含 `config.db` + `poll.duckdb`）。
- 支持：浏览/选择文件夹、切换工作区（停轮询→重开库→发事件→重启轮询）、最近使用记录（重启自动回到上次工作区）。
- **限制**：非默认工作区不自动播种演示设备；无跨工作区复制/迁移。

### 5.14 日志（logs）

- 记录操作/运行日志；API 提供查询与清空。

### 5.15 MCP 服务（AI 接口）

- 独立 node:http 服务器，streamable-http（有状态），端点 `/mcp`。
- 14 个工具：`list_devices / list_registers / read_register / get_device_snapshot / query_history / write_register / get_device_health / list_alarm_rules / create_group / update_group / create_register / update_register / delete_register / delete_group`。
- 供 DSH（或任意 MCP 客户端）接入；模型得到 `mcp__probestation__*` 原生工具。
- **说明**：`write_register` 直接执行 + 记日志，**无审批/鉴权**——工具忠实执行、不兜底，这是定位。

## 6. 接口规格（摘要）

### 6.1 REST API（8080）

完整清单见 `docs/03` §9。核心分组：

| 资源 | 能力 |
|---|---|
| 工作区 | 当前/浏览/切换 |
| 设备 | 列表/新建/更新/删除/启停/分组 |
| 组 | 更新/删除/暂停/寄存器列表/新建 |
| 寄存器 | 更新/删除/写值 |
| 数据 | 最新快照/单地址历史/全设备历史/导出 CSV/XLSX |
| 规则 | 列表/新建/删除 |
| 日志 | 查询/清空 |

### 6.2 WebSocket（`/ws`）

- 连接推 `latest`；广播 `poller/result`、`rule/trigger`、`group-error`/`group-ok`、`workspace/changed`。

### 6.3 MCP（8081，`/mcp`）

- streamable-http，12 个工具（见 §5.15）。

## 11. 风险与开放问题

1. **责任边界**：工具忠实执行、不兜底，写错是 agent 的责任——产品需在文档/契约中明确这一边界。
2. **核心卖点待验证**：MCP 原始数据接口已完善（14 工具 + 新鲜度），但「说明书流转 + 调试闭环」尚未验证。
3. **性能债**：无降采样，长期运行拖垮查询与磁盘。
4. 语义由 YAML 说明书承载（agent 自用），平台不消费；AI 判读靠 agent 查说明书。
